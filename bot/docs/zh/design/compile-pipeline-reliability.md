# Wiki 产物校验与链接发布

用户已确认本轮按四份 PR 收敛；本 PR 只负责实际文件的结构、来源、缓存及链接正确性。实现细节和回归由 AI 完成，维护者评审未完成。模型执行/恢复移至 #7124，文件发布及退出状态归 #7122，图片与额外时限归 #7093。

## 问题与实现

- 实际 Wiki 文件可能只有 frontmatter、包含非法 YAML，或引用缺失/重复/未分配的输入 ID。生成提交与缓存命中均重新校验，反馈真实结构错误；普通文件、无输入模板和 Entry 增量无变更语义保留。
- 不再要求每个有输入的局部文件任务必须产文件。空局部分支保持原来的 unreferenced 记账，不能视为已交付，更不能作为整体内容验收证明。
- Wiki 链接中的裸空格会破坏 Markdown 导航。保留编码、尖括号、标题和代码/注释保护，向生成者返回可修复反馈，发布前再次校验。
- 嵌套页复制 Wiki 根相对路径会跳到错误目录。先验证正常页面相对目标；只有其不存在且 Wiki 根候选确实存在时才转换。任务 catalog 不完整，未知候选通过原有鉴权 stat 精确核对，仅 NOT_FOUND 表示不存在，不枚举历史目录。未知链接保持原样并由验收报告。
- 原始候选哈希保持不变，最终发布收据的哈希对应实际转换后的字节。

## 代价与边界

链接处理增加本地路径操作和去重后的少量 stat 请求，没有额外模型调用或依赖。结构校验可能触发既有模型修复；它只能验证结构及来源引用，不能证明事实正确或内容完整。沿用同一客户端、身份与目标命名空间，不绕过 API 访问宿主目录。

本轮移出路由候选扩张、固定 50 条切组策略变化、并行 Combine、合并时惰性正文读取及持久挂载跳过备份枚举，保持 main 对应行为。这是收窄交付范围，不宣称这些策略已证明错误。

原始公开 PPT 的 71 处坏链接已有只读回放证据。既有单份 PPT 工作流与性能数据来自旧组合提交，不能视为本轮四 PR 新提交的全链路验收。按用户要求，本次仅运行必要回归与静态检查，不重跑 Compile；事实矛盾、内容遗漏和商业线上验收仍未解决或未验证。
