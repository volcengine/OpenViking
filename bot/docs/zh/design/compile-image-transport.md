# Compile 图片传输修复

目标：输入目录包含图片时，Compile 直接尝试带图请求，不因本地能力名单提前拒绝。

已确认 main 的错误来自 Compile 自身的能力拦截；本地 LiteLLM 1.83.12 的 DeepSeek 路由还复现了图片被转成纯文本的问题。反馈用户的实际路由和 SDK 版本尚未确认。

- 删除读取和模型调用阶段的能力拦截；Compile 的工具读取保留原图，继续执行现有大小和格式限制。
- 传输声明只选择图片放在工具结果还是关联用户消息中；未知声明默认使用用户消息，备用模型不能阻止主模型接收图片。
- 验证原图和来源 URI 能交给 provider，包括能力未知的模型和备用模型；真实接口错误按现有错误路径返回。

LiteLLM 升级单独提交 PR，使用上游修复，不在 OV 增加 DeepSeek 特判。1.100.0 首次包含保图代码，1.102.0 的内置模型表已覆盖官方 deepseek-flash；未知别名仍受上游模型表限制，不能宣称升级后全部支持。

本 PR 不修改依赖版本、部分失败后的任务状态或增量检查点，不新增配置项或模型能力名单。

代价：不增加依赖、模型探测或重试；发送原图会产生接口原有的图片计费和载荷开销，沿用现有图片预算。验证采用真实 SDK 和模拟 HTTP，实际模型识图效果仍需现场确认。
