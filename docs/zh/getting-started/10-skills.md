# 技能使用

技能（Skill）将一项任务的操作方法、输出格式和检查要求整理成可复用的说明。对于反馈整理、报告撰写、代码审查等重复任务，Agent 可以读取技能，按照其中的要求处理不同输入。

OpenViking 负责保存和检索技能，Agent 负责读取说明并执行任务。本节以“反馈简报”为例，带你添加一个技能，再通过 VikingBot 处理两组反馈，查看同一套工作方法如何在不同会话中复用。

## 准备环境

开始前，请准备以下环境：

- **OpenViking 服务和 CLI**：按照[快速开始](02-quickstart.md)完成连接配置。
- **VikingBot**：确认服务已启用 VikingBot，并完成模型配置。安装与配置方法见 [VikingBot](11-vikingbot.md)。本节通过 `ov chat` 调用模型生成简报，会产生相应的模型调用费用。
- **技能目录权限**：本节将技能添加到共享目录 `viking://agent/skills/`，当前账号需要具备写入权限。CLI 和 VikingBot 应连接同一服务，并使用能够访问该技能的账号。

下载[反馈简报技能包](/quickstart/feedback-brief-v1.zip)，在终端中进入下载文件所在的目录。包内包含 `SKILL.md` 和中英文示例输入，可以直接用于后续操作。

## 添加样例技能

解压技能包，得到 `feedback-brief` 目录：

```bash
unzip feedback-brief-v1.zip
```

将整个目录添加到 OpenViking。`--wait` 会等待技能处理完成，便于接下来查看内容。

```bash
ov add-skill ./feedback-brief -p viking://agent/skills --wait
```

查看技能列表，确认其中包含 `feedback-brief`：

```bash
ov skills list
```

读取 `SKILL.md`，了解 Agent 将遵循的要求：

```bash
ov read viking://agent/skills/feedback-brief/SKILL.md
```

这个技能要求 Agent 只使用当前输入中的信息，并按输入语言生成以下内容：

| 内容 | 要求 |
| --- | --- |
| 已知事实 | 保留输入中的事实和数字，标注输入编号 |
| 建议行动 | 用表格列出行动、负责人和依据，将建议与事实区分开；负责人缺失时标为“未指定” |
| 待确认 | 列出缺失的信息，日期缺失时标为“尚未确定” |

技能会让 Agent 在对话中返回简报。完成导入后，接下来通过对话让 Agent 读取并使用它。如果已添加过这个样例，可以确认技能内容后直接继续。

<a id="用第一组输入"></a>

## 生成反馈简报

第一组反馈包含一个耗时数据、一项改进建议和一个待确认的日期。在新会话中提供反馈，并指定技能路径，让 VikingBot 按照技能要求整理：

```bash
ov chat --session feedback-skill-a -m "请先发现并读取 viking://agent/skills/feedback-brief/SKILL.md，按技能整理以下输入，只在对话中返回结果：反馈 A：离线导出耗时 8 分钟，试点管理员建议增加进度提示；上线日期未确定。"
```

简报应包含“已知事实”“建议行动”“待确认”三部分。结合输入核对以下内容：

- “离线导出耗时 8 分钟”保留在事实中，并标注输入编号 A。
- “增加进度提示”作为建议行动呈现，负责人标为“未指定”。
- 上线日期保持为“尚未确定”，列入待确认事项。

通过工具调用记录或服务日志，还可以确认 VikingBot 是否读取了 `SKILL.md`。这一步用于核对简报是否基于指定技能生成。

## 换一组输入

在另一个会话中提供第二组反馈，观察 Agent 能否复用同样的整理方法。使用新的会话可以避免上一组反馈影响本次结果；重复体验时，可以将示例中的会话名换成新的名称。

```bash
ov chat --session feedback-skill-b -m "请先发现并读取 viking://agent/skills/feedback-brief/SKILL.md，按技能整理以下输入，只在对话中返回结果：反馈 B：登记模板缺少问题分类字段；有 3 条重复反馈，负责人未指定。"
```

这份简报应保留“缺少问题分类字段”和“3 条重复反馈”，标注输入编号 B，并将负责人标为“未指定”。建议行动可以包括补充分类字段、合并重复反馈，同时注明它们是基于输入提出的建议。

对照两份结果：内容应随输入变化，三部分结构、行动表和依据标注应保持一致。你也可以查看[简报示例与技能读取记录](/quickstart/skill-output-zh-v1.txt)，了解输出形式。

## 检查结果

| 检查项 | 预期结果 |
| --- | --- |
| 技能已添加 | 技能列表中存在 `feedback-brief`，且 `SKILL.md` 可读取 |
| Agent 已读取技能 | 工具调用记录或日志中包含对 `SKILL.md` 的读取 |
| 工作方法可复用 | 两份简报都包含约定的三部分结构、行动表和输入编号 |
| 内容符合输入 | 数字与事实保持准确，建议有明确标注，缺失信息保持为待确认 |

模型生成的措辞可能有所不同，核对时以输入事实和技能要求为准。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 技能未出现在列表中 | 查看导入命令的处理结果；如果导入报错，按错误信息检查服务连接、目录权限或模型配置 |
| CLI 能读取技能，VikingBot 无法访问 | 核对两者连接的服务和账号，并确认 VikingBot 使用的身份能够读取该目录 |
| 对话中没有技能读取记录 | 确认提示词中的技能路径可读取，并检查 VikingBot 的 OpenViking 工具配置 |
| 简报结构或内容不符合要求 | 先确认 Agent 已读取技能，再指出具体差异，请它按技能要求修订 |

## 继续使用

你可以把自己的工作方法整理为 `SKILL.md`，添加到 OpenViking 后供 Agent 复用。技能格式、更新方式以及其他客户端的接入方法，见[技能参考](../api/04-skills.md)。

如果希望让 Agent 使用技能生成可持续维护的知识库文件，可以继续阅读[上下文编译](13-compile.md)。体验结束后，如需清理样例，可在 Studio 中确认 `feedback-brief` 是本次添加的技能后删除。
