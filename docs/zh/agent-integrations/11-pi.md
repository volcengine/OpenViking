# pi

为 [pi](https://github.com/earendil-works/pi) 提供跨会话的长期记忆。扩展基于 pi 原生扩展 API 运行在 pi 进程内：每次提问时召回相关记忆，把每一轮对话捕获进 OpenViking session，把服务端的 MCP 工具注册为 pi 原生工具，并可选择接管 pi 的压缩。

源码：[examples/pi-coding-agent-extension](https://github.com/volcengine/OpenViking/tree/main/examples/pi-coding-agent-extension)

## 安装

前置条件：Node.js 22.19.0+ 和 npm、pi coding agent（`npm i -g @earendil-works/pi-coding-agent`），以及一个 OpenViking 服务（托管或自建；本地服务可用 `curl http://localhost:1933/health` 检查）。

连接托管服务时选择 **OpenViking Managed Service**，然后：

- **火山引擎：** 输入服务 API key，URL 由安装器填写。
- **BytePlus：** 输入 API key。见 [BytePlus 接入指南](../guides/27-byteplus-setup.md)。

```bash
curl -fsSL https://openviking.ai/install | bash
# AI agent 如不确定是否执行，可先阅读脚本头部，其中写明了它会做什么、如何核实。
```

安装器把扩展装到 pi 的自动发现目录之一 `~/.pi/agent/extensions/openviking`，并配置 `~/.openviking/ovcli.conf`。不要再对该路径执行 `pi install`：扩展会被加载两次，`/viking` 也会出现两次。

从仓库手动复制：

```bash
git clone https://github.com/volcengine/OpenViking.git
cd OpenViking
node examples/memory-plugin-shared/sync.mjs
mkdir -p ~/.pi/agent/extensions/openviking
cp -R examples/pi-coding-agent-extension/. ~/.pi/agent/extensions/openviking/
npm ci --prefix ~/.pi/agent/extensions/openviking --omit=dev --ignore-scripts
```

`sync.mjs` 生成扩展不在 git 中的 `shared/` 目录；复制前先运行，每次 `git pull` 后再运行一次。凭据来自 `OPENVIKING_*` 环境变量、`~/.openviking/ovcli.conf` 或 `~/.openviking/ov.conf`；`node ~/.pi/agent/extensions/openviking/scripts/setup.mjs` 会写入 `ovcli.conf`。`plugin.pi` 下的设置覆盖共享的 `plugin` 键。

## 验证

启动 `pi`。连接成功后，底栏显示 `OV ✓` 状态段，`/viking` 会打印会话映射和已注册的 `openviking_*` 工具数量。问一件之前会话里提过的事，确认召回生效。

出现问题时，运行 `node ~/.pi/agent/extensions/openviking/scripts/ov-memory-doctor.mjs`，或让 agent 使用 `ov-memory-doctor` skill。

## pi 上的不同之处

- **`/viking` 和 `/viking commit`：** `/viking` 打印状态，包括已注册的工具数或最近一次 MCP 握手错误；`/viking commit` 立即提交当前会话。
- **MCP 工具作为原生工具：** 扩展注册服务端 MCP `tools/list` 返回的全部工具，统一加 `openviking_` 前缀（`openviking_find`、`openviking_read`、`openviking_search` ……）。服务端增删工具，在下一个 pi 会话生效。`mcpEnabled: false` 关闭工具和自带 skills，召回与捕获照常。握手失败不会阻塞启动，底栏显示 `tools ✗`。
- **接管**（`takeoverEnabled`，环境变量 `OPENVIKING_TAKEOVER`，默认关闭）：OpenViking 在 pi 的 `context` hook 中用最新归档概览替换已提交的本地历史，只保留最近几轮。开启接管后由接管负责提交（不设置服务端的 token 和空闲提交）。接管失败时放行：提交或归档概览未就绪时，pi 保留完整历史或使用自己的压缩。见 [pi 接管](./16-capability-reference.md#pi-takeover)。
- **事件：** 在 `turn_end` 捕获，压缩前（`session_before_compact`）和 `session_shutdown` 时提交，pi 给 `session_shutdown` 3 秒。
- **viking:// 防护：** pi 的 `read`/`grep`/`find`/`ls`/`write`/`edit` 作用于 `viking://` 路径时被拦截，并提示对应的 `openviking_*` 工具；携带该 URI 的 `bash` 命令照常执行，结果附带提示。

## 封存密钥 {#seal-secrets}

`sealSecrets` 让 OpenViking 服务端已知的密钥不出现在模型看到的内容里；模型在工具调用中写下的引用只在交给工具时还原为真实值。默认关闭，需要 OpenViking 服务端 0.5.7 或更新版本。

| 设置 | 环境变量 | 默认值 | 作用 |
|------|----------|--------|------|
| `sealSecrets` | `OPENVIKING_SEAL_SECRETS` | `false` | 封存你输入的内容和每个工具结果 |
| `enrollToolSecrets` | `OPENVIKING_ENROLL_TOOL_SECRETS` | `false` | 同时保存工具结果中发现的新密钥 |

两者都不能在工作区文件中设置。无法封存时（服务端低于 0.5.7，或 `/health`、封存、还原调用失败）会停止：你输入的内容不发送，工具结果被扣下，引用无法还原的工具调用不执行。不覆盖：系统提示词和上下文文件、skill 与 prompt 模板文本、召回块、压缩摘要，以及开启封存之前的历史。详见 [扩展 README](https://github.com/volcengine/OpenViking/blob/main/examples/pi-coding-agent-extension/README.md)。

召回、捕获、提交、离线重试等与其他集成共用：见 [集成能力参考](./16-capability-reference.md)。
