# 目录 TTL

TTL 默认关闭，作用于用户和 peer 的 `events/YYYY/MM/DD` 日期目录及 `sessions/{session_id}`。resources 和其他记忆类别不在范围内。

## 配置与全量应用

TTL 复用实例默认配置和 Account 配置覆盖（Web Studio 中的“库”对应 Account），支持全局默认、类型默认和以下三类根：

- `viking://user/{user_id}/memories/events`
- `viking://user/{user_id}/peers/{peer_id}/memories/events`
- `viking://user/{user_id}/sessions`

每个具体根 URI 都能独立配置；不同 user、不同 peer 可以使用不同期限，并非全库只有三个配置项。Session 位于 user 下，没有 peer sessions 根。未覆盖的根继承对应类型，新建 user／peer 的目录也自动继承。

先合并同一节点的 Account 覆盖 → 实例运行时配置 → 启动配置，再选择具体根 → 类型（`user_events`、`peer_events`、`sessions`）→ `global`。Account 的 `global` 不会盖掉实例中更具体的类型默认；例如实例 `sessions=30 天`，需要通过 Account 的 `sessions` 节点覆盖该类型。user／peer 身份用于定位根，不增加配置层。

`disabled` 在该节点停止继承，`inherit` 跳过该节点；PATCH 中的 `null` 删除当前层覆盖。类型默认未配置时继承 `global`，全局默认关闭。可选的最佳实践为 User events 60 天、Peer events 60 天、Sessions 30 天，仅在用户主动选择后启用。

年月、日期、单 Session、子目录和文件只展示期限，不支持编辑。首次启用和修改根策略会按优先级更新仍有效的已有目录，并为历史未纳管目录补 TTL。相对期限按原业务时间加新天数重算，绝对期限取配置值；缩短策略可能立即过期。关闭有效策略会清除仍有效目录的期限，已过期或已删除的对象不会恢复。

配置请求逐层取得直接子目录清单，只保留名称，以最多 8 个并发更新。清理删除前面的目录不会使后续目录漏出清单。请求等待目录元数据更新完成，部分失败会返回未完成的目录；重试同一份配置即可继续。相对策略下，历史目录缺少可靠原始时间时会报告未完成，不使用修改配置的时间或目录 modTime 代替。空 event 日期目录可以创建，首次写入正文后才开始计时。

批量应用策略和新目录初始化期限时，从配置源读取最新策略；每个账号的批量更新复用同一份策略，普通内容更新使用已保存的期限。这些读取不修改运行时配置缓存及其刷新机制。目录名称清单的内存随当前父目录的直接子目录数量增长。

## 期限计算

每个生命周期目录在 `.meta.json` 保存一个 `expires_at`。相对期限使用固定基准：Session 复用 `created_at`，events 用 `received_at` 记录首次成功写入时间；`ttl_days` 只保留在策略配置中。events 兼容读取旧 `.ttl.json`。AGFS 元数据更新保留同一文件中的其他业务字段，目录 stat 返回该目录自己的 `expires_at`。

- events：第一次成功写入内容时开始计时，路径日期仅用于归组。后续追加或修改正文不自动续期；用户修改根策略可以调整仍有效目录的期限。
- Session：创建时继承 `sessions` 根策略。相对期限为创建时间加配置天数，绝对期限取配置值。成功追加消息、完成 commit 和任务重放都不改变期限。
- 本期不支持写入自动续期或续期补偿。用户可在到期前修改库或根策略，重算仍有效目录的期限；相对期限始终从固定基准计算，不从修改配置的时间重新计时。活跃 Session 也按原期限到期。

目录内的消息、附件、归档、L0/L1/L2 共用同一到期时间，不做 JSONL 消息级 TTL。无 `ttl_generation`、单 Session 覆盖或逐文件模式。

正文、摘要格式和抽取 Context 不增加 TTL 字段；读取时统一查询所属目录。正文中的同名字段只作为用户内容。首次 Event 写入先登记目录期限，正文写入失败则回滚；不增加写入日志或成功后的第二次元数据写入。

## 可见性

UTC 时间达到 `expires_at` 后，目录及全部后代不可见。直接访问返回 404；Session 列表、文件列表、find/search/recall、grep/glob 会过滤到期内容，并补足可见候选。

结构化对象回显实际所属目录的 `expires_at`，未开启时明确返回 `null`。跨目录结果逐项回显；单对象的文本或列表响应在外层提供期限。纯 URI 列表兼容模式和下载字节格式不变，仍执行服务端过滤。年月及根目录没有共同期限，返回 `null`；根目录另展示 `policy`、`effective_policy`。

快照读取优先使用当前目录期限，目录已删除时检查快照内期限。原样导入或恢复会拒绝覆盖仍有 TTL 的目录，并拒绝已过期的源数据，避免覆盖时丢失期限。每个受影响目录只校验一次，不按文件重复读取相同的元数据。

## 清理任务与性能

任务沿用 Session commit 的 QueueFS 离线执行框架。扫描器读取使用过 TTL 的账号下的目录元数据，将到期目录送入队列，分批推进并等待队列消费。完成一轮后默认间隔一天再扫描。账号标记不保存具体对象的期限，不再维护逐对象调度索引或领取租约。

删除前以元数据文件锁复查目录期限；Session 复用现有 Session 写入互斥锁。目录内逐文件加锁删除，锁忙则重试，不使用 tree 锁，不逐文件判断过期时间。先按账号和目录 URI 删除全部关联向量并确认清空，再删除目录内正文、消息、附件及 L0/L1。确认正文已移除后，最后删除目录元数据并确认目录消失。向量记录不需要 `expires_at` 字段；已有账号和 URI 字段可以覆盖整个子树，包括对应文件已经不存在的向量。目录外的上层摘要保持原样，删除不触发 LLM、embedding 或摘要重建。

锁忙、向量删除失败或正文残留时，保留目录期限供下轮扫描重试。扫描器重启后从目录元数据重新发现候选，不依赖持久化扫描游标或任务历史。最后一次确认请求失败仍报错，即使数据实际已删除。对于目录及元数据早已丢失、仅剩向量的历史孤儿记录，目录扫描无法自行发现；已知原目录 URI 时仍可通过 strict 删除清理。

每轮扫描成本为使用过 TTL 的账号下 owner 目录数的 O(N)。每批最多检查 `batch_size` 个目录，在目录之间检查时间预算，并等待队列消费后推进下一批。存储列举延迟或积压可能延长一轮扫描；普通写入、复制和恢复不再维护第二份到期记录。

系统执行 strict 清理时，向量删除直接使用目录 URI 范围，不为收集向量 URI 额外遍历文件树。逐文件删除仍保留锁和结果确认。

向量查询在一次查询及其补查中复用 owner 元数据，只校验目录期限，不逐条检查正文或摘要文件是否存在。无元数据的历史对象按 owner 目录是否存在判断。发现过期或已删除的 owner 后，补查直接排除整个目录及后代，保留其他目录的有效候选；单文件删除的向量一致性沿用原删除链路。目录 `count` 沿用后端计数，随物理删除收敛，不为实时扣除过期内容扫描全部向量；返回的内容仍即时执行到期过滤。计费允许随异步物理删除延迟；云端计费、网关转发和备份不由 OV 清理完成状态自动证明。

## 接口

- [TTL 配置](../configuration/01-server.md#ttl)：库、类型及根目录策略。
- [期限查询](../api/12-content.md#文档到期时间)：`GET /api/v1/content/ttl`，SDK/MCP `get_ttl`，CLI `ov ttl get`。
- [Session](../api/05-sessions.md#session-ttl)：统一继承根目录策略，创建/配置接口不接收 TTL 参数。

异步 Session commit 写回会在短暂的 Session 锁内核对原 Phase 1 的 `task_id`。旧任务不能把已删除 Session 的结果写入复用同 ID 的新 Session，也不能从已删除来源重建 event。新的 Session 仍可导入历史日期的事件。普通正文 I/O 不持有公共元数据锁；清理在阻止新写入后检查已有文件锁，包括正文尚未落盘的写入。
