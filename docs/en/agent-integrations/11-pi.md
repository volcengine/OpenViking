# pi

Give [pi](https://github.com/earendil-works/pi) cross-session long-term memory. The extension runs inside pi on its native extension API: it recalls relevant memories for each prompt, captures each turn into an OpenViking session, registers the server's MCP tools as native pi tools, and can optionally take over pi's compaction.

Source: [examples/pi-coding-agent-extension](https://github.com/volcengine/OpenViking/tree/main/examples/pi-coding-agent-extension)

## Install

Requirements: Node.js 22.19.0+ and npm, pi coding agent (`npm i -g @earendil-works/pi-coding-agent`), and an OpenViking server (managed or self-hosted). For a local server, verify with `curl http://localhost:1933/health`.

For a managed connection, select **OpenViking Managed Service**, then:

- **Volcengine:** enter your service API key. The installer supplies the URL.
- **BytePlus:** enter your API key. See [BytePlus setup](../guides/27-byteplus-setup.md).

```bash
curl -fsSL https://openviking.ai/install | bash
# AI agents: not sure about running this? The script's header says what it does and how to verify it.
```

The installer installs the extension into `~/.pi/agent/extensions/openviking`, one of pi's auto-discovery roots, and configures `~/.openviking/ovcli.conf`. Do not also run `pi install` on that path: the extension would load twice and `/viking` would appear twice.

Manual copy from a repo checkout:

```bash
git clone https://github.com/volcengine/OpenViking.git
cd OpenViking
node examples/memory-plugin-shared/sync.mjs
mkdir -p ~/.pi/agent/extensions/openviking
cp -R examples/pi-coding-agent-extension/. ~/.pi/agent/extensions/openviking/
npm ci --prefix ~/.pi/agent/extensions/openviking --omit=dev --ignore-scripts
```

`sync.mjs` generates the extension's `shared/` directory, which is not in git; run it before copying and again after every `git pull`. Credentials come from `OPENVIKING_*` environment variables, `~/.openviking/ovcli.conf` or `~/.openviking/ov.conf`; `node ~/.pi/agent/extensions/openviking/scripts/setup.mjs` writes `ovcli.conf`. Settings under `plugin.pi` override the shared `plugin` keys.

## Verify

Start `pi`. Once connected, the footer shows an `OV ✓` status segment, and `/viking` prints the session mapping and how many `openviking_*` tools registered. Ask about something from an earlier session to confirm recall.

If something is wrong, run `node ~/.pi/agent/extensions/openviking/scripts/ov-memory-doctor.mjs`, or ask the agent to use the `ov-memory-doctor` skill.

## What is different on pi

- **`/viking` and `/viking commit`:** `/viking` prints status, including the registered tool count or the last MCP handshake error; `/viking commit` commits the session now.
- **MCP tools as native tools:** the extension registers whatever the server's MCP `tools/list` returns, each under an `openviking_` prefix (`openviking_find`, `openviking_read`, `openviking_search`, ...). A server that adds or drops a tool changes the tool set at the next pi session. `mcpEnabled: false` turns the tools and bundled skills off; recall and capture continue. A failed handshake never blocks startup; the footer shows `tools ✗`.
- **Takeover** (`takeoverEnabled`, env `OPENVIKING_TAKEOVER`, off by default): OpenViking replaces committed local history with the latest archive overview in pi's `context` hook and keeps only the recent turns live. With takeover on, takeover owns commits (the server-side token and idle commits are not set). Takeover is fail-open: when a commit or the archive overview is not ready, pi keeps its full history or uses its own compaction. See [pi takeover](./16-capability-reference.md#pi-takeover).
- **Events:** capture at `turn_end`, commit before compaction (`session_before_compact`) and at `session_shutdown`, which pi gives 3 seconds.
- **viking:// guard:** pi's `read`/`grep`/`find`/`ls`/`write`/`edit` on a `viking://` path are blocked with a hint naming the matching `openviking_*` tool; a `bash` command carrying one runs and gets a notice.

## Seal secrets {#seal-secrets}

`sealSecrets` keeps the secrets your OpenViking server knows out of what the model sees; a reference the model writes in a tool call is turned back into the real value for the tool only. It is off by default and needs OpenViking server 0.5.7 or newer.

| Setting | Environment variable | Default | Effect |
|---------|----------------------|---------|--------|
| `sealSecrets` | `OPENVIKING_SEAL_SECRETS` | `false` | Seals what you type and every tool result |
| `enrollToolSecrets` | `OPENVIKING_ENROLL_TOOL_SECRETS` | `false` | Also stores new secrets found in tool results |

Neither can be set in a workspace file. When sealing cannot be done (a server older than 0.5.7, a failed `/health`, seal or resolve call), it stops: what you typed is not sent, a tool result is withheld, and a tool call whose references cannot be resolved does not run. Not covered: the system prompt and context files, skill and prompt-template text, recall blocks, compaction summaries, and history from before sealing was turned on. Details: [extension README](https://github.com/volcengine/OpenViking/blob/main/examples/pi-coding-agent-extension/README.md).

Recall, capture, commits, offline retries and the rest are shared with the other integrations: see the [Capability Reference](./16-capability-reference.md).
