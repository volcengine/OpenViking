# OpenViking 扩展参考

[接入引导](https://docs.openviking.net/agents/zh/onboarding.md)已包含普通接入需要的解释。本文件用于回答用户追问或处理扩展目标，无需在开始接入时通读；只查与当前问题有关的部分。知识不代表当前工具一定支持，也不授予执行额外任务的许可。

## 内容类型与处理状态

- 会话保留支持范围内的交互过程；记录存在不证明包含最新消息。
- 记忆由服务按策略从已提交的会话提取、更新，例如偏好、事项和经验。记忆可能遗漏或过时，当前用户要求优先。
- 资料保存需求、方案、报告等可读取正文；聊天提到文件不等于原件上传，正文入库也不证明所有附件已备份。
- 技能提供可复用的操作方法；保存经验不会自动生成或安装技能。

消息写入、提交提取、提取完成、检索命中、实际采用是不同状态。确认状态要检查对应结果；不能从文件存在推断提取完成，从来源计数推断答案使用过。

## Hooks、规则与资源消耗

Hooks 是宿主在会话事件发生时运行插件的机制，用于载入背景、召回、捕获或触发提交。具体事件、信任要求、发送范围和提交时机以安装版本为准。客户端不使用 Hooks 时，以其实际插件机制说明，不要求用户寻找不存在的审批入口。

长期规则指导 Agent 何时补查原文、主动保存哪些内容以及怎样反馈；不创建后台文件监控器，也不保证每轮一定正确执行。已有自动注入足够时不强制追加查询，普通对话已捕获时不再手动保存一遍。

检索、注入和整理可能消耗上下文与模型调用。按任务相关性取回背景，需要细节时才读原文；不能承诺固定节省比例。与宿主原生记忆是否重叠，要核对各自作用范围，不能笼统宣称替代。

## 目录与分层读取

OpenViking 通过目录和 URI 保留内容归属与来源。L0 摘要帮助识别主题，L1 概览帮助理解内容，L2 原文供细节核对；按问题选择粒度，不默认加载全部历史，也不要求用户先学这些术语。

接续工作先用注入的上下文和相关记忆、笔记，需要细节再读会话原文；跨多个会话时结合日期、范围和原记录核对，不能把最新一个会话当成整个项目。已完成事项不重新打开，历史方案不当作当前上线事实，摘要冲突时回查原文。

## 跨 Agent 与身份

另一会话或 Agent 接入同一身份可访问的内容后，可以用已有背景接续工作。它不实时复制整个聊天窗口、设备状态、客户端规则或未上传附件；最近尚未提交或处理的内容也可能缺失。

只检查用户选定两端的身份与内容可用性，不为解释主动安装第二个客户端。验证要由独立上下文实际取回背景；原聊天读取成功不等于跨 Agent 验证成功。

同一地址不等于同一用户。绑定或切换身份不自动搬运旧资料；需重新对齐读写范围，保留原配置。没有实际绑定或切换能力时说明限制，不编造命令。

## 偏好、经验与知识整理

偏好帮助协作符合稳定的表达和判断方式；仅在当前工作适用时采用，不把一次选择固化为永久偏好，不为展示效果收集无关个人信息。

经验保留有效做法、纠正和适用条件。说明它为什么适合当前任务，避免机械照搬；是否启用提取、是否可检索需核对，不能承诺每轮自动产生经验。

知识整理／Compile 适合基于多份材料形成有来源的主题知识或 Wiki，通过 `ov` 命令行的 `ov compile` 执行（安装器的 `cli` 一项装的就是 `ov`），由服务端的 Compile Runtime 运行，结果写回 OpenViking。先检查服务是否支持、来源范围和输出位置，再按用户授权执行；用法见 https://docs.openviking.net/zh/context-compilation/01-overview 。安装插件、导入历史或生成普通摘要都不等于已执行 Compile。
