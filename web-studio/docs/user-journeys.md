# Web Studio 接入与身份使用流程

Web Studio 将用户工作台和管理后台作为两种工作区域。管理权限决定后台可用能力；日常入口由可用数据身份和用户保存的偏好决定。

## 首次进入

Server 内置 Studio 从 `/studio/` 访问，首次引导自动带入该 Server 的 origin。独立部署的 Studio 仍可填写其他服务地址。语言和主题即时生效，服务与凭据必须验证后才能进入。

| 配置                    | 自动识别后的行为                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------- |
| User Key                | 绑定服务端返回的 Account/User，默认进入工作台                                                   |
| Account Admin Key       | 同时拥有自己的数据身份和本 Account 管理能力，默认进入工作台，提供管理后台入口                   |
| Root Key                | 进入后台，提示创建使用身份或配置已有 User Key                                                   |
| 数据 Key 与独立管理 Key | 工作台使用数据 Key，后台使用管理 Key；默认进入工作台                                            |
| 本地 dev                | 无需 Key，默认进入工作台；后台提供服务配置等可用服务功能，不提供依赖 API Key Manager 的成员管理 |

User、Account Admin、Root 均可填写主 API Key 输入框，服务端返回的角色与身份为准。单独填入管理字段的 Account Admin Key 同样可作为该管理员自己的数据身份。首次验证不自动枚举身份目录；需要选择其他身份时可展开高级选项，API Key 模式下仍需对应用户凭据。

## Root 初始化与团队成员创建

Root-only 后台提供“创建使用身份”和“配置已有 User Key”。创建成功后展示凭据，管理员可以复制、关闭，或明确选择“进入工作台”。只有明确进入时才切换并保存工作台身份，且等待持久化完成后导航。

创建团队成员不自动切换管理员当前数据身份。团队常见流程为：平台 Root 建立 Account 与首位 Account Admin；Account Admin 管理本 Account 成员；成员使用自己的 User Key 访问工作台。

## 再次进入与身份恢复

- 刷新和直接访问具体 URL 保留路由用途，权限仍由服务端校验；默认入口不会覆盖显式深链。
- 从 Studio 根入口进入时，有效的显式默认偏好优先；自动规则为有数据身份进入工作台，只有管理凭据进入后台。
- 默认偏好按本机连接配置保存，兼容已有服务/Account 偏好。管理 Account 切换不会改变这个连接的默认入口。
- 工作台的 Account/User/数据 Key 与后台管理的 Account 分别记忆，按连接隔离，并随加密配置保存。后台管理 Account B 后返回工作台，恢复此前的 Account A/User；再次进入后台继续管理 B。
- 显式选择一个新的数据用户会更新工作台身份；管理 Account 切换及管理页的 ACL 授权身份恢复都保留原工作台身份。
- 激活另一份连接后先重新验证，再判断当前区域是否可用。普通 User 连接从后台回到工作台，Root-only 连接从工作台进入后台；连接设置在两种区域保持可修复。
- 更换浏览器或 origin（域名、协议、端口）会使用新的本机存储空间；已有凭据失效时进入连接修复，不重新执行全套首次引导。

## 存储与部署

HTTPS、localhost 等支持 Web Crypto 与 IndexedDB 的环境，继续自动加密保存，无需保险箱口令。无法使用这些能力时，Studio 使用本页内存保存临时连接，并明确提示刷新/关闭后需重新配置；不读取或覆盖旧加密记录，不将新 Key 写入明文 Web Storage。

仅本页模式用于维持可用性，不为普通 HTTP 增加传输加密。团队和生产部署应使用 HTTPS。存储损坏或解密失败仍停止恢复并保留原记录，不静默清除或覆盖。

API Key 模式的工作台不回退到 Root 凭据，也不读取 Root 用户目录；trusted 模式继续按服务端协议使用受信凭据及 Account/User 声明。前端变化不改变服务端权限。
