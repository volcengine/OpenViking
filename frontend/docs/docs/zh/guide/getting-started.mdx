# 快速开始

OpenViking UI 是构建 OpenViking AI 应用界面的 React 基础。OpenViking 是面向 AI 智能体的上下文数据库；本 workspace 提供 Rslib 构建、双语文档、分层目录约定与样式隔离方案。应用负责业务界面、数据、认证与流程编排。

包提供 FileTree、FilePreview、五种文件类型图标，以及五个业务模块占位组件。当前范围见[组件概览](../components/)和[模块概览](../modules/)；业务 Hook 尚未实现。

## 本地运行

使用 Node.js 22.12 或更新版本。在仓库根目录执行：

```bash
cd frontend
npm ci
npm run dev
```

打开 Rspress 输出的 `/ui/` 地址。英文使用 `/ui/`，简体中文使用 `/ui/zh/`；顶部语言菜单支持在对应页面间切换。

workspace 开发插件会在文档服务器启动前运行 Rslib watch。文档示例通过公开导出使用构建产物，不使用源码别名。React 和 ReactDOM 为 peer dependencies，声明支持 React 18.2 和 React 19；文档应用使用 React 19。

## 组织应用代码

- `packages/react/src/components/`：可复用视图，通过 props 接收处理后的数据，通过回调表达用户意图。
- `packages/react/src/modules/`：五个可导入的占位组件，业务 Hook 与组合交互后续迁入。
- `packages/react/src/hooks/` 与 `utils/`：包内共享逻辑，没有公开子路径。
- `docs/docs/en/` 与 `docs/docs/zh/`：对应的双语文档页面；共用的可运行示例放在 `docs/docs/_demos/`。

应用专属流程与认证留在应用层；模块 Hook 通过共享 Client 加载数据。组件不获取业务数据，也不依赖应用路由。

## 公开入口

根入口 `@openviking/react` 导出 FileTree、五个业务模块占位组件及其公开类型。FileTree 和 FilePreview 也可通过各自的 `components/<模块>` 子路径使用。`@openviking/react/icons` 提供五种文件类型图标。

没有 `components` 或 `modules` 分类聚合 JavaScript 入口。业务占位组件使用独立的 `modules/<模块>` 入口：

```tsx
import { FileBrowser } from '@openviking/react/modules/file-browser';
import '@openviking/react/modules/file-browser/style.css';

<FileBrowser />;
```

五个占位组件均接受 `className`、`style` 和可替换的 `labels`，无需 Provider。可运行示例与 Props 类型见[业务模块](../modules/)。

业务模块将按具体能力组合取数 Hook 与视图，从对应模块入口分别导出 Hook 和组合视图，接入方可只复用 Hook 并自行组装 UI。共享 Client 遵循 OpenViking 原生 API 的路径、入参和响应类型；认证、账号作用域、路由、权限及完整页面流程由宿主负责。业务 Hook 及跨模块公共 Hook 当前尚无实现或导出。

模块规划聚焦个人终端：`file-browser` 将目录、搜索和预览作为一个整体，统一维护资源选择、结果定位、内容加载与刷新联动；宿主可按需受控指定当前资源。`console` 将 VikingBot 与 TUI 作为一个交互面板，内部协调模式切换、工具栏和公共上下文，各自保留会话与命令状态。Agent 接入、任务管理和当前 User 的用量统计分别接入。宿主负责模块间布局、导航与联动；产品引导、资源与 Skill 导入流程及同步配置由宿主负责，经验看板和会话内容通过文件浏览模块的预览扩展接入，管理后台不在此范围内。这些交互仍为规划，当前模块组件仅展示占位内容。

请求配置将通过 `OpenVikingProvider` 下发：`baseURL` 和 headers，鉴权由宿主明确提供。共享 Client 将复用现有 OpenAPI 生成 SDK 与 Axios 请求层；Fetch / SSE 调用共用其服务地址与鉴权头生成逻辑。模块和独立 Hook 可通过 `requestOptions` 按字段覆盖，优先级为局部配置、最近的 Provider、库默认值；`baseURL` 为空表示同源请求。标准 API 接入无需逐模块实现 Adapter，非标准网关集中在宿主请求接入层适配。Client 和 Provider 当前仍为规划，尚无实现或导出。

## 样式

样式通过 CSS Modules 隔离，变量使用 `--ov-ui-` 前缀，不引入全局 reset。JavaScript 导入不会自动加载 CSS；按需选择整包、分类集合或独立样式：

```ts
import '@openviking/react/style.css';
// 也可选择 @openviking/react/components/style.css
// 或 @openviking/react/modules/style.css。
// 独立入口：@openviking/react/<分类>/<模块>/style.css。
```

Rslib 将 ESM JavaScript、TypeScript 声明和 CSS 输出到 `packages/react/dist/`。每个公开样式入口可独立使用；模块样式当前覆盖占位视图，组合视图迁入后须包含其组件依赖。后续单独使用 Hook 无需 CSS。

## 构建与检查

在 `frontend/` 中执行：

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run preview
```

`lint` 先构建组件库，再通过 Rslint 检查代码规则与类型，并使用 Prettier 检查格式。`typecheck` 检查组件库、构建配置与文档 TypeScript 项目。`test` 构建组件库并验证公开包入口。`build` 生成组件库和静态文档，站点输出到 `docs/doc_build/`。

在 `npm run lint --` 后传入文件或加引号的 glob，可限定格式检查和 lint 的目标；类型检查仍覆盖配置的完整项目。JavaScript 和 TypeScript 文件最多 200 行，不计空行和纯注释行。

## 部署

`frontend/` 下的变更触发 UI 检查。在 `main` 上，现有产品文档部署会将 UI 站点合并到同一完整产物或存储桶的 `/ui/` 路径。npm 发布使用独立的标签触发流程，本地构建与测试不会发布包。
