# 快速开始

OpenViking UI 是 OpenViking 仓库中的 React 组件库 workspace。当前版本提供构建和文档基础设施，并以 `StatusBadge` 作为示例模块。

该包目前为私有包，尚未发布到 npm。文件树、预览和 TUI 尚未迁入。

## 本地运行

使用 Node.js 22.12 或更新版本。在仓库根目录执行：

```bash
cd frontend
npm ci
npm run dev
```

打开 Rspress 输出的 `/ui/` 地址。使用顶部语言菜单切换为简体中文，或直接访问 `/ui/zh/`。本地和生产环境使用相同的部署前缀。

## 使用示例

在此 workspace 内，从公开包入口导入组件及样式：

```tsx
import { StatusBadge } from '@openviking/react';
import '@openviking/react/style.css';

export default function Example() {
  return <StatusBadge status="ready">已连接</StatusBadge>;
}
```

React 和 ReactDOM 为 peer dependencies，声明支持 React 18.2 和 React 19；文档应用使用 React 19。

官方 workspace 开发插件会在文档服务器启动前运行组件库的 Rslib watch。开发与生产示例都通过公开包入口消费构建产物，验证应用将使用的 JavaScript 和样式。Rslib 将 ESM JavaScript、TypeScript 类型声明和 `style.css` 输出到 `packages/react/dist/`；公开样式入口仍为 `@openviking/react/style.css`。

## 构建与检查

```bash
npm run lint
npm run lint:fix
npm run typecheck
npm run build
npm run preview
```

静态站点输出到 `frontend/docs/doc_build/`。也可以通过 `npm run build:lib` 单独构建组件库。检查命令会先构建组件库，让示例能够解析其声明。`npm run lint` 通过 Rslint 检查代码规则与类型，并使用 Prettier 检查格式。`npm run lint:fix` 应用可用的 lint 修复并格式化文件。`npm run typecheck` 使用 TypeScript 的 `tsc --noEmit` 检查组件库、构建配置和文档项目，不运行格式检查和 lint 规则。TypeScript 也用于生成组件库的类型声明。

在 `--` 后传入文件、目录或加引号的 glob，即可限定格式检查和 lint 规则的目标。不传参数时，`lint` 和 `lint:fix` 检查整个前端 workspace。类型检查始终覆盖配置的完整 TypeScript 项目，即使 lint 指定了文件。类型错误需要手动修正。

JavaScript 和 TypeScript 文件（含 JSX、TSX）每个文件最多 200 行，不计空行和纯注释行，超出时 lint 报错。

```bash
npm run lint -- packages/react/src/index.ts
npm run lint -- packages/react/src/index.ts docs/rspress.config.ts
npm run lint:fix -- 'docs/docs/_demos/**/*.tsx'
```

## 公开入口

从 `@openviking/react` 或 `@openviking/react/components/<模块>` 导入已实现能力。不提供 `components`、`pages` 分类聚合 JS 入口。原 `/tree`、`/preview`、`/console`、`/tui`、`/viking-bot` 路径已替换为分层组件路径。

目前预留 `file-tree`、`file-preview`、`tui`、`viking-bot`、`scope-switcher`、`agent-connect`、`resource-import` 七个业务模块，尚无组件可导入。页面及公共 Hook 尚无实现或导出，首个页面暂未定义。

## 样式

按需选择整包、组件集合或单组件样式，各入口可独立使用，JS 不自动加载 CSS。业务占位模块目前提供空样式文件。

```tsx
import { StatusBadge } from '@openviking/react/components/status-badge';
import '@openviking/react/components/status-badge/style.css';
// 也可选择 @openviking/react/components/style.css 或 @openviking/react/style.css
```

页面实现后再提供 `pages/style.css` 和 `pages/<页面>/style.css`，单页面样式包含所需组件样式；当前尚无页面 CSS 导出。

模块通过 CSS Modules 隔离样式，不依赖 Tailwind、Arco 或全局 reset。可以在容器元素上覆盖主题颜色：

```css
.my-workbench {
  --ov-ui-status-ready: #187347;
  --ov-ui-status-processing: #2563c5;
  --ov-ui-status-error: #c43838;
  --ov-ui-radius: 6px;
}
```

文档提供亮色与暗色主题下的示例。应用需根据自身背景选择合适的颜色。

## 部署

`frontend/` 下的变更会触发 UI 检查工作流。在 `main` 分支上，现有产品文档部署流程会构建 UI 站点，并将其放入同一产物或存储桶的 `/ui/` 路径。

GitHub Pages 发布完整站点产物，因此部署前会合并组件站与产品文档。TOS 部署复用仓库现有凭证。npm 发布属于后续独立步骤。

使用方式与交互示例见 [StatusBadge 状态徽标](../components/status-badge)。
