# FileBrowser 文件浏览

目录树、搜索和文件预览组成的文件浏览区块：读取 OpenViking 的目录和内容，支持预览、编辑、导入导出、历史版本和权限管理，并内置 Wiki 与经验看板。

## 何时使用

- 需要在应用里浏览 OpenViking 的上下文目录（用户、会话、Agent、资源），并预览、编辑其中的文件。
- 希望目录加载、分页、预览和刷新由区块协调：区块通过 `OpenVikingProvider` 请求原生 API，登录、账号作用域、路由和导入流程由宿主提供，权限由服务端校验。
- 只需要纯视图、数据自己加载时，单独使用 [FileTree](../components/file-tree) 和 [FilePreview](../components/file-preview)；需要命令面板或对话时使用 [Console](./console)。

## 引入

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import '@openviking/react/modules/file-browser/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <FileBrowser />
</OpenVikingProvider>;
```

样式入口已包含 FileTree、FilePreview、FileBrowserActionBar、WikiDashboard 和 ExperienceDashboard 的样式。文件内容由 [FilePreview](../components/file-preview) 渲染，需要先安装可选的 peer 依赖 `@ark-design/ui`。Provider 与请求配置的规则见[区块概览](./)。

### 基础用法

展示目录树、搜索和预览的联动，以及 Wiki 与经验看板。底部的按钮切换预览的资源类型，下拉框切换预览操作区的模式。


示例使用固定数据，不访问网络。在搜索框输入 `profile` 查看搜索结果，输入 `error` 查看搜索失败；点击「导入资源」，底部会显示宿主收到的 `onImportResources` 事件。

### ACL 权限管理

开启 `acl` 后，`viking://resources/` 下的节点显示当前用户的有效权限，权限为「可管理」时可以在权限标签的详情里打开授权弹窗。切换「当前权限」查看不同权限下的界面，勾选「模拟保存失败」或「模拟成员加载失败」查看失败状态。

```tsx file="../../_demos/file-browser-acl.tsx" preview

```

示例是离线模拟，不会修改真实授权。

### 预览操作区

`previewActions` 隐藏内置操作，`previewSlots` 追加、替换或隐藏操作区；基础用法示例底部的下拉框可以查看各种模式。

```tsx
<FileBrowser
  previewActions={{
    edit: false,
    delete: false,
    importPack: false,
    configure: false,
  }}
  previewSlots={{
    actionItems: (context) => [
      ...context.defaultActions,
      [
        {
          key: 'share',
          icon: <ShareIcon />,
          label: '分享',
          onClick: () => share(context.path),
        },
      ],
    ],
  }}
/>
```

### FileBrowserPreviewActions

每一项默认在当前资源支持该操作时显示。设为 `false` 隐藏，设为 `true` 不会增加资源本来没有的能力。

| 参数        | 说明                                                                                                                                          | 类型      | 默认值 |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ------ |
| copyPath    | 「复制路径」按钮，位于面包屑旁；预览有路径时显示                                                                                              | `boolean` | `true` |
| viewSwitch  | 「预览 / 源码」切换；只在同时支持两种视图的格式上显示，图片、视频和 `viking://system` 下的目录不支持                                          | `boolean` | `true` |
| edit        | 编辑按钮；只在可写且格式可编辑的文件上显示，经验文件、`viking://system` 下的资源和 L0/L1 摘要不可编辑                                         | `boolean` | `true` |
| copyContent | 「复制内容」操作，复制当前预览的文本或目录摘要，超过预览行数上限时只复制已显示的部分；二进制媒体和 `viking://system` 下的目录不显示           | `boolean` | `true` |
| download    | 「下载」操作，下载文件的原始内容；只在文件上显示                                                                                              | `boolean` | `true` |
| history     | 「查看历史版本」操作；在支持的文本文件和 Wiki 目录上显示                                                                                      | `boolean` | `true` |
| configure   | 「编译配置」操作；只在 Wiki 编译目标的根目录上显示，只读时仍可查看                                                                            | `boolean` | `true` |
| importPack  | 「导入 .ovpack」操作；只在可写的目录上显示，且目录位于 `viking://user`（含 `viking://~`）或 `viking://resources` 下                           | `boolean` | `true` |
| exportPack  | 「导出 .ovpack」操作；在 `viking://user`（含 `viking://~`）或 `viking://resources` 下的文件和目录上显示，`.relations.json` 等内部控制文件除外 | `boolean` | `true` |
| delete      | 「删除文档」操作；只在可管理的文件上显示，目录、`viking://system` 下的文件和 L0/L1 摘要不可删除                                               | `boolean` | `true` |

### FileBrowserPreviewSlots

| 参数         | 说明                                                                                              | 类型                                                                                               | 默认值 |
| ------------ | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------ |
| actions      | 替换整个操作区，`null` 隐藏；替换后需要自己渲染保存、取消和追加的操作，复制路径和权限标签不受影响 | `ReactNode \| ((context: FileBrowserPreviewActionContext) => ReactNode)`                           | -      |
| extraActions | 追加到默认操作区末尾，编辑状态下隐藏                                                              | `ReactNode`                                                                                        | -      |
| actionItems  | 替换默认的操作列表；函数形式可以通过 `context.defaultActions` 复用、追加或重排默认操作            | `FilePreviewActionItems \| ((context: FileBrowserPreviewActionContext) => FilePreviewActionItems)` | -      |

操作列表的每一项是单个操作或一组操作（数组），格式见 [FilePreview](../components/file-preview)。

### FileBrowserPreviewActionContext

`previewSlots.actions` 和 `previewSlots.actionItems` 的函数形式收到的上下文，只读取，不需要自己构造。它包含 [FilePreview](../components/file-preview) 的 `FilePreviewActions` 的全部属性（`source`、`path`、`viewMode`、`setViewMode`、`canSwitchView`、`editing`、`busy`、`canEdit`、`startEditing`、`saveEditing`、`cancelEditing`、`canCopyPath`、`copyPath`），并增加下面三项。

| 参数           | 说明                                                                  | 类型                     | 默认值 |
| -------------- | --------------------------------------------------------------------- | ------------------------ | ------ |
| defaultActions | 内置操作，已按资源能力、`previewActions`、`readOnly` 和权限过滤       | `FilePreviewActionItems` | -      |
| canDelete      | 当前用户能否删除当前资源，不受 `previewActions.delete` 影响           | `boolean`                | -      |
| deleteFile     | 打开内置的删除确认框，不会关闭预览页签；`canDelete` 为 `false` 时无效 | `() => void`             | -      |

`defaultActions` 分三组：复制内容、下载、历史版本和编译配置；导入和导出 .ovpack；删除。各操作的 `key` 依次是 `copyContent`、`download`、`history`、`configure`、`importPack`、`exportPack`、`delete`。

### FileBrowserAclOptions

`acl` 传入对象时的配置，全部可选；传入 `true` 等同于不设置任何选项。

| 参数                    | 说明                                                                                                         | 类型                                                                                                                                          | 默认值     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| readOnly                | 禁止修改授权，仍可查看                                                                                       | `boolean`                                                                                                                                     | `false`    |
| administratorUserId     | 宿主已确认的管理员 ID，在授权列表显示为固定成员                                                              | `string`                                                                                                                                      | -          |
| supportedPrincipalTypes | 允许新增授权的主体类型；传空数组会隐藏添加入口，仍可编辑已有授权                                             | `readonly ('user' \| 'group')[]`                                                                                                              | 两种都支持 |
| resolvePermission       | 返回当前用户在资源上的有效权限，未知时返回 `undefined`；省略时读取 `fs/stat` 的 `access`，缺失时探测管理权限 | `(uri: string, context: FileBrowserAclContext) => Promise<FileBrowserAclLevel \| undefined>`                                                  | 内置实现   |
| listPrincipals          | 返回可添加的 User 或 Group，`page` 从 1 开始；省略时调用账号的用户和用户组接口，不读取凭证                   | `(query: { type: 'user' \| 'group'; keyword: string; page: number }, context: FileBrowserAclContext) => Promise<FileBrowserAclPrincipalPage>` | 内置实现   |
| onChange                | 授权保存成功后触发，保存失败时不触发；回调抛出的错误不影响保存结果                                           | `(report: FileBrowserAclReport) => void`                                                                                                      | -          |

### FileBrowserAclContext

| 参数           | 说明                                                            | 类型               | 默认值 |
| -------------- | --------------------------------------------------------------- | ------------------ | ------ |
| client         | 当前 Provider 的请求客户端                                      | `OvClient`         | -      |
| requestOptions | 本次请求使用的配置，调用 `client.request` 时作为 `options` 传入 | `OvRequestOptions` | -      |

### FileBrowserAclPrincipalPage

| 参数       | 说明                                             | 类型       | 默认值 |
| ---------- | ------------------------------------------------ | ---------- | ------ |
| principals | 当前页的成员，格式为 `user:<id>` 或 `group:<id>` | `string[]` | 必填   |
| hasMore    | 是否还有下一页                                   | `boolean`  | 必填   |

### FileBrowserAclReport

`acl.onChange` 收到的授权报告，只读取，不需要自己构造。`acl_mode` 为 `'none'` 表示该节点及其上级都没有设置权限，`'inherit'` 表示继承上级并叠加直接授权，`'restricted'` 表示不继承上级、只按直接授权生效。

| 参数              | 说明                 | 类型                                  | 默认值 |
| ----------------- | -------------------- | ------------------------------------- | ------ |
| uri               | 资源 URI             | `string`                              | -      |
| acl_mode          | 权限模式             | `'none' \| 'inherit' \| 'restricted'` | -      |
| direct_entries    | 直接授予该资源的授权 | `FileBrowserAclEntry[]`               | -      |
| inherited_entries | 从上级继承的授权     | `FileBrowserAclEntry[]`               | -      |
| effective_entries | 实际生效的授权       | `FileBrowserAclEntry[]`               | -      |

### FileBrowserAclEntry

授权报告里的一条授权，只读取，不需要自己构造。

| 参数      | 说明                                                                    | 类型                  | 默认值 |
| --------- | ----------------------------------------------------------------------- | --------------------- | ------ |
| principal | 被授权的成员，格式为 `user:<id>` 或 `group:<id>`，`user:*` 表示全部用户 | `string`              | -      |
| level     | 授权级别                                                                | `FileBrowserAclLevel` | -      |

### FileBrowserAclLevel

`'read' | 'write' | 'manage'`：`read` 可以查看内容，`write` 可以查看和编辑，`manage` 还可以删除并管理授权。

## 注意

### 请求与布局

- FileBrowser 的高度是父容器的 100%，父容器需要有明确的高度；组件没有外框和背景，由宿主决定。
- `rootUri`、`defaultExpandedUri` 或 `requestOptions` 变化时，目录树回到根目录并重新加载，进行中的请求被中止；`requestOptions` 变化还会让预览重新请求。
- 内联的 `requestOptions` 对象在每次渲染时都是新的，请在组件外定义或用 `useMemo` 保持引用稳定。
- `acl.resolvePermission` 和 `acl.listPrincipals` 同理：引用变化会重新请求权限和成员，请在组件外定义或用 `useCallback` 保持稳定。
- 类型从 `@openviking/react/modules/file-browser` 导出，包根入口只导出 `FileBrowser` 和 `FileBrowserProps`。

### 目录与预览

- 目录按需展开，每页加载 200 项，目录末尾的「加载更多」继续加载。
- 根目录 `viking://` 下按用户、会话、Agent、资源的顺序显示，其余目录随后；`rootUri` 为其他值时保持接口返回的顺序。
- 点击文件预览正文；点击目录展开并选中它，预览区显示该目录的 L0 摘要和 L1 总览。
- `viking://system` 下的目录保留页签和路径，不显示摘要；目录中的文件仍可预览。
- 设置 `uri` 只切换预览的资源，不会展开目录树；需要初始就展开到某个位置时使用 `defaultExpandedUri`。
- 文本文件最多读取 2000 行，超出时提示内容被截断。
- 图片、视频、音频、PDF、Office 文档和压缩包按扩展名通过内容下载接口读取。
- 可编辑的格式有 `.md`、`.json`、`.jsonl`、`.txt`、`.yaml`、`.yml`：进入编辑时重新读取完整内容，保存调用 `POST /api/v1/content/write`，成功后重新加载预览。
- 文件正文读取显式请求 `raw=false`，并在区块共用读取层兜底；预览、源码和编辑草稿使用同一份正文。
- 记忆命名空间内文件末尾的 `MEMORY_FIELDS` 注释是服务端写入的内部元数据，预览和编辑时都不显示；正文中间的同形注释，以及资源和技能文档里的示例保留。
- YAML 文件按标量范围保留值中的同名注释，独立追加的真实尾注仍会移除；正文不经过重新序列化。
- 行边界、空白与单词字符沿用服务端的 Python 语义。读满预览上限时先取全文、过滤后再截断，避免把首屏末尾误当成文件末尾，或展示被截断的元信息。
- Wiki 归属沿用编译目标和资源标签判断，与看板页签是否显示无关。末尾的 `CONFLICTS_CONTENT` 注释从正文分离，仍提供给冲突看板解析；损坏的 JSON 不进入正文，看板保留错误与重试。
- 编辑保存 Wiki 文件时通过原生 `resolve_conflicts: true` 契约交由服务端保留、更新冲突记录；其他文本文件不携带此参数。
- 所有 YAML 头、普通 HTML 注释和 Markdown 代码围栏中的示例保留；已确认作用域的 Markdown 文件中，独占一行的未闭合保留尾注隐藏至文件末尾；YAML 头、代码围栏和行内示例中的标记保留。
- 刷新按钮重新加载已展开的目录和当前预览。

### 打开并定位资源

`FileBrowser` 支持 React 18/19 的 ref。导入结果、搜索结果或文件链接可调用 `openResource`：模块打开预览，逐级展开祖先目录，按需加载后续页找到目标，选中并滚动到该行。其他分支的展开状态保留；重复打开同一 URI 也会再次滚动定位。

```tsx
import { useRef } from 'react';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import type { FileBrowserHandle } from '@openviking/react/modules/file-browser';

const browserRef = useRef<FileBrowserHandle>(null);

<FileBrowser ref={browserRef} />;

await browserRef.current?.openResource(resultUri, { reveal: true });
```

传入以 `/.abstract.md` 或 `/.overview.md` 结尾的链接时，模块打开父目录并分别切换到 L0 摘要或 L1 总览；树定位与 `onUriChange` 使用父目录 URI。同一目录内重复打开链接也会切换到指定层级，之后仍可手动切换。

`reveal` 默认 `true`；传 `{ reveal: false }` 只发出打开预览的请求，发出后返回 `true`。普通 `uri` 属性变化不会展开或滚动目录树。受控模式需要宿主在 `onUriChange` 中更新 `uri` 接受打开意图。目标行选中并滚动后 Promise 返回 `true`；目标不存在、不可访问、不在 `rootUri` 下、被后续操作替代或组件卸载时返回 `false`。根目录本身没有树行，打开其预览后返回 `false`。目录列表请求或必要的当前用户别名解析失败会 reject，宿主可捕获并展示提示。服务端明确不支持别名解析时，按原 URI 写法匹配。调用方主动取消时返回 `false`。Promise 不等待预览正文加载完成。内置搜索复用同一导航入口。

### 搜索

- 左栏顶部的搜索框打开模块内置的搜索弹窗；`⌘K` 是真实快捷键，同一页面挂多个实例时只有最近交互过的那个响应。
- 输入停顿 400ms 后自动请求，没有提交按钮。关闭弹窗会取消在途请求并清空输入与筛选。
- 四种检索方式共用一套输入与结果列表。有匹配结果时，可在结果区顶部点「切换」：

| 方式     | 接口                    | 输入解释   | 可用筛选                     |
| -------- | ----------------------- | ---------- | ---------------------------- |
| `find`   | `/api/v1/search/find`   | 自然语言   | 目录（多选）、内容层级、时间 |
| `search` | `/api/v1/search/search` | 自然语言   | 同上                         |
| `grep`   | `/api/v1/search/grep`   | 正则表达式 | 目录（单选）、忽略大小写     |
| `glob`   | `/api/v1/search/glob`   | 文件模式   | 目录（单选）                 |

- 结果按 URI 去重；`grep` 例外——同一文件的多行命中是不同结果，各带自己的行号。
- `glob` 的模式不含 `/` 时自动补 `**/` 前缀；目录命中去掉尾斜杠后再参与导航，目录这一事实记在 `isDir` 上。
- 高级面板的筛选项按当前方式启用或禁用，禁用的分区保留可见并置灰，标题旁说明原因。目录候选从 `rootUri` 派生，用户根用 `~` 别名；切换根时失效的已选目录会被丢弃。
- 高级选项可勾选常用目录，或通过「选择目录」继续浏览子目录。选择创建时间或更新时间后显示日期范围；忽略大小写只在 `grep` 中显示。
- 按 **↑ / ↓** 切换当前结果，点击或按 **Enter** 关闭弹窗、打开资源并在树中定位。

### 预览操作区

- 标题行右侧依次是「预览 / 源码」切换、编辑按钮和操作菜单，「复制路径」在面包屑旁，权限标签在其后。
- 显隐开关只控制默认按钮是否显示，不改变能力：`previewSlots` 上下文里的 `canDelete`、`deleteFile()` 和编辑方法仍然可用。
- `readOnly` 禁止所有写入，包括保存编译配置；开启 `acl` 后，编辑、导入和保存编译配置要求 `write` 或 `manage`，删除要求 `manage`。
- 复制内容、下载、导出、查看历史版本和查看编译配置不受 `readOnly` 和 ACL 的限制。
- 没有开启 `acl`，或资源不在 `viking://resources/` 下时，区块不探测权限，由服务端鉴权。
- 保存普通文件会更新正文。要为已保存的内容创建版本，打开「历史版本」，填写备注并点击「保存快照」。此操作仅对可编辑的普通文件开放，调用 `POST /api/v1/snapshot/commit`。
- 历史版本通过 `GET /api/v1/snapshot/log` 读取该资源最近最多 500 条快照。Wiki 编译产物用 `GET /api/v1/snapshot/versions` 读取最多 100 个保留版本。可预览或复制历史正文，并与当前文件对比。
- 编译配置：`GET /api/v1/compile/config` 读取，`POST /api/v1/compile/config/update` 保存来源目录、技能、指令、自动更新和每天或每周的定时更新。
- 导入 .ovpack：先通过 `POST /api/v1/resources/temp_upload` 上传文件，再调用 `POST /api/v1/pack/import` 导入到当前目录；失败时保留所选文件，重试会重新上传。
- 导出 .ovpack：调用 `POST /api/v1/pack/export`，把返回的内容保存为 `<名称>.ovpack`；下载使用 `GET /api/v1/content/download`。
- 删除：确认后调用 `DELETE /api/v1/fs?uri=...&wait=true`；失败时保留确认框并允许重试，成功后选中父目录并刷新目录树。只能删除文件，不能删除目录。
- 操作进行中不会重复提交，切换账号或资源、卸载组件时会中止进行中的请求。

### 权限（ACL）

- `acl` 只作用于 `viking://resources/` 下的非根节点；其他位置不显示权限标签，也不受 ACL 限制。
- 有效权限先读 `GET /api/v1/fs/stat` 返回的 `access`；没有该字段时调用 `GET /api/v1/acl` 探测，成功视为 `manage`，403 视为未知。
- 权限未知时不显示权限标签，编辑和删除不可用；权限读取失败时标题旁显示「重试」。
- 权限标签显示有效权限，`manage` 的标签详情里有「管理权限」按钮，点击打开授权弹窗。
- `read` 不能编辑，`write` 可以编辑和导入，`manage` 还可以删除和管理授权。
- 弹窗里可以搜索并添加 User 或 Group，授予 `read`、`write` 或 `manage`，也可以调整级别和移除；「数据空间管理员」一行固定为 `manage`。
- 节点继承上级权限时，只增加权限会直接保存；降低或移除已有权限需要先在弹窗里确认停止继承，节点随后变为受限（`restricted`），取消则不写入。
- 受限节点可以「恢复继承」：弹窗先列出将不再生效的直接授权，确认后清空直接授权并跟随上级。
- 保存期间不能重复提交或关闭弹窗；保存失败时保留上次成功的授权并显示服务端的原因。
- 保存成功后刷新目录和预览；服务端的索引更新可能异步完成，以服务端的鉴权结果为准。
- 目录列表（`fs/ls`）里 `access: 'denied'` 的节点不能选中或展开，`access: 'container'` 的节点只能展开以访问有权限的子节点、不能预览自身。
- `access: 'read'` 的节点显示只读标记。
- 以上节点标记来自目录列表，不依赖 `acl`。
- 授权调用 `GET`、`PUT /api/v1/acl`，恢复继承时将 `acl_mode` 设为 `inherit` 并发送空的直接授权列表；成员目录调用账号的用户和用户组接口（用户每页 20 条，`include_credentials=false`），需要在 Provider 或 `requestOptions` 里提供 `accountId`。
- 用户组目录需要账号管理权限，资源管理者无权读取时会显示失败和重试，可以用 `acl.listPrincipals` 接入自己的目录。
- `acl.readOnly` 只禁止修改授权，与 `readOnly` 相互独立。

### 看板

- 用户的 `memories/experiences` 目录和其中直接的 `.md` 文件（包括 `peers/<peer>/` 下的）显示经验看板。
- 带有 `compile_target=true` 标签或属于编译配置的目录显示 Wiki 看板，目录下的文件和子目录也有各自的 Wiki 看板。
- 标签优先于编译配置：配置里缺少该目标时仍显示看板。
- 编译配置（`GET /api/v1/compile/configs`）按需读取：打开 Wiki 看板，或正文中的 Wiki 保留尾注需要确认归属时才请求，普通浏览不请求。
- `dashboardKinds` 不含 `'wiki'` 时，不再识别 Wiki，也不读取编译配置，Wiki 资源不再提供编译配置和编译版本索引。
- 文件树里带看板的行显示看板图标，点击直接打开；Wiki 有待处理冲突时图标不同。
- 预览区的页签可以在正文和看板之间切换。
- 普通资源没有 Wiki 页签，已识别的 Wiki 即使没有冲突也保留看板。
- `viking://~/...` 别名和规范 URI 指向同一个资源时识别结果相同，传给 `renderDashboard` 的 `uri` 保持原来的写法。
- 两个看板也可以脱离 FileBrowser 单独使用，见 [WikiDashboard](../components/wiki-dashboard) 和 [ExperienceDashboard](../components/experience-dashboard)。

### 失败状态

- 目录列表失败时，树里显示失败行和重试按钮，根目录失败也一样，不会显示成「没有文件」；失败行的「重试」只重新加载该目录。
- 预览失败时，右侧显示失败状态：`labels.error` 是结论，服务端返回的原始消息是原因，`labels.retry` 是重试按钮，重试会同时重新加载目录树和当前预览。
- 只有没选中资源时才显示空状态（`labels.empty`），选中了资源却读不出来时显示失败状态。
- 目录的 L0 摘要和 L1 总览分别请求：一级失败时只有该级显示失败原因，两级都失败时整个预览显示失败状态；服务端没有返回消息时显示 `labels.summaryFailed`。
- 搜索失败时，弹窗保留接口返回的原因，可以再次提交同一个关键词重试。

### 目录树宽度

- 容器小于 521px 时，目录树和预览上下排列，隐藏横向分隔条。

- 树与预览之间有可拖拽的分隔条：拖动，或聚焦后用左右方向键（每次 16px）调整树宽；分隔条的无障碍名称来自 `labels.resizeTree`。
- 默认 352px，最小 200px，最大为 520px 与「容器宽度减去 321px」（预览区至少 320px，加 1px 分隔线）中的较小值，因此放进窄栏时树会收窄，不会挤没预览区。
- 宽度只在当前实例内生效，不写入 `localStorage`，是否记住由宿主决定。
- 当前宽度以 CSS 变量 `--ov-file-browser-tree-width` 写在根元素的内联样式上，可以读取，但覆盖它不会生效。
