# VikingBot 无头对话

管理对话请求、流式内容和会话，供 Console 或独立 VikingBot 宿主复用。此模块不导出组合组件，也没有 CSS 入口。

## 引入

```tsx
import {
  useVikingBotChat,
  useVikingBotSessions,
} from '@openviking/react/modules/viking-bot';
```

## 代码演示

`VikingBot` 保持纯视图。独立使用时，从 `@openviking/react/modules/viking-bot` 导入 `useVikingBotChat` 与 `useVikingBotSessions`，继承 `OpenVikingProvider` 的请求配置；无 Provider 时默认同源。下面使用固定模拟服务，不访问真实数据。

## API

### 配置

| 参数            | 说明                                                        | 类型                                               | 默认值                      |
| --------------- | ----------------------------------------------------------- | -------------------------------------------------- | --------------------------- |
| locale          | 界面与本库错误文案语言，不改变原始内容或重启请求            | `'zh-CN' \| 'en-US'`                               | 继承 Provider，否则 `en-US` |
| enabled         | 禁用时不自动请求，也不执行操作                              | `boolean`                                          | `true`                      |
| requestOptions  | 覆盖 Provider 的请求配置                                    | `OvRequestOptions`                                 | 继承 Provider               |
| scopeKey        | 动态身份变化时更新，取消旧身份请求并清理状态                | `string`                                           | -                           |
| service         | 稳定的服务对象；两个 Hook 分别接受对话或会话服务契约        | `VikingBotChatService` / `VikingBotSessionService` | 原生服务                    |
| sessionId       | 对话 Hook 当前会话                                          | `string`                                           | 首次发送时创建              |
| initialMessages | 对话 Hook 的初始消息；保持引用稳定                          | `readonly VikingBotMessage[]`                      | `[]`                        |
| persist         | 对话完成后保存消息；服务未提供 `saveMessage` 时由后端持久化 | `boolean`                                          | `true`                      |

### 返回值与操作

`useVikingBotChat` 返回 `sessionId`、`messages`、`streaming`、`status`、`error` 与独立的 `persistenceError`；`send(string | VikingBotDraft)` 返回是否收到正常结束事件，失败或取消返回 `false`，并保留已收到的内容。`abort()` 停止，`selectSession(id)` 读取历史，`reset()` 开始空白会话，`reload()` 重读当前历史，`setMessages()` 在空闲时替换本地记录。新会话在首次发送时创建。`persist` 默认 `true`；原生接口不保存临时推理。

`useVikingBotSessions` 返回 `sessions`、`isLoading`、`error`、`refresh()`、`create()` 和 `remove(id)`；创建失败返回 `undefined`，删除失败返回 `false`，失败后可重试。默认挂载加载列表；`enabled: false` 禁用自动请求及操作。

两者支持 `requestOptions`、`scopeKey` 和稳定的 `service`。`sessionId`、`initialMessages`、`persist` 是对话配置；稳定保存 `service` 与 `initialMessages` 引用。服务、会话或身份变化会重建请求归属并取消旧请求；语言变化只更新界面和本库错误文案。原始输入、AI 回复和后端错误不翻译。商业版宿主把 TOP 的稳定事件 ID、delta/snapshot 与终止状态转换成 `VikingBotChatEvent`，并省略 `saveMessage` 以避免重复持久化；认证、CSRF、监控和产品副作用留在宿主。

`canInterrupt` 表示服务是否提供 `interrupt`。宿主仅在它为 `true` 时传 `onCancel`；不支持该能力的商业版适配器不显示停止入口。`abort()` 也可用于本地连接清理，但断开前端连接不等于后端任务已停止。原生适配器支持生成中追问，火山版当前适配器不启用。

`canSteer` 表示适配器是否实现 `steer(input, signal)`。独立视图将它映射到 `canSendWhileStreaming`，并传入 `isSubmitting`；两项视图属性默认分别为 `false`，不包含协议判断。生成中调用同一个 `send()` 会走 steer，返回是否接受；空闲时调用会创建正常请求，等待整次流完成。已接受追问会在下一条 iteration 事件处切分助手段落和用户输入，保持渲染与持久化顺序一致。

## 组合使用

[Console](./console) 已内置消费此模块。独立宿主使用 [VikingBot](../components/viking-bot) 时单独引入该组件的样式；本模块不包含 UI、CSS 或浏览器全局依赖，不从包根或 Console 入口转导出 Hook。
