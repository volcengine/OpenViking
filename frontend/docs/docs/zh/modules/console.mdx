# Console 交互面板

在一块面板里提供对话和命令两种模式：对话模式接通原生 VikingBot 对话；命令模式把 `ov` 命令发送到 OpenViking 原生 API 并展示结果。

## 何时使用

- 需要一块让用户既能和 VikingBot 对话，又能用 `ov` 命令浏览、检索和写入知识库的面板。
- 需要在浏览器里执行 OpenViking 原生 API 命令，并在切换模式时保留命令记录和输入草稿。
- 只需要对话视图或命令输入区时，使用 [VikingBot](../components/viking-bot) 或 [CommandConsole](../components/command-console)；需要自己提供命令目录时也使用后者，Console 的命令是内置的。

## 引入

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/console/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <Console />
</OpenVikingProvider>;
```

样式入口已包含 CommandConsole 和 VikingBot 的样式。Provider 与请求配置的规则见[区块概览](./)。

对话模式使用 [VikingBot](../components/viking-bot)，它依赖可选 peer 依赖 `@ark-design/ui`，不会随 `@openviking/react` 自动安装，安装方式见该页的「引入」。

示例使用模拟服务和固定的对话数据，不访问真实服务。对话模式的 `+` 只在浏览器里选择附件，示例没有提供 `onSend`，输入区不能发送。

### 内置对话

省略 `conversation.messages`、`conversation.onSend` 和 `conversation.composer` 时，Console 内部管理请求、消息和输入框。宿主仍可提供文案、插槽与 `conversation.sessions`：其 `items`、加载及错误信息用于展示，`currentId` 可同步路由；每次主动选择历史会话（包括重新选择当前会话）都通过 `onSelect` 通知一次，异步创建的会话 ID 也通过 `onSelect` 同步。每次主动新建通过 `onNew` 通知，即使远端会话尚未创建。宿主将新建 ID 写回 `currentId` 不会重启正在进行的回复。切换会话会清空旧草稿，已取消的请求不会将其恢复到新会话。

请求、会话和流式状态由 Console 内部管理；可通过 `chatOptions.service` 适配其他后端，服务同时实现对话与会话契约。模块切换保留当前对话；新建或切换会话会取消旧连接。历史保存失败单独提示，不改变已成功的回答。


示例使用模拟服务，可切换原生能力与火山当前契约。原生适配器提供 `interrupt` 和 `steer`，支持停止及生成中追问；火山当前适配器省略这两个方法，生成中禁用发送且不显示停止。回答后的下一轮提问两者均支持。

### 功能选择

`modes={['command']}` 只启用 TUI，`modes={['conversation']}` 只启用 VikingBot。省略时两者都启用；单功能时隐藏模式切换，关闭的模式不渲染，也不发起请求。当前 `mode` 或 `defaultMode` 不在启用列表时，显示列表第一项，不触发 `onModeChange`。切换模式保留对话；从 `modes` 中移除对话会中止连接，重新启用时重新加载会话。

### VikingBotChatService

| 参数             | 说明                                                                     | 类型                                                                                    | 默认值 |
| ---------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- | ------ |
| stream           | 流式请求；必须发出 complete 或 interrupted 终止事件                      | `(input: VikingBotChatInput, signal: AbortSignal) => AsyncIterable<VikingBotChatEvent>` | 必填   |
| createSession    | 新建会话                                                                 | `(signal: AbortSignal) => Promise<VikingBotSession>`                                    | 必填   |
| loadMessages     | 读取完整会话历史                                                         | `(id: string, signal: AbortSignal) => Promise<readonly VikingBotMessage[]>`             | 必填   |
| attachmentUpload | 启用添加资源按钮；发送时将 `upload` 返回的标识传给 `attachment.uploadId` | `VikingBotAttachmentUpload`                                                             | 可选   |
| saveMessage      | 逐条保存；后端自动持久化时省略，避免重复                                 | `(id: string, message: VikingBotMessage, signal: AbortSignal) => Promise<void>`         | 可选   |
| interrupt        | 实际中断后端生成；与本地断开连接不同                                     | `(id: string, signal: AbortSignal) => Promise<{ interrupted: boolean }>`                | 可选   |
| steer            | 向当前流追加输入；accepted 仅表示接受，不表示回复完成                    | `(input: VikingBotChatInput, signal: AbortSignal) => Promise<{ accepted: boolean }>`    | 可选   |

`VikingBotAttachmentUpload` 接收可选的文件选择器过滤器 `accept`，以及必填的 `upload(file, signal)`，它返回已上传文件的标识。文件选择器不会过滤拖入的文件，适配器仍需验证文件。附件上传完成后才可发送。移除附件会取消该文件的上传；切换账号、请求身份或会话，或取消请求信号时，会取消待完成的上传并清空托管附件。通过 `conversation.sessions.currentId` 回写新建会话 ID 时，会保留该会话的正常上传。如果宿主提供草稿附件或文件选择回调，则使用宿主的配置。

### VikingBotChatEvent

| 参数        | 说明                                                         | 类型                                                                                                             | 默认值 |
| ----------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------ |
| reasoning   | delta=true 追加；false 替换；id 可选，稳定 ID 更新同一推理项 | `{ type: 'reasoning'; text: string; delta: boolean; id?: string }`                                               | -      |
| text        | delta=true 追加正文；false 替换当前正文片段                  | `{ type: 'text'; text: string; delta: boolean }`                                                                 | -      |
| iteration   | 下一次模型迭代边界；将已接受追问归入新的交流段               | `{ type: 'iteration'; iteration: number }`                                                                       | -      |
| tool        | 每次实际调用唯一 ID；相同参数也不得合并                      | `{ type: 'tool'; part: VikingBotToolPart }`                                                                      | -      |
| tool-result | 通过 id 对应调用；原生无 ID 协议按 FIFO 配对                 | `{ type: 'tool-result'; id: string; output: string; isError?: boolean; tasks?: readonly ConsoleTaskSnapshot[] }` | -      |
| complete    | 正常结束；可选 text 是最终正文快照                           | `{ type: 'complete'; text?: string }`                                                                            | -      |
| interrupted | 中断终止，保留已有内容                                       | `{ type: 'interrupted' }`                                                                                        | -      |

Console 按适配器是否提供方法决定停止与追问能力。`steer` 返回 `accepted: false` 表示未接受输入；不要发出虚假的用户消息。事件流没有终止事件就结束会报 `BOT_STREAM_TRUNCATED`。

`tool-result.tasks` 声明工具实际发起的后台任务，包含必填 `id` 及可选 `kind`、`uri`、`status`。原生适配器从已知提交工具的结构化结果中提取任务 ID，其他服务直接提供 `tasks`。工具返回、聊天回复结束与后台任务完成分别处理，工具片段保留原始输出并展示任务快照。

### ConsoleTaskSnapshot

| 参数       | 说明                                       | 类型                                                                               | 默认值 |
| ---------- | ------------------------------------------ | ---------------------------------------------------------------------------------- | ------ |
| id         | 后台任务 ID                                | `string`                                                                           | 必填   |
| status     | 任务状态，查询结果必须提供                 | `'pending' \| 'running' \| 'cancelling' \| 'completed' \| 'failed' \| 'cancelled'` | -      |
| kind       | 任务类别，用于通知标题                     | `'resource' \| 'skill' \| 'memory' \| 'compile'`                                   | -      |
| uri        | 任务关联的资源 URI                         | `string`                                                                           | -      |
| stage      | 服务端返回的执行阶段                       | `string`                                                                           | -      |
| result     | 服务端返回的任务结果                       | `unknown`                                                                          | -      |
| error      | 服务端返回的任务错误                       | `string`                                                                           | -      |
| queryError | 调度器生成的查询错误，保留最后一次任务状态 | `{ code: 'request' \| 'invalid-response'; message?: string }`                      | -      |

调度器每 3 秒查询一次活跃任务，同一作用域和任务 ID 只保留一个查询，最多并发 4 个请求。查询失败指数退避至最多 30 秒，到达终态后停止。进行中的任务通知使用内置 loading 图标，到达终态后替换为结果图标；查询异常显示警告，不改变任务状态。

切换模式或聊天会话、清空终端记录、关闭通知均不取消后台任务。关闭通知后仍更新关联记录；切换身份或卸载 Console 会中止查询并忽略旧响应。通知与任务状态不跨页面刷新持久化。

其他后端通过 `taskService` 适配请求和状态字段。该对象及 `chatOptions.taskService` 应保持引用稳定；后者可覆盖对话任务的查询方式。不同服务、身份或 `scopeKey` 的任务分别跟踪。宿主完全控制 `conversation` 时，任务状态也由宿主提供。

## 命令

命令模式只执行内置的原生 API 命令。输入 `/` 或运行 `ov help`，可以按「核心流程」「文件系统」「搜索与上下文」「配置与状态」查看命令和各自的选项。

### 写法

- 命令可以写成 `ov find`、`/find`，也可以直接写 `find`。
- 含空格的参数用单引号或双引号包住，也可以用反斜线转义。
- 以 `--` 开头的值要加引号，例如 `ov write viking://resources/a.md "--heading"`；也可以用 `--` 结束选项解析，例如 `ov write viking://resources/a.md -- --heading`。选项值同理，例如 `--description "--example"`。
- 参数按数据解析，不执行 Shell。未加引号的 `| ; & < > $` 和反引号会被拒绝，含 `&` 的 URL 要加引号。
- 未知选项、重复选项、缺少参数、不以 `viking://` 开头的 URI 和未闭合的引号都会生成失败记录，不发送请求。

### 支持的命令

| 能力       | 命令                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 添加与编译 | `add-resource <path>`、`add-skill <path>`、`add-memory <content> --session-id <session-id>`、`compile --from <from> --to <to>`、`compile create --from <from> --to <to>` |
| 本地       | `help`、`clear`                                                                                                                                                          |
| 服务       | `health`、`status`                                                                                                                                                       |
| 浏览       | `ls [uri]`、`tree [uri]`、`stat <uri>`                                                                                                                                   |
| 内容       | `read <uri>`、`abstract <uri>`、`overview <uri>`                                                                                                                         |
| 检索       | `find <query>`、`search <query>`、`grep <pattern>`、`glob <pattern>`                                                                                                     |
| 写入       | `mkdir <uri>`、`write <uri> <content>`、`cp <from_uri> <to_uri>`、`mv <from_uri> <to_uri>`、`rm <uri>`                                                                   |
| 任务       | `task list`、`task status <id>`、`task cancel <id>`                                                                                                                      |

- `ls` 和 `tree` 默认从 `viking://` 开始，最多返回 100 条；用 `--limit` 和 `--offset` 分页，`tree` 另有 `--level_limit`。
- `write` 默认覆盖已有内容；`--mode create` 表示创建，`--mode append` 表示追加。
- `add-resource` 和 `add-skill` 接受远程地址，不接受本地文件路径。
- `add-memory` 把内容作为用户消息追加到 `--session-id` 指定的会话，再提交该会话。
- `compile` 默认使用内置的 llm-wiki Skill，用 `--skill` 指定其他 Skill；`compile create` 只保存编译配置，不启动编译。
- `task cancel` 向服务端请求协作取消，任务可能不会立即停止。
- 选项名的写法因命令而异，例如 `add-skill` 用 `--target-uri`，`find` 用 `--target_uri`，以 `ov help` 为准。
- 导入、编译与记忆提交返回任务 ID 后自动跟踪；任务状态独立于提交结果，终端输入在提交请求返回后恢复可用。
- 命令集只包含浏览器能调用的原生 API，本地配置、登录、本地文件上传下载和会话管理类命令不在其中。

## 注意

发送失败的提问和客户端错误保留在消息列表中。会话尚未创建时，下次发送会补建会话，将未送达的用户输入作为上下文合并到同一次聊天请求，分别保存原始用户消息；错误提示不会保存或发送给模型。原生网关只接收单条 `message`，因此仅补写会话消息不能恢复模型上下文。 未送达的输入会保留到收到首个流事件；在此之前失败，下次发送仍会携带这些上下文。生成开始后不再重放旧输入。

- 默认发送原生 VikingBot 对话请求。传入 `conversation.messages` 或 `conversation.onSend` 时改由宿主管理对话和附件状态。
- 宿主查询 Bot 状态后设置 `conversation.isAvailable` 和 `conversation.unavailableMessage`，不可用时输入区被禁用并显示说明。
- 命令只在用户提交时发送请求，挂载时不请求。同一实例一次只执行一条命令，执行期间输入框被禁用。
- 命令失败时，错误显示在对应的记录里，修正后重新提交即可；写入类命令失败时服务端可能已经接收，重新提交前先核对结果。
- 命令模式的「新建会话」会中止进行中的请求并忽略迟到的响应，同时清空命令记录、错误和输入框；服务端已接收的操作不会撤销，服务端数据也不会删除。`clear` 命令只清空本地记录。
- 命令历史列出当前面板的记录，最新的在前，时间为提交时的本地时间（`YYYY-MM-DD HH:mm`）；点击一条会把命令填回输入框，不会执行。
- 命令记录和草稿只保存在内存中。`scopeKey`、`requestOptions` 或 Provider 的配置变化时，Console 清空记录和草稿并中止进行中的请求，卸载时同样中止。
- 身份字段使用函数时，保持函数引用稳定，并在身份变化时更新 `scopeKey`，或用身份作为组件的 `key`。
- Console 撑满父容器的宽高，父容器需要有明确的高度，或是可伸展的 flex 布局。
- 切换 `locale` 会更新已有记录里的命令帮助、参数错误和取消提示，保留记录和草稿；服务端返回的内容保持原样。
- 认证、账号切换和页面布局由宿主负责。`onOpenUri` 只上报资源链接的打开意图，导航由宿主完成。
- 类型从 `@openviking/react/modules/console` 导出，包根入口只导出 `Console` 和 `ConsoleProps`。
