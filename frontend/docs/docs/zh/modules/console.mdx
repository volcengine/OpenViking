# Console 交互面板

在一块面板里提供对话和命令两种模式：对话模式接通原生 VikingBot 对话；命令模式把 `ov` 命令发送到 OpenViking 原生 API 并展示结果。

## 何时使用

- 需要一块让用户既能和 VikingBot 对话，又能用 `ov` 命令浏览、检索和写入知识库的面板。
- 需要在浏览器里执行 OpenViking 原生 API 命令，并在切换模式时保留命令记录和输入草稿。
- 只需要对话视图或命令输入区时，使用 [VikingBot](../components/viking-bot) 或 [CommandConsole](../components/command-console)；需要自己提供命令目录时也使用后者，Console 的命令是内置的。

## 引入

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/console/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <Console />
</OpenVikingProvider>;
```

样式入口已包含 CommandConsole 和 VikingBot 的样式。Provider 与请求配置的规则见[区块概览](./)。

对话模式使用 [VikingBot](../components/viking-bot)，它依赖可选 peer 依赖 `@ark-design/ui`，不会随 `@openviking/react` 自动安装，安装方式见该页的「引入」。

### 内置对话

省略 `conversation.messages`、`conversation.onSend` 和 `conversation.composer` 时，Console 内部管理请求、消息和输入框。宿主仍可提供文案、插槽与 `conversation.sessions`：其 `items`、加载及错误信息用于展示，`currentId` 可同步路由；每次主动选择历史会话（包括重新选择当前会话）都通过 `onSelect` 通知一次，异步创建的会话 ID 也通过 `onSelect` 同步。每次主动新建通过 `onNew` 通知，即使远端会话尚未创建。宿主将新建 ID 写回 `currentId` 不会重启正在进行的回复。切换会话会清空旧草稿，已取消的请求不会将其恢复到新会话。

请求、会话和流式状态由 Console 内部管理；可通过 `chatOptions.service` 适配其他后端，服务同时实现对话与会话契约。模块切换保留当前对话；新建或切换会话会取消旧连接。历史保存失败单独提示，不改变已成功的回答。

点击「创建 Wiki」或「定时日报」可填入空白草稿或切换预设。发送后由配置的对话服务处理请求，编译相关的确认问题通过下方介绍的流程展示。用 `conversation.quickInputs` 提供自定义列表，传入 `[]` 可隐藏快捷入口。


示例使用模拟服务，可切换原生能力与火山当前契约。原生适配器提供 `interrupt` 和 `steer`，支持停止及生成中追问；火山当前适配器省略这两个方法，生成中禁用发送且不显示停止。回答后的下一轮提问两者均支持。

点击底部的 `@`，或在输入框中键入 `@`，可浏览、搜索并引用文件和目录。内置选择器使用当前请求作用域下的 `/api/v1/fs/ls` 和 `/api/v1/search/glob`，打开时才加载。通过 `chatOptions.referenceSelection` 传入 `{ selected, onChange }`，可以让目录树与内置 `@` 选择器共享已选引用。发送后由宿主移除已发送的引用，重置会话时由 Console 清空已选引用。设置 `conversation.references` 可自行提供候选项和已选引用，替代内置选择器。自定义对话服务可通过发送参数中的 `references` 读取已选引用。

库决定 VikingBot 是否可用且由宿主启动运行时，可以传入 `chatOptions.activation`。示例模拟了允许启用、库未开启 Bot 和首次启用失败三种情况。


通过 `isEligible` 确认当前作用域是否允许使用 Bot。返回 `true` 后，Console 显示对话标签页，并通过 `getStatus` 查询 Bot 是否已就绪。尚未启动时，用户点击「启用 VikingBot」会触发宿主的 `start` 回调。Console 会再次确认状态，就绪后加载对话和会话历史。切换库或身份时，更新 `scopeKey` 或传入对应的 `activation`。模拟火山宿主适配器将 `GetOpenVikingCollection` 返回的 `EnableVikingBot === true` 映射为 `isEligible` 的布尔结果。

当前库和身份不变时保持适配器引用稳定。三个回调都接收 `AbortSignal`，失败时应抛出错误。可通过 `media` 用介绍视频或封面替换默认插图。


Console 在 `request_user_input` 工具成功且当前轮正常结束后展示问题，当输出目录依赖来源目录和配置名称时，先收集这两项。中断、截断、错误结果和不支持的协议保留普通工具展示。传入 `chatOptions.hitl={false}` 关闭自动交互；显式传入 `conversation.interaction` 时使用宿主的问题与回调。

配置文件系统后，Console 使用选择器选取来源目录和技能，并在继续前检查输出目录。自定义对话服务未连接文件系统时，可以直接输入 URI。输出目录不能与来源目录相同或互相包含。已有明确答案或可以从技能识别产物类型时，Console 会跳过产物类型问题。只有工具明确提供已启用的计划，或用户主动启用，才会开启自动更新。

历史消息不包含可确认的轮次终止状态，加载历史只恢复消息和答案摘要，不重新触发问题卡片。新一轮实时回复正常结束后仍可触发交互。

最后一项提交后，Console 发送 `request_user_input_response` JSON 继续下一轮对话，包含 `schema_version: '1.0'`、`tool_call_id` 和按原顺序排列的 `answers: { card_type, title, value }[]`。用户气泡、复制和历史展示采用标签/值摘要；发送与存储保留协议原文，选项名称从对应问题中恢复。

宿主通过 `chatOptions.hitl.cards[card_type]` 提供扩展。同一类型的多个问题可用 `configureCard(card)` 按 `card.id` 或 `card.payload` 分别配置。字段名与值类型见 [VikingBotInteractionFields](../components/viking-bot#vikingbotinteractionfields)。校验通过后才进入下一项，最后一项才调用对话服务。宿主可以添加校验，并为自定义选择器提供数据和请求。

### 提交会话

点击最新一条完整回复下方的「提交会话」，可为当前对话发起记忆提取。Console 会显示提交状态，并在服务端返回任务 ID 时跟踪后台任务。如果任务返回记忆变更文件，且宿主提供了 `conversation.onOpenUri`，可从完成通知中打开结果。

设为 `chatOptions.memoryCommit={false}` 可隐藏该操作。自定义对话服务可实现 `commitSession`；未实现时，由原生对话或已配置的 Provider 提供原生会话接口。

### 功能选择

`modes={['command']}` 只启用 TUI，`modes={['conversation']}` 只启用 VikingBot。省略时两者都启用；单功能时隐藏模式切换，关闭的模式不渲染，也不发起请求。当前 `mode` 或 `defaultMode` 不在启用列表时，显示列表第一项，不触发 `onModeChange`。切换模式保留对话；从 `modes` 中移除对话会中止连接，重新启用时重新加载会话。

#### 内置卡片

| card_type           | 默认表单字段                | 协议中的 value                                                 |
| ------------------- | --------------------------- | -------------------------------------------------------------- |
| compile_name        | `value`，文本               | `string`                                                       |
| compile_output_type | `value`，单选               | 选项的 `value`                                                 |
| compile_source      | `value`，多选目录           | 去空值、去重后的 `string[]`                                    |
| compile_target      | `value`，推荐或自定义目录   | `string`                                                       |
| compile_skill       | `value`，推荐或自定义 Skill | `string`                                                       |
| compile_instruction | `value`，多行文本           | `string`                                                       |
| compile_schedule    | `mode`、`time`、`weekday`   | `{ frequency: 'disabled' }` 或包含频率、时间、星期和时区的对象 |

工具结果支持直接 JSON、MCP `structuredContent` 或文本 `content`，`schema_version` 必须为 `'1.0'`。优先读取 `structuredContent`；一组中任一问题无效或未注册时，整组保留为工具结果。原生服务接受裸工具名及 `mcp_openviking-mcp_request_user_input`；自定义适配器应保留工具调用的唯一 `id`，将服务名设为 `openviking-mcp`、工具名设为 `request_user_input`。

`createRequest` 可返回 `kind: 'custom'`，由自定义组件通过 `context.submit(value)` 提交对象或其他答案，并自行管理其字段校验。配置 `serialize` 适配服务端值，配置 `summarize` 提供可读展示；未知类型需提供 `createRequest` 才会触发交互。

| 参数             | 说明                                                                     | 类型                                                                                                                             | 默认值 |
| ---------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------ |
| stream           | 流式请求；必须发出 complete 或 interrupted 终止事件                      | `(input: VikingBotChatInput, signal: AbortSignal) => AsyncIterable<VikingBotChatEvent>`                                          | 必填   |

| saveMessage      | 逐条保存；后端自动持久化时省略，避免重复                                 | `(id: string, message: VikingBotMessage, signal: AbortSignal) => Promise<void>`                                                  | 可选   |
| commitSession    | 提交当前会话以提取记忆                                                   | `(id: string, signal: AbortSignal) => Promise<{ status: 'accepted'; taskId: string } \| { status: 'skipped'; reason?: string }>` | 可选   |

`VikingBotAttachmentUpload` 接收可选的文件选择器过滤器 `accept`，以及必填的 `upload(file, signal)`，它返回已上传文件的标识。文件选择器不会过滤拖入的文件，适配器仍需验证文件。附件上传完成后才可发送。移除附件会取消该文件的上传；切换账号、请求身份或会话，或取消请求信号时，会取消待完成的上传并清空托管附件。通过 `conversation.sessions.currentId` 回写新建会话 ID 时，会保留该会话的正常上传。如果宿主提供草稿附件或文件选择回调，则使用宿主的配置。

### VikingBotSessionService

### ConsoleTaskSnapshot

| 参数       | 说明                                       | 类型                                                                               | 默认值 |
| ---------- | ------------------------------------------ | ---------------------------------------------------------------------------------- | ------ |
| id         | 后台任务 ID                                | `string`                                                                           | 必填   |
| status     | 任务状态，查询结果必须提供                 | `'pending' \| 'running' \| 'cancelling' \| 'completed' \| 'failed' \| 'cancelled'` | -      |
| kind       | 任务类别，用于通知标题                     | `'resource' \| 'skill' \| 'memory' \| 'compile'`                                   | -      |
| uri        | 任务关联的资源 URI                         | `string`                                                                           | -      |
| stage      | 服务端返回的执行阶段                       | `string`                                                                           | -      |
| result     | 服务端返回的任务结果                       | `unknown`                                                                          | -      |
| error      | 服务端返回的任务错误                       | `string`                                                                           | -      |
| queryError | 调度器生成的查询错误，保留最后一次任务状态 | `{ code: 'request' \| 'invalid-response'; message?: string }`                      | -      |

调度器每 3 秒查询一次活跃任务，同一作用域和任务 ID 只保留一个查询，最多并发 4 个请求。查询失败指数退避至最多 30 秒，到达终态后停止。资源导入进度显示在结果记录中，其他任务还会显示加载通知。任务到达终态后显示结果图标，查询异常时显示警告并保留任务状态。

任务快照优先使用完成结果里的资源 URI，并以提交任务时的 URI 兜底。自定义任务服务可以在 `uri` 中直接提供最终资源地址。终端任务完成且有资源 URI 时，「查看结果」会通过 `command.onOpenUri` 或 `Console.onOpenUri` 打开资源。通知会保留到点击按钮或关闭。

切换模式或聊天会话、清空终端记录、关闭通知均不取消后台任务。关闭通知后仍更新关联记录；切换身份或卸载 Console 会中止查询并忽略旧响应。通知与任务状态不跨页面刷新持久化。

其他后端通过 `taskService` 适配请求和状态字段。该对象及 `chatOptions.taskService` 应保持引用稳定；后者可覆盖对话任务的查询方式。不同服务、身份或 `scopeKey` 的任务分别跟踪。宿主完全控制 `conversation` 时，任务状态也由宿主提供。

## 命令

命令模式只执行内置的原生 API 命令。输入 `/` 或运行 `ov help`，可以按「核心流程」「文件系统」「搜索与上下文」「文件传输」「会话」「配置与状态」查看命令和各自的选项。

### 写法

- 命令可以写成 `ov find`、`/find`，也可以直接写 `find`。
- 含空格的参数用单引号或双引号包住，也可以用反斜线转义。
- 以 `--` 开头的值要加引号，例如 `ov write viking://resources/a.md --content "--heading"`。传入位置参数前也可以用 `--` 结束选项解析。短选项区分大小写。`tree` 中 `-L` 限制树深度，`-l` 限制摘要长度。
- 参数按数据解析，不执行 Shell。未加引号的 `| ; & < > $` 和反引号会被拒绝，含 `&` 的 URL 要加引号。
- 未知选项、重复的单值选项、缺少参数、无效的资源 URI 和未闭合的引号都会生成失败记录，不发送请求。

### 支持的命令

| 能力       | 命令                                                                                                                                                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 添加与编译 | `add-resource [path-or-url]`、`add-skill [skill-content-or-url]`、`add-memory <content> --session-id <id>`、`compile create --compile-name <name> --from <source-uri> --to <target-uri> --skill <skill-uri>`、`compile --compile-name <name>` |
| 本地       | `help`、`clear`                                                                                                                                                                                                                               |
| 服务       | `health`、`status`                                                                                                                                                                                                                            |
| 浏览       | `ls [uri]`、`tree <uri>`、`stat <uri>`                                                                                                                                                                                                        |
| 内容       | `read <uri>`、`abstract <uri>`、`overview <uri>`                                                                                                                                                                                              |
| 检索       | `find [query]`、`search [query]`、`grep <pattern>`、`glob <pattern>`                                                                                                                                                                          |
| 写入       | `mkdir <uri>`、`write <uri> --content <text>`、`cp <from-uri> <to-uri>`、`mv <from-uri> <to-uri>`、`rm <uri>`                                                                                                                                 |
| 任务       | `task list [--task-type <type>] [--status <status>]`、`task status <task-id>`、`task cancel <task-id>`                                                                                                                                        |

- `ls` 默认从 `viking://` 开始。`ls` 和 `tree` 用 `-n` 或 `--node-limit` 限制返回条数，默认 256 条，用 `-a` 或 `--all` 包含隐藏文件。`ls` 支持 `-r` 或 `--recursive` 递归列出子目录，以及 `-s` 或 `--simple` 只返回路径。用 `ov tree viking://resources -L 2` 或 `ov tree viking://resources --level-limit 2` 控制深度，默认 3 层。已有的 `--offset` 可继续用于分页。
- 用 `find` 或 `search` 获取排序后的结果时，`-u` 或 `--uri` 指定检索范围，`-n` 或 `--node-limit` 限制返回条数，`-t` 或 `--threshold` 设置最低分数。两者都支持用 `--image <url>` 检索图片，以及用 `--after` 或 `--before` 按时间筛选。`search --mode context` 用于组装上下文。`grep` 支持 `-i` 或 `--ignore-case`、`-x` 或 `--exclude-uri`、`-L` 或 `--level-limit`。
- `write` 默认覆盖已有内容。用 `--mode create` 创建文件，用 `--append` 追加文本。`mkdir` 和 `write` 支持用 `--acl` 传入带引号的 JSON 对象，例如 `ov mkdir viking://resources/demo --acl '{"acl_mode":"inherit","entries":[]}'`。复制或删除目录树时使用 `-r` 或 `--recursive`。
- `add-resource` 支持远程地址，可用 `--include` 和 `--exclude` 指定过滤条件。`add-resource` 和 `add-skill` 都可以通过 `--temp-file-id <id>` 引用宿主已上传的文件。`add-skill` 还支持直接传入 Skill 内容，用 `-p` 或 `--target-uri` 指定目标位置。
- `add-memory` 把内容作为用户消息追加到 `--session-id` 指定的会话，再提交该会话。
- 用 `compile create` 保存命名配置，再用 `compile --compile-name <name>` 执行。可以重复传入 `--from`，也可以用英文逗号分隔多个来源目录 URI。通过 `--instruction` 补充指令，或用 `--args` 传入模型、定时计划等 JSON 参数。用 `task status <task-id>` 查询返回的任务 ID。
- `task cancel` 向服务端请求协作取消，任务可能不会立即停止。
- 导入、编译与记忆提交返回任务 ID 后自动跟踪；任务状态独立于提交结果，终端输入在提交请求返回后恢复可用。
- `session` 支持创建、列表、详情、上下文、归档、消息写入、提交和配置。批量消息用 `ov session add-messages <session-id> '<messages-json>'`。
- `ov get <uri> <local-path>` 和 `ov export <uri> <output.ovpack>` 由浏览器下载。输出路径的最后一段用作文件名。`export` 和 `backup` 支持 `--include-vectors`。
- `ov import <file.ovpack> <target-uri>` 通过本地文件选择器上传 OVPack，可传 `--on-conflict` 和 `--vector-mode`。宿主可以通过 `commandOptions.choosePackFile` 复用文件管理器的导入弹窗。弹窗只接受有效的 `.ovpack` 文件。
- `add-resource` 的本地来源以及 `write --from-file` 通过浏览器选择文件。浏览器的本机配置和登录由宿主处理。管理员命令 `backup`、`restore` 默认关闭，由有授权的宿主通过 `commandOptions.allowAdminCommands` 启用。

## 注意

发送失败的提问和客户端错误保留在消息列表中。会话尚未创建时，下次发送会补建会话，将未送达的用户输入作为上下文合并到同一次聊天请求，分别保存原始用户消息；错误提示不会保存或发送给模型。原生网关只接收单条 `message`，因此仅补写会话消息不能恢复模型上下文。 未送达的输入会保留到收到首个流事件；在此之前失败，下次发送仍会携带这些上下文。生成开始后不再重放旧输入。

- 默认发送原生 VikingBot 对话请求。传入 `conversation.messages` 或 `conversation.onSend` 时改由宿主管理对话和附件状态。
- 宿主查询 Bot 状态后设置 `conversation.isAvailable` 和 `conversation.unavailableMessage`，不可用时输入区被禁用并显示说明。
- 命令只在用户提交时发送请求，挂载时不请求。同一实例一次只执行一条命令，执行期间输入框被禁用。
- 命令失败时，错误显示在对应的记录里，修正后重新提交即可；写入类命令失败时服务端可能已经接收，重新提交前先核对结果。
- 命令模式的「新建会话」会中止进行中的请求并忽略迟到的响应，同时清空命令记录、错误和输入框；服务端已接收的操作不会撤销，服务端数据也不会删除。`clear` 命令只清空本地记录。
- 命令历史列出当前面板的记录，最新的在前，时间为提交时的本地时间（`YYYY-MM-DD HH:mm`）；点击一条会把命令填回输入框，不会执行。
- 命令记录和草稿只保存在内存中。`scopeKey`、`requestOptions` 或 Provider 的配置变化时，Console 清空记录和草稿并中止进行中的请求，卸载时同样中止。
- 设置 `commandHistoryKey` 后，Console 将已提交的命令文本及时间保存在浏览器本地存储中。刷新后，历史菜单和方向键可回查同一份记录。浏览器存储空间不足时，新记录会按需替换当前作用域最早的记录。若新记录仍无法写入，则保留已有历史并跳过保存。「新建会话」清除当前作用域的历史。
- 身份字段使用函数时，保持函数引用稳定，并在身份变化时更新 `scopeKey`，或用身份作为组件的 `key`。
- Console 撑满父容器的宽高，父容器需要有明确的高度，或是可伸展的 flex 布局。
- 切换 `locale` 会更新已有记录里的命令帮助、参数错误和取消提示，保留记录和草稿；服务端返回的内容保持原样。
- 认证、账号切换和页面布局由宿主负责。`onOpenUri` 只上报资源链接的打开意图，导航由宿主完成。
- 类型从 `@openviking/react/modules/console` 导出，包根入口只导出 `Console` 和 `ConsoleProps`。

原生 VikingBot 的附件在发送请求前校验，不符合原有图片类型或 URL 要求时通过 Toast 提示并保留草稿。自定义 `chatOptions.service` 负责自己的附件契约。
