# 登录与认证表单

六个组件，覆盖选择登录方式、邮箱或 API Key 登录、请求重置邮件、设置密码和确认邀请。

## 何时使用

- `EmailLoginForm`：用邮箱和密码登录，可附带忘记密码入口。
- `ApiKeyLoginForm`：用 API Key 登录，输入内容默认遮蔽，可切换显示。
- `PasswordResetRequestForm`：用户忘记密码时请求发送重置邮件，支持重新发送并显示等待秒数。
- `PasswordSetupForm`：首次设置密码，或通过邮件链接重置密码。
- `LoginMethodSelector`：宿主支持多种登录方式时，让用户先选择一种。
- `InvitationConfirmation`：展示邀请信息，让用户接受、拒绝或稍后处理。
- 请求、登录态和页面跳转由宿主负责：这些组件只负责输入、校验和展示，不发起请求，也不需要 `OpenVikingProvider`。

## 引入

```tsx
import { EmailLoginForm } from '@openviking/react/components/auth/email-login-form';
import '@openviking/react/components/auth/email-login-form/style.css';

import { ApiKeyLoginForm } from '@openviking/react/components/auth/api-key-login-form';
import '@openviking/react/components/auth/api-key-login-form/style.css';

import { PasswordResetRequestForm } from '@openviking/react/components/auth/password-reset-request-form';
import '@openviking/react/components/auth/password-reset-request-form/style.css';

```

## API

### 公共属性

`EmailLoginForm`、`ApiKeyLoginForm`、`PasswordResetRequestForm` 和 `PasswordSetupForm` 都支持以下属性。

| 参数        | 说明                                                                   | 类型                  | 默认值                   |
| ----------- | ---------------------------------------------------------------------- | --------------------- | ------------------------ |
| loading     | 宿主处理提交期间设置：禁用输入和提交，并显示忙碌状态                   | `boolean`             | `false`                  |
| disabled    | 禁用输入和提交                                                         | `boolean`             | `false`                  |
| error       | 显示在提交按钮上方的错误提示，组件不解析后端错误码                     | `ReactNode`           | -                        |
| title       | 表单标题，渲染为 `h2`                                                  | `ReactNode`           | -                        |
| description | 标题下方的说明                                                         | `ReactNode`           | -                        |
| back        | 表单顶部的返回入口，没有 `onClick` 时不显示                            | `AuthAction`          | -                        |
| agreements  | 协议配置；`items` 非空时显示协议勾选框，未勾选的提交会先弹出确认对话框 | `AuthAgreements`      | -                        |
| labels      | 覆盖界面文案，字段见 `AuthLabels`                                      | `Partial<AuthLabels>` | -                        |
| locale      | 界面语言，规则见[国际化](../guide/i18n)                                | `'zh-CN' \| 'en-US'`  | 继承上级，默认 `'en-US'` |
| className   | 附加到根元素的类名                                                     | `string`              | -                        |

## 注意

- 提交时先校验输入，再处理协议：已勾选则直接触发 `onSubmit`，未勾选则弹出确认对话框，点击同意会勾选协议并触发 `onSubmit`。
- 确认对话框使用原生 `<dialog>` 的 `showModal()`，需要浏览器支持。取消或按 Esc 会关闭对话框，保留输入，不勾选协议，也不提交。
- 组件不发起请求，也忽略 `onSubmit` 的返回值。宿主在处理期间设置 `loading`，失败时通过 `error` 展示，成功后的跳转也由宿主完成。
- 表单的 `loading` 和 `disabled` 禁用输入、提交按钮和 `forgotPassword`，`back` 和 `alternateLogin` 仍可点击；`InvitationConfirmation` 的 `loading` 和 `disabled` 禁用全部按钮。
- 输入内容、字段错误、密码显隐和协议勾选保存在表单内部。更换账号或协议内容时，给表单设置新的 `key` 重新挂载，才会清空输入和已同意的协议。
- 邮箱按基本格式校验，为空时同样提示邮箱无效。登录密码和 API Key 只检查非空，不套用新密码的强度规则。
- `PasswordSetupForm` 检查两次输入一致，密码强度只由 `validatePassword` 决定，组件没有默认强度规则。
- 把 `required`、`invalidEmail` 或 `mismatch` 设为空字符串，只会隐藏对应的错误文案，校验结果不变。
- 密码和 API Key 只保存在输入框状态里，组件不会存储、记录或去除首尾空白；邮箱在提交前去除首尾空白。
- 输入框设置了 `autocomplete`，密码管理器可以识别：邮箱登录用 `username` 和 `current-password`，设置密码用 `new-password`，API Key 输入框为 `off`。
- `LoginMethodSelector` 没有内置文案，不提供 `locale` 和 `labels`。`InvitationConfirmation` 只有接受按钮一条内置文案，用 `acceptLabel` 修改，不提供 `labels`。
- `InvitationConfirmation` 只展示 `details`，`onAccept`、`decline` 和 `defer` 只通知宿主。邀请预览、状态判断，以及展示登录、设置密码还是确认加入，由宿主决定。
- 每个组件最宽 440px，宽度随容器收缩，居中和整页布局由宿主决定。
- 六个组件共用同一份样式，各 `style.css` 入口内容相同；同一页面用到多个组件时，引入其中一个即可。
- 颜色取自 `--ov-ui-color-*` 主题变量，暗色模式跟随 `<html>` 上的 `.dark` 类，详见[快速开始](../guide/getting-started)。
- 类型从各组件子路径导出：`AuthAction`、`AuthAgreements` 和 `AuthLabels` 可从四个表单的子路径导入，`AuthAction` 也可从 `invitation-confirmation` 导入。包根入口只导出六个组件和它们的 Props 类型。
