# VikingBot headless chat

Manage chat requests, streamed content and sessions for Console or a standalone VikingBot host. This module exports no composed view and has no CSS entry.

## Import

```tsx
import {
  useVikingBotChat,
  useVikingBotSessions,
} from '@openviking/react/modules/viking-bot';
```

## Example

`VikingBot` remains a view component. Import `useVikingBotChat` and `useVikingBotSessions` from `@openviking/react/modules/viking-bot` to use it independently. They inherit `OpenVikingProvider` request settings, or use same-origin defaults. This example uses a fixed simulated service and never accesses real data.

## API

### Options

| Property        | Description                                                                     | Type                                               | Default                      |
| --------------- | ------------------------------------------------------------------------------- | -------------------------------------------------- | ---------------------------- |
| locale          | Localizes UI and library errors without changing content or restarting requests | `'zh-CN' \| 'en-US'`                               | Inherited, otherwise `en-US` |
| enabled         | Disables automatic requests and operations when false                           | `boolean`                                          | `true`                       |
| requestOptions  | Overrides Provider request settings                                             | `OvRequestOptions`                                 | Inherited                    |
| scopeKey        | Change alongside a dynamic identity to cancel previous requests and clear state | `string`                                           | -                            |
| service         | Stable service; chat and session hooks accept their corresponding contracts     | `VikingBotChatService` / `VikingBotSessionService` | Native service               |
| taskService     | Background task query adapter; shared inside Console                            | `VikingBotTaskService`                             | Native task endpoint         |
| sessionId       | Current session for the chat hook                                               | `string`                                           | Created on first send        |
| initialMessages | Initial chat messages; keep the reference stable                                | `readonly VikingBotMessage[]`                      | `[]`                         |
| persist         | Saves completed messages; omit `saveMessage` when the backend persists          | `boolean`                                          | `true`                       |

### Results and operations

`useVikingBotChat` returns `sessionId`, `messages`, `streaming`, `status`, `error` and separate `persistenceError`. `send(string | VikingBotDraft)` returns whether a normal terminal event was received; failure or cancellation returns `false` while retaining partial content. `abort()` stops, `selectSession(id)` loads history, `reset()` starts a blank conversation, `reload()` reloads history, and `setMessages()` replaces local messages while idle. First send creates a session. `persist` defaults to `true`; native history does not store transient reasoning.

`useVikingBotSessions` returns `sessions`, `isLoading`, `error`, `refresh()`, `create()` and `remove(id)`. Creation failure returns `undefined`; removal failure returns `false`; both allow retry. Mounting loads the list. `enabled: false` disables automatic requests and operations.

Both accept `requestOptions`, `scopeKey` and stable `service` objects. Chat also accepts `sessionId`, `initialMessages` and `persist`; keep `service` and `initialMessages` references stable. Service, session or identity changes cancel the previous owner. Locale changes only update presentation and library-generated error text; inputs, AI replies and backend errors remain unchanged. Commercial hosts normalize TOP event IDs, delta/snapshot and terminal states to `VikingBotChatEvent`, omitting `saveMessage` when the backend persists automatically. Authentication, CSRF, monitoring and product side effects stay in the host.

`canInterrupt` reports whether the service implements `interrupt`. Only wire `onCancel` when it is true; commercial adapters without it show no stop action. `abort()` can also clean up the local connection, which does not imply that the backend task stopped. Native adapters support in-flight follow-ups; current commercial adapters do not enable them.

`canSteer` reports whether the adapter implements `steer(input, signal)`. Standalone views map it to `canSendWhileStreaming` and pass `isSubmitting`; both view props default to `false` and contain no protocol checks. Calling the same `send()` during generation uses steer and returns acceptance; calling it while idle starts a normal request and waits for the stream to finish. Accepted follow-ups split assistant segments at the next iteration event, preserving display and persistence order.

### Background tasks

Declare tasks started by a tool in `tool-result.tasks`. Each `VikingBotTaskReference` requires `id` and optionally includes `kind`, `uri` and `status`. The native adapter extracts task IDs from structured JSON returned by known submission tools, never prose. Other adapters supply `tasks` directly.

Tool completion, chat completion and background task completion remain separate. Tool parts in returned messages expose current snapshots through `tasks`, preserving the original `output`. Console shares scheduling and notifications with Terminal; standalone hooks track tasks within their own instance, leaving notifications to the host. See [Console task API](./console#consoletaskservice) for query, state and lifecycle rules; `VikingBotTaskService` uses the same query contract.

## Composition

[Console](./console) consumes this module internally. Standalone hosts using [VikingBot](../components/viking-bot) import its component styles separately. This module has no UI, CSS or browser-global dependency; hooks are not re-exported from the package root or Console.

## Adapter API

Every method receives the operation AbortSignal and must honor cancellation. Reject/throw on failure, preserving backend errors. Native history reads complete `messages.jsonl` via the session metadata URI with `limit: -1`, rather than budgeted `/context`. Stream failures persist completed segments and accepted inputs. The unfinished reply remains visible locally and is not persisted as a complete assistant message; send still returns `false` and status remains error, so partial output does not imply success.

### VikingBotChatInput

| Property    | Description               | Type                             | Default  |
| ----------- | ------------------------- | -------------------------------- | -------- |
| sessionId   | Session ID                | `string`                         | Required |
| text        | Submitted text            | `string`                         | Required |
| attachments | Host-uploaded attachments | `readonly VikingBotAttachment[]` | Required |
| references  | Resource references       | `readonly VikingBotReference[]`  | -        |

### VikingBotChatService

| Property      | Description                                                           | Type                                                                                    | Default  |
| ------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | -------- |
| stream        | Streaming request; must emit a complete or interrupted terminal event | `(input: VikingBotChatInput, signal: AbortSignal) => AsyncIterable<VikingBotChatEvent>` | Required |
| createSession | Create a session                                                      | `(signal: AbortSignal) => Promise<VikingBotSession>`                                    | Required |
| loadMessages  | Read complete session history                                         | `(id: string, signal: AbortSignal) => Promise<readonly VikingBotMessage[]>`             | Required |
| saveMessage   | Save a message; omit when the backend persists automatically          | `(id: string, message: VikingBotMessage, signal: AbortSignal) => Promise<void>`         | Optional |
| interrupt     | Interrupt backend generation; distinct from local connection cleanup  | `(id: string, signal: AbortSignal) => Promise<{ interrupted: boolean }>`                | Optional |
| steer         | Append input to the active stream; acceptance is not completion       | `(input: VikingBotChatInput, signal: AbortSignal) => Promise<{ accepted: boolean }>`    | Optional |

### VikingBotSessionService

| Property      | Description      | Type                                                            | Default  |
| ------------- | ---------------- | --------------------------------------------------------------- | -------- |
| listSessions  | List sessions    | `(signal: AbortSignal) => Promise<readonly VikingBotSession[]>` | Required |
| createSession | Create a session | `(signal: AbortSignal) => Promise<VikingBotSession>`            | Required |
| removeSession | Delete a session | `(id: string, signal: AbortSignal) => Promise<void>`            | Required |

### VikingBotChatEvent

| Property    | Description                                                                            | Type                                                                                                                | Default |
| ----------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------- |
| reasoning   | delta=true appends, false replaces; optional stable id updates the same reasoning item | `{ type: 'reasoning'; text: string; delta: boolean; id?: string }`                                                  | -       |
| text        | Append text for delta=true; otherwise replace the current text segment                 | `{ type: 'text'; text: string; delta: boolean }`                                                                    | -       |
| iteration   | Next model iteration boundary; accepted follow-ups start a new segment                 | `{ type: 'iteration'; iteration: number }`                                                                          | -       |
| tool        | Unique ID for every actual call, including identical arguments                         | `{ type: 'tool'; part: VikingBotToolPart }`                                                                         | -       |
| tool-result | Match calls by id; native ID-less events pair in FIFO order                            | `{ type: 'tool-result'; id: string; output: string; isError?: boolean; tasks?: readonly VikingBotTaskReference[] }` | -       |
| complete    | Normal terminal event; optional text is the final text snapshot                        | `{ type: 'complete'; text?: string }`                                                                               | -       |
| interrupted | Interrupted terminal event; retains content and send returns false                     | `{ type: 'interrupted' }`                                                                                           | -       |

`canInterrupt` / `canSteer` derive from method presence. `accepted: false` rejects follow-up input without adding a user message. Ending a stream without a terminal event produces `BOT_STREAM_TRUNCATED`.
