# Modules

FileBrowser coordinates directory browsing, search and preview through `useFileBrowser`. Console provides a native command panel and standalone `useConsole`, alongside the ScopeCascade coordinator. Conversation services remain host-owned.

Modules load native API data through their Hooks. Hosts supply configuration and controlled values; modules report changes through callbacks.

| Module                           | Component                | Target capability |
| -------------------------------- | ------------------------ | ----------------- |
| [`file-browser`](./file-browser) | `FileBrowser`            | File browser.     |
| [`console`](./console)           | `Console` / `useConsole` | Console.          |

## Import and styles

Import a component and its Props / Labels / Slots types from `@openviking/react/modules/<module>`. The two component bodies and their main Props types are also exported from `@openviking/react`; Labels, Slots and the enum types come from the subpath only.

JavaScript does not load CSS. Import `@openviking/react/modules/<module>/style.css` for one module, `@openviking/react/modules/style.css` for all modules, or `@openviking/react/style.css` for the full library. Each stylesheet works independently. There is no aggregate `@openviking/react/modules` JavaScript entry.

Requests inherit `OpenVikingProvider` from `@openviking/react/client`; `useFileBrowser` and `useConsole` are also available independently. FileBrowser loads directories automatically; Console issues requests only when a command is submitted.

## Host responsibilities

Hosts own page layout, authentication, account scope, routing, and permissions. Product onboarding, resource and Skill import flows, and synchronization settings remain in the host. Administration is outside these module boundaries.

## Scope cascade

[ScopeCascade](./scope-cascade) provides working request and cascade Hooks plus a default view. Supply three host API adapters; each level subscribes independently.
