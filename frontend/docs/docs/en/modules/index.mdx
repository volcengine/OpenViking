# Blocks

Blocks ship with their own data loading and state: import one from `@openviking/react` and place it in your page to get a complete feature, such as a file browser, a command panel or a cascading selector.

## When to use

- You want a file browser or command panel where the block handles requests, paging and state: FileBrowser and Console call the OpenViking native API through `OpenVikingProvider`.
- You need to pick a library, a space and a user in turn: ScopeCascade loads through the three functions you provide and does not call the OpenViking native API.
- You only need plain views and load the data yourself: use the [business components](../components/), which do not need `OpenVikingProvider`.

## Import

```tsx
import { FileBrowser } from '@openviking/react/modules/file-browser';
import '@openviking/react/modules/file-browser/style.css';
```

The subpath of a block is `modules`: import it from `@openviking/react/modules/<name>`; the table above has the full paths. The root entry `@openviking/react` also exports the block component and its main Props type, such as `FileBrowser` and `FileBrowserProps`; other types, such as Labels, Slots and enums, come from the subpath only. There is no aggregate `@openviking/react/modules` entry.

JavaScript imports do not load CSS. Pick one of these stylesheet entries; each works on its own:

- `@openviking/react/modules/<name>/style.css`: one block, including the styles of the components it uses.
- `@openviking/react/modules/style.css`: all blocks.
- `@openviking/react/style.css`: the whole library.

## Request configuration

FileBrowser and Console request the OpenViking native API through the nearest `OpenVikingProvider`, so they must sit inside one. Put a single Provider at your app root and configure the service address and credentials there once; the blocks take no such props:

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <FileBrowser />
  <Console />
</OpenVikingProvider>;
```

Without a Provider, FileBrowser sends no requests and its tree stays in the loading state, while Console uses a same-origin default client that carries no identity.

ScopeCascade does not use the shared client, has no `requestOptions` and does not need a Provider; inside a Provider it can inherit language and use [analytics](../guide/analytics).

### OpenVikingProvider

An omitted field inherits from the outer Provider; in the outermost Provider it takes the value in the Default column.

| Property           | Description                                                                                                                                                                    | Type                                          | Default                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------- | -------------------------------- |
| baseURL            | Service address with an optional gateway prefix, excluding `/api/v1`; an empty string means same-origin requests                                                               | `string`                                      | `''`                             |
| apiKey             | Credential, sent as the `X-API-Key` header; the commercial edition authenticates with a browser cookie, so omit it there                                                       | `string \| (() => string \| Promise<string>)` | -                                |
| accountId          | OpenViking account ID, which corresponds to the data space, sent as the `X-OpenViking-Account` header                                                                          | `string \| (() => string \| Promise<string>)` | -                                |
| userId             | User ID within the account, sent as the `X-OpenViking-User` header                                                                                                             | `string \| (() => string \| Promise<string>)` | -                                |
| resourceId         | Current library ID, which decides the library a request addresses, sent as the `V-Resource-Id` header                                                                          | `string \| (() => string \| Promise<string>)` | -                                |
| credentials        | The `credentials` option passed to `fetch`, which decides whether cookies are sent; cross-origin requests still follow the server's CORS rules and the browser's cookie policy | `'include' \| 'same-origin' \| 'omit'`        | `'include'`                      |
| signal             | Aborts requests; in-flight requests are cancelled when it fires                                                                                                                | `AbortSignal`                                 | -                                |
| fetch              | Replaces the global `fetch`, for tests, tracing or environments without a global `fetch`                                                                                       | `typeof fetch`                                | Global `fetch`                   |
| locale             | Interface language of the subtree, see [Internationalization](../guide/i18n)                                                                                                   | `'zh-CN' \| 'en-US'`                          | Inherited, otherwise `'en-US'`   |
| analytics          | Interaction and exposure configuration; see [Analytics](../guide/analytics)                                                                                                    | `OpenVikingAnalyticsOptions \| false`         | Inherited, disabled at the root  |
| queryClient        | Reuses a host TanStack Query v5 client; inherits or creates an internal client when omitted                                                                                    | `QueryClient`                                 | Stable for the Provider lifetime |
| requestConcurrency | Positive integer limits per API path; merges with inherited settings                                                                                                           | `Partial<Record<OvPath, number>>`             | `{ [OV_PATHS.fsLs]: 3 }`         |
| children           | The subtree that uses this request configuration                                                                                                                               | `ReactNode`                                   | -                                |

- The identity fields `apiKey`, `accountId`, `userId` and `resourceId` also accept a function that is evaluated on every request, so it can read a rotated credential.
- `fetch`, `signal` and function-valued identity fields are compared by reference. A change creates a new client and the blocks that use it reset, so keep them referentially stable.
- Mounting the Provider sends no request and reads no credential stored in the browser.

### Query cache and concurrency

The SDK includes its query runtime; installing `@tanstack/react-query` separately is unnecessary. Each internal QueryClient stays stable for its Provider lifetime, retries once after failure, uses a 5-second stale time, and retains TanStack's default window-focus refetch behavior. Directory pages and searches live in the query cache; expansion, selection, and input belong to each block instance.

If your host already uses TanStack Query v5, pass its native client directly. No additional QueryClientProvider is required:

```tsx
import { QueryClient } from '@tanstack/react-query';
import { OpenVikingProvider, OV_PATHS } from '@openviking/react/client';

const queryClient = new QueryClient();

<OpenVikingProvider
  baseURL="/openviking"
  queryClient={queryClient}
  requestConcurrency={{ [OV_PATHS.fsLs]: 3 }}
>
  <App />
</OpenVikingProvider>;
```

External clients retain the host's query policies. The SDK neither overwrites their defaults nor clears their caches on unmount. Nested Providers inherit the parent's client unless explicitly overridden.

By default, `requestConcurrency` limits only directory children requests, `GET /api/v1/fs/ls`. Other endpoints are unlimited unless configured. Settings merge per endpoint, including through nested Providers. Under one QueryClient, trees and search-scope pickers share a queue for the same service and identity scope. Endpoints count independently. Actual retries pass through the queue; retry delays hold no slot.

Query keys include the resolved service, identity and resource scope, and response parameters. Credentials never appear in readable query keys. Removing one consumer does not cancel another consumer's shared request. An explicit `signal` ends that consumer's subscription; the query runtime handles cancellation when the last consumer leaves. Successful directory writes invalidate the current scope's cache. A failed background refresh retains loaded rows and offers retry, without changing a successful write into failure.

Search debouncing belongs to the block, outside QueryClient configuration. FileBrowser uses 400ms.

### Overriding the request configuration

FileBrowser and Console accept an optional `requestOptions` prop of type `OvRequestOptions`, exported from `@openviking/react/client`. Use it to change the request configuration of one block only, for example to point it at another library:

```tsx
const otherLibrary = { resourceId: 'library-b' };

<FileBrowser requestOptions={otherLibrary} />;
```

`OvRequestOptions` contains `baseURL`, `apiKey`, `accountId`, `userId`, `resourceId` and `signal`, with the same meanings as in the table above; `credentials` and `fetch` can be set on the Provider only. The rules:

- Fields are resolved one by one, from highest priority to lowest: the block's `requestOptions`, the nearest `OpenVikingProvider`, then the library defaults.
- With nested Providers, the inner one overrides only the fields it declares and inherits the rest from the outer one.
- An omitted or `undefined` field inherits; `baseURL: ''` explicitly means same-origin.
- Passing `''` for an identity field clears the inherited value, and the request no longer sends that header.
- An override affects that one block only: it does not change the Provider or any other block.
- Keep the `requestOptions` object referentially stable by defining it outside the component or with `useMemo`; the Notes of each block page describe what happens when it changes.
