# FileBrowser

A file browser that combines a directory tree, search and a file preview. It reads OpenViking directories and content itself and supports editing, `.ovpack` import and export, version history and permission management, with built-in Wiki and experience dashboards.

## When to use

- You want users to browse OpenViking context directories (user, session, agent, resources) and preview or edit the files in them.
- You want the block to coordinate loading, paging, preview and refresh: it calls the native API through `OpenVikingProvider`, while your app provides sign-in, account scope, routing and import flows, and the server checks permissions.
- You only need the plain views and load the data yourself: use [FileTree](../components/file-tree) and [FilePreview](../components/file-preview) on their own. Use [Console](./console) for the command panel or conversation.

## Import

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import '@openviking/react/modules/file-browser/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <FileBrowser />
</OpenVikingProvider>;
```

The stylesheet includes the styles of FileTree, FilePreview, FileBrowserActionBar, WikiDashboard and ExperienceDashboard. File content is rendered by [FilePreview](../components/file-preview), so install its optional peer dependency `@ark-design/ui` first. For the Provider and request configuration, see the [blocks overview](./).

### Basic usage

Shows how the directory tree, search and preview work together, plus the Wiki and experience dashboards. The buttons below switch the previewed resource type, and the drop-down switches the preview actions mode. Dashboard actions stay pinned to the visible right edge of the tree during horizontal scrolling.

Select “Preview video” to see the sample segment’s transcript and extracted frames. Select a transcript entry to seek the player or a frame to enlarge it.


The example uses fixed data and sends no network requests. Enter `profile` in the search box for results or `error` for a failed search, and click Import resources to see the `onImportResources` event your app receives below the example.

### Directory navigation

Calling `openResource` automatically expands and refreshes a directory target. Page two contains an expandable directory with an extensionless file. Reveal that directory, then refresh its parent to check paging and expansion; clear the simulated failure before retrying in the tree.

```tsx file="../../_demos/file-browser-navigation.tsx" preview

```

This is an offline simulation. The root has no tree row; revealing it scrolls its child list to the top.

### ACL permission management

With `acl` on, nodes under `viking://resources/` show the current user's effective permission, and a user who can manage the node opens the grants dialog from the details of the permission tag. Switch "Current permission" to see each level, and tick "Simulate save failure" or "Simulate directory failure" to see the error states.

```tsx file="../../_demos/file-browser-acl.tsx" preview

```

The example is an offline simulation and changes no real grants.

### Preview actions

`previewActions` hides built-in actions and `previewSlots` appends, replaces or hides the action area. The drop-down below the Basic usage example shows each mode.

```tsx
<FileBrowser
  previewActions={{
    edit: false,
    delete: false,
    importPack: false,
    configure: false,
  }}
  previewSlots={{
    actionItems: (context) => [
      ...context.defaultActions,
      [
        {
          key: 'share',
          icon: <ShareIcon />,
          label: 'Share',
          onClick: () => share(context.path),
        },
      ],
    ],
  }}
/>
```

### Rendering failure

When host content fails to render, the block shows the default fallback: an illustration, a message and a Retry display button. Pass `slots.errorFallback` to replace it.

```tsx file="../../_demos/file-browser-crash.tsx" preview

```

FileBrowser manages the daily, weekly and disabled schedule choices. Weekly schedules include a weekday picker; enabled schedules accept a typed time or the time panel. Changing frequency preserves unsaved weekday and time values, and failed saves can be retried. Hover or focus directory and Skill paths to read their full values.

History dialogs reserve their content height and show a centred loading indicator while reading files, versions and content. Compilation directory and Skill pickers remain busy from opening until their initial path has finished expanding.

### FileBrowserExpansionSnapshot

Save the complete object returned by `onExpansionSnapshotChange` and pass it to `defaultExpansionSnapshot` on the next mount.

| Property      | Description                                                                      | Type                                            | Default           |
| ------------- | -------------------------------------------------------------------------------- | ----------------------------------------------- | ----------------- |
| expandedUris  | Expanded folder URIs                                                             | `readonly string[]`                             | Required          |
| collapsedUris | Explicitly folded folder URIs                                                    | `readonly string[]`                             | Required          |
| pendingEdits  | Optional edits awaiting alias identity resolution, ordered from oldest to newest | `readonly { uri: string; expanded: boolean }[]` | `[]` when omitted |

Each pending edit identifies a folder with `uri`. `expanded: true` opens it and `false` folds it. Preserve the emitted order so that the latest edit takes precedence after identity resolution. A stored fold takes precedence over an equivalent expanded URI unless a later pending reopen supersedes it.

### FileBrowserOpenResourceOptions

| Property | Description                                                                               | Type      | Default |
| -------- | ----------------------------------------------------------------------------------------- | --------- | ------- |
| reveal   | Expands ancestors and directory targets, refreshes target children and scrolls to the row | `boolean` | `true`  |

| viewSwitch  | The Preview / Source switch; hidden while editing; only for formats that support both views, so not for images, video or directories under `viking://system`                               | `boolean` | `true`  |
| edit        | The edit button; only for writable files in an editable format, never for experience files, `viking://system` resources or L0/L1 summaries                                                 | `boolean` | `true`  |
| copyContent | The Copy content action, which copies the previewed text or directory summary (only the displayed part if truncated); hidden for binary media and `viking://system` directories            | `boolean` | `true`  |
| download    | The Download action, which saves the original content of a file; shown for files only                                                                                                      | `boolean` | `true`  |
| history     | The Version history action; shown for Wiki outputs, Wiki directories and non-resource text files                                                                                           | `boolean` | `true`  |
| configure   | The Compile configuration action; shown only on the root directory of a Wiki compile target, and still viewable when read-only                                                             | `boolean` | `true`  |

### FileBrowserPreviewSlots

| Property     | Description                                                                                                                                       | Type                                                                                               | Default |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------- |
| actions      | Replaces the whole action area, `null` hides it; you render Save, Cancel and extras yourself, and Copy path and the permission tag are unaffected | `ReactNode \| ((context: FileBrowserPreviewActionContext) => ReactNode)`                           | -       |

Each item is a single action or an array of actions; see [FilePreview](../components/file-preview) for the action format.

### FileBrowserPreviewActionContext

The context received by `previewSlots.actions` and by the function form of `previewSlots.actionItems`; you only read it and never build it. It contains every property of the `FilePreviewActions` of [FilePreview](../components/file-preview) (`source`, `path`, `viewMode`, `setViewMode`, `canSwitchView`, `editing`, `draft`, `busy`, `canEdit`, `startEditing`, `saveEditing`, `cancelEditing`, `canCopyPath` and `copyPath`) and adds the three below.

| Property       | Description                                                                                                       | Type                     | Default |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------ | ------- |
| defaultActions | Built-in actions, already filtered by resource capability, `previewActions`, `readOnly` and permissions           | `FilePreviewActionItems` | -       |
| canDelete      | Whether the current user can delete the current resource; not affected by `previewActions.delete`                 | `boolean`                | -       |
| deleteFile     | Opens the built-in delete confirmation without closing the preview tab; has no effect when `canDelete` is `false` | `() => void`             | -       |

`defaultActions` has three groups: copy content, download, version history and compile configuration; import and export .ovpack; delete. The action keys are `copyContent`, `download`, `history`, `configure`, `importPack`, `exportPack` and `delete`.

### FileBrowserAclReport

The grants report received by `acl.onChange`; you only read it. `acl_mode` is `'none'` when neither the node nor its ancestors have permissions set, `'inherit'` when it inherits the parent's grants and adds direct ones, and `'restricted'` when it ignores the parent and uses only direct grants.

| Property          | Description                           | Type                                  | Default |
| ----------------- | ------------------------------------- | ------------------------------------- | ------- |
| uri               | Resource URI                          | `string`                              | -       |
| acl_mode          | Permission mode                       | `'none' \| 'inherit' \| 'restricted'` | -       |
| direct_entries    | Grants made directly on this resource | `FileBrowserAclEntry[]`               | -       |
| inherited_entries | Grants inherited from ancestors       | `FileBrowserAclEntry[]`               | -       |
| effective_entries | Grants that are actually in effect    | `FileBrowserAclEntry[]`               | -       |

### FileBrowserAclEntry

One grant in the grants report; you only read it.

| Property  | Description                                                                                    | Type                  | Default |
| --------- | ---------------------------------------------------------------------------------------------- | --------------------- | ------- |
| principal | The principal that is granted access, as `user:<id>` or `group:<id>`; `user:*` means all users | `string`              | -       |
| level     | Grant level                                                                                    | `FileBrowserAclLevel` | -       |

### FileBrowserAclLevel

`'read' | 'write' | 'manage'`: `read` can view content, `write` can view and edit, and `manage` can also delete and manage grants.

## Notes

### Requests and layout

- FileBrowser is `100%` of its parent's height, so the parent needs an explicit height. The component has no border or background; your app decides its frame.
- Changes to `rootUri` or `requestOptions` reload the tree from the root and abort in-flight requests. A `requestOptions` change also reloads the preview. A structured snapshot applies to the initial query scope only. After the client, identity, root or cache scope changes, it is discarded. If `defaultExpandedUris` was omitted, `defaultExpandedUri` controls initialization again and its changes reload that new tree.
- An inline `requestOptions` object is new on every render, so define it outside the component or keep it stable with `useMemo`.
- The same goes for `acl.resolvePermission` and `acl.listPrincipals`: a new reference requests permissions and members again, so define them outside the component or keep them stable with `useCallback`.
- Types are exported from `@openviking/react/modules/file-browser`; the package root exports only `FileBrowser` and `FileBrowserProps`.

### Directories and preview

- Directories expand on demand and load 200 entries per page; Load more at the end of a directory loads the next page.
- Under the `viking://` root, directories appear in the order user, session, agent, resources, followed by the rest. With any other `rootUri`, the order the server returns is kept.
- Click a file to preview its content; click a directory to expand and select it, and the preview shows its L0 summary and L1 overview.
- Names derived from resource URIs are decoded once for tree rows, preview tabs, search labels and breadcrumbs. Requests, selection and expansion snapshots keep the original URI; malformed escapes remain unchanged.
- Directories under `viking://system` show no summaries.
- Use `defaultExpandedUri` on its own to expand the tree to a single location at mount. After the first render, changes to the controlled `uri` [open and reveal the resource](#open-and-reveal-a-resource).
- To persist tree expansion across mounts, save the complete `onExpansionSnapshotChange` object per account and root and pass it as `defaultExpansionSnapshot` on the next mount. Keep optional `pendingEdits` in their emitted order. After identity resolution, a stored fold takes precedence over an equivalent expanded URI unless a later pending reopen supersedes it. An initial controlled URI is located within the restored open folders.
- If a listing fails during restoration, the saved snapshot is kept. Collapsing a visible folder or expanding a folder through a later controlled `uri` change reports a new snapshot without waiting for the remaining pages to load. It retains unresolved paths in other open branches, including folders on a later, failed root page. Identity recovery resumes saved descendants on later pages even when it succeeds during the initial restoration pass. Manual tree toggles take precedence over earlier controlled navigation that is still loading. Retry keeps the error visible while it waits for the active restoration pass to finish. With the URI-only `onExpandedUrisChange` callback, a potentially matching fold waits for a successful home lookup before publishing. Refresh retries the lookup.
- Text files are read up to 2000 lines, and the preview says when the content is truncated.
- Images, video, audio, PDF, Office documents and archives are read through the content download endpoint, chosen by file extension.
- Editable formats are `.md`, `.json`, `.jsonl`, `.txt`, `.yaml` and `.yml`: editing reloads the full content, saving calls `POST /api/v1/content/write`, and the preview reloads afterwards.
- File body reads explicitly request `raw=false`, with a fallback in the block's shared read layer. Preview, source and editing drafts receive the same body.
- Trailing `MEMORY_FIELDS` comments are internal metadata written by the server. They are removed only in memory namespaces, so preview and editing never show them; same-shaped body comments, and examples in resources and skills, survive.
- YAML scalar ranges preserve same-shaped value content, while separately appended trailers are still removed; the body is never reserialized.
- Line boundaries, whitespace and word characters follow the server's Python semantics. A page that fills the preview cap triggers a full read before filtering and truncation, so a page end cannot be mistaken for a file end or expose partial metadata.
- Wiki ownership follows compile targets and resource tags, independently of dashboard visibility. Trailing `CONFLICTS_CONTENT` comments are separated from the body and still supplied to the conflict dashboard parser. Invalid JSON stays out of the body while the dashboard retains its error and retry behavior.
- When you open a Wiki file for editing, unresolved conflicts with a unique body match highlight the matching lines. The highlight follows edits until the entire highlighted block is deleted. Select a conflict's pencil to open the editor at that conflict. Hover over a highlighted line to see its description and reason. Scrolling the editor or moving focus outside closes the tooltip.
- The dashboard tab is hidden while editing a file and returns after saving or cancelling.
- Saving a Wiki file shows a progress notice in the upper right, followed by a success notice if the write succeeds. Wiki saves send `use_snapshot: true` to preserve version history and `resolve_conflicts: true` so the server preserves and updates conflict records. Ordinary text saves leave snapshots disabled by default.
- All YAML frontmatter, ordinary HTML comments and fenced Markdown examples survive. In a Markdown file with confirmed scope, an unclosed reserved trailer starting on its own line is hidden through the end of the file; markers quoted in YAML frontmatter, code fences or inline examples survive.
- The refresh button reloads the expanded directories and the current preview.

### Open and reveal a resource

Pass a terminal link, search result, or import result URI to the mounted `FileBrowser` through `uri`. The browser opens the preview, expands ancestors, loads additional pages as needed, selects the target and scrolls it into view. Other expanded branches are preserved.

`FileBrowser` accepts a React 18/19 ref for explicit navigation. Call `openResource` to reveal the current URI again, wait for navigation to finish, or open only the preview.

```tsx
import { useRef } from 'react';
import { FileBrowser } from '@openviking/react/modules/file-browser';
import type { FileBrowserHandle } from '@openviking/react/modules/file-browser';

const browserRef = useRef<FileBrowserHandle>(null);

<FileBrowser ref={browserRef} />;

await browserRef.current?.openResource(resultUri, { reveal: true });

// Expand the imported directory and refresh its children.
await browserRef.current?.openResource(directoryUri);
```

Links ending in `/.abstract.md` or `/.overview.md` open the parent directory at L0 Summary or L1 Overview, respectively. Tree navigation and `onUriChange` use the parent URI. Opening another summary link in the same directory selects its requested level; manual level switching remains available.

`openResource` reveals the target by default. With `{ reveal: false }`, it requests only a preview and resolves to `true` once it issues the request. In controlled mode, update `uri` in `onUriChange` to accept the command. The promise resolves to `true` after the selected row has scrolled, or `false` when the target is missing, inaccessible, outside `rootUri`, superseded, or the component unmounts.

Directory targets automatically expand and refresh their children; file targets only expand their ancestors and never request children. Refresh keeps the old list visible and replaces it atomically after reloading the loaded range. A previously exhausted listing is reloaded through its new last page. If expanded child directories move beyond the loaded range, loading continues until they are found or the listing ends. Other directories keep their cached data and expansion state. Entries confirmed deleted by the refreshed listing are removed. A failed child refresh retains the old list and selection, with the existing directory error row and retry action; it does not turn successful navigation into failure.

The root has no tree row. Revealing it refreshes its children and, once the host accepts selection, scrolls its tree container to the top and returns `true`. No child is selected on its behalf and no synthetic root row is added.

Directory listings needed to locate the target, or required home alias lookups, reject on failure; catch them to display host feedback. An explicitly unsupported alias lookup falls back to matching the original URI spelling. Caller cancellation resolves to `false`. The promise waits for navigation and the requested child refresh, but not for preview content to finish loading. Built-in search uses the same navigation entry, so directory results also expand automatically. Your app supplies the URI; task display names are never appended to file paths.

### Search

- The search box at the top of the left column opens the module's search dialog; `⌘K` is a real shortcut, and when a page mounts several instances only the one interacted with last responds.
- Typing pauses for 400 ms before the request fires; there is no submit button. Closing the dialog cancels the in-flight request and clears the input and filters.
- Four retrieval modes share one input and one result list. Use “Switch” at the top of the results area at any time. The result count appears after each successful search, including when there are zero matches. Switching modes keeps the query and filters supported by the new mode:

| Mode     | Endpoint                | Input              | Filters                                |
| -------- | ----------------------- | ------------------ | -------------------------------------- |
| `find`   | `/api/v1/search/find`   | Natural language   | Directory (multi), content level, time |
| `search` | `/api/v1/search/search` | Natural language   | Same as `find`                         |
| `grep`   | `/api/v1/search/grep`   | Regular expression | Directory (single), ignore case        |
| `glob`   | `/api/v1/search/glob`   | File pattern       | Directory (single)                     |

- Semantic results rank by score and deduplicate by URI. `grep` keeps each match and its line number, even when several matches share a file.
- A `glob` pattern without `/` gains a `**/` prefix; a directory match drops its trailing slash before navigation and records the directory fact on `isDir`.
- Filter groups enable or disable with the mode. A disabled group stays visible but dimmed, with the reason beside its title. Directory candidates derive from `rootUri` with the `~` alias; selections invalidated by a root change are dropped.
- In Advanced, select a suggested directory or use “Choose a directory” to browse its subdirectories. Choose a time field to show the date range. The start date must be on or before the end date. Ignore case is shown in `grep` mode.
- Use **↑ / ↓** to move the current result. Click or press **Enter** to close the dialog, open the resource and reveal its tree row.

### Preview actions

- While browsing, the right side of the header holds the Preview / Source switch, the edit button and the action menu. Copy path sits beside the breadcrumb, followed by the permission tag.
- Editing hides the Preview / Source switch. Save and Cancel stay visible, along with Version history, Copy content and Copy path when available for the current file.
- The visibility flags only control whether a default button is shown, not the capability: `canDelete`, `deleteFile()` and the editing methods in the `previewSlots` context keep working.
- Compilation settings display source directories, target directory, Skill and update schedule. Edit each field with its picker or schedule form; changes apply to future runs.
- Ordinary resource files have no history action.
- `readOnly` disables all writes, including saving the compile configuration. With `acl` on, editing, import and saving the compile configuration require `write` or `manage`, and deletion requires `manage`.
- Copying content, downloading, exporting, viewing version history and viewing the compile configuration remain available regardless of `readOnly` and ACL settings.
- Without `acl`, or for resources outside `viking://resources/`, the block does not probe permissions and the server enforces access.
- After an editable non-resource text file saves, choose **Keep a snapshot** or **Skip**. Keeping it opens a required description field; **Save snapshot** sends `POST /api/v1/snapshot/commit`. Skipping or cancelling leaves the file saved. Failures keep the description for retry, and unchanged content shows a separate result. Wiki compile files retain their automatic versions.
- The history dialog also lets you describe and save a non-resource text file snapshot. It captures the server’s current file at submission time; intervening writes may be included.
- Wiki directories let users select a descendant file, preview historical content, compare two versions, and restore a single file through `POST /api/v1/snapshot/restore`. History pages native Git commits through `GET /api/v1/snapshot/versions` with `before_snapshot`, displays committer time, and reads content with the selected commit ID and current file path. Legacy version indexes remain supported; services without the versions endpoint fall back to the latest 500 entries from `GET /api/v1/snapshot/log`. The first version supports an added-file diff. Turn off Show changes to read the full document. A version that deletes the file can show the removed lines in Show changes. With Show changes off, that version shows a deletion notice instead of an empty document.
- Gateways can provide history through `GET /api/v1/snapshot/log` and historical content through `GET /api/v1/snapshot/show`. Both deletion confirmation paths require an HTTP 404 from `/show` with `error.code` set to `"NOT_FOUND"`, `error.details.type` set to `"git_blob"`, and a string `error.details.resource` (the requested file URI in the native response).
- Within `error.details`, `reason: "path_not_found"` and `deleted_file: true` confirm that the path is missing in the selected commit and the first parent has a file at that exact path. `deleted_file: false` leaves the read error in place.
- For a matching 404 with no `error.details.deleted_file`, the legacy fallback accepts an omitted `error.details.reason` or `"path_not_found"`. FileBrowser queries `/log` from the selected commit (`branch`) with the file URI (`paths`). If the selected commit matches, it uses `GET /api/v1/snapshot/diff` to confirm a `deleted` change from `parents[0]` to the selected commit. The `/log` filter compares the exact tree entry against `parents[0]`, including for merge commits. A different `reason` or a non-boolean `deleted_file` leaves the read error in place.
- The native `/diff` endpoint handles UTF-8 text up to 10 MiB and 100,000 lines per input, with a 20 MiB limit on the generated diff. If this fallback cannot confirm a deletion, the history view displays a read error.
- Compile configuration: `GET /api/v1/compile/config` reads it, and `POST /api/v1/compile/config/update` saves source directories, Skill and the update schedule. The target directory is read-only, and existing instructions and execution arguments are preserved. When multiple configurations share a directory, tabs switch between their settings and edits, initially showing the first configuration. A single configuration opens directly without tabs. Reads and updates identify it by `compile_name`. An empty state appears when the current user has no associated configuration.
- Import .ovpack: the file is first uploaded through `POST /api/v1/resources/temp_upload`, then `POST /api/v1/pack/import` imports it into the current directory. On failure the chosen file is kept, and a retry uploads it again.
- Export .ovpack: `POST /api/v1/pack/export` returns the content, which is saved as `<name>.ovpack`; downloads use `GET /api/v1/content/download`.
- Delete: after confirmation, `DELETE /api/v1/fs?uri=...&wait=true` runs. On failure the dialog stays open and can retry; on success the parent directory is selected and the tree is refreshed. Only files can be deleted, not directories.
- A request is not submitted twice while one is running, and in-flight requests are aborted when the account or resource changes or the component unmounts.

### Permissions (ACL)

- `acl` only applies to non-root nodes under `viking://resources/`; elsewhere no permission tag appears and ACL imposes no limits.
- The effective permission is read from `access` in `GET /api/v1/fs/stat`. If it is missing, `GET /api/v1/acl` is probed: success counts as `manage` and a 403 counts as unknown.
- While the permission is unknown, no permission tag shows and editing and deletion are unavailable; if reading it fails, a Retry button appears beside the title.
- The permission tag shows the effective permission, and for `manage` its details include a Manage permissions button that opens the grants dialog.
- `read` cannot edit, `write` can edit and import, and `manage` can also delete and manage grants.
- In the dialog you can search and add Users or Groups, grant `read`, `write` or `manage`, change levels and remove grants. The administrators row is fixed. The host can supply a known administrator ID to show the user by name.
- While a node inherits its parent's permissions, adding permissions saves immediately. Lowering or removing an existing permission first needs a confirmation in the dialog to stop inheriting, after which the node becomes `restricted`; cancelling writes nothing.
- A restricted node can Restore inheritance: the dialog lists the direct grants that will stop applying, and confirming clears them and follows the parent again.
- While saving, the dialog cannot be submitted again or closed. If saving fails, the last saved grants stay and the server's reason is shown.
- After a successful save the tree and preview refresh; the server's index update may finish later, and the server's authorization result is authoritative.
- In the directory listing (`fs/ls`), nodes with `access: 'denied'` cannot be selected or expanded, and nodes with `access: 'container'` can only be expanded to reach accessible children and cannot be previewed themselves.
- Grants use `GET` and `PUT /api/v1/acl`. Restoring inheritance sends an empty direct grant list with `acl_mode: inherit`. The member directory calls the account's user and group endpoints (20 users per page, `include_credentials=false`) and needs an `accountId` from the Provider or `requestOptions`.
- The group directory needs account administration access. When a resource manager cannot read it, the dialog shows a failure with Retry; supply your own directory through `acl.listPrincipals`.
- `acl.readOnly` only blocks changing grants and is independent of `readOnly`.

### Dashboards

- The experience dashboard shows for a user's `memories/experiences` directory and its direct `.md` files, including those under `peers/<peer>/`.
- The Wiki dashboard shows for directories with the `compile_target=true` tag or listed in the compile configuration, and the files and subdirectories below them get their own Wiki dashboards.
- The tag takes precedence over the compile configuration: a dashboard still shows when the configuration lacks the target.
- The compile configuration (`GET /api/v1/compile/configs`) is read on demand: when a Wiki dashboard opens, or when a reserved Wiki trailer in the body needs an ownership check; ordinary browsing does not request it.
- When `dashboardKinds` omits `'wiki'`, Wiki is no longer detected and the compile configuration is not read, so Wiki resources lose their Compile configuration and the Compile-specific history index.
- Rows that have a dashboard show an icon in the tree. Hover or focus the icon for an action hint, and click it to open the dashboard.
- Pending conflicts can mark the file and its ancestor Wiki directories, including collapsed directories. Refresh reloads the conflict markers. If a conflict lookup fails, unconfirmed statuses remain unknown.
- The tabs in the preview switch between the content and the dashboard.
- Ordinary resources have no Wiki tab, and a detected Wiki keeps its dashboard even with no conflicts.
- A `viking://~/...` alias and the canonical URI of the same resource are detected the same way, and the `uri` passed to `renderDashboard` keeps the spelling it came with.
- Both dashboards can also be used without FileBrowser, see [WikiDashboard](../components/wiki-dashboard) and [ExperienceDashboard](../components/experience-dashboard).

### Experience dashboard data source

Pass host request functions through `experienceDataSource`. Omitted functions use the default OpenViking endpoints, except for `effect`, `sourceGroups`, `trajectoryMessages`, and `tests`. Keep each callback reference stable and pass its `signal` to the underlying request. Reject on failure so the built-in dashboard can display the error and retry.

- `list({ uri, offset, limit, signal })` returns `{ items, hasMore, total? }`, with one page of experience files in `items`. Resolve to `undefined` to use the default listing for that URI.
- `effect({ uri, startDate, endDate, signal })` returns `{ injectionCount, recallCount, injectionRate }` for a single experience. The rate is a fraction from 0 to 1. Omit the loader to show dashes.
- `outcomes({ uri, startDate, endDate, signal })` returns an array of `{ outcome, count }` entries.
- `trajectories({ uri, offset, limit, startDate, endDate, signal })` returns `{ items, hasMore, total }`, with one page of injection trajectories in `items`.
- `sources({ uri, signal })` returns an array of source trajectories.
- `sourceGroups({ uri, signal })` returns commit groups newest first, each with `id`, `updatedAt`, and `trajectories`. Takes precedence over `sources`.
- `trajectoryMessages({ uri, signal })` receives a trajectory URI when its details open and returns `{ archiveUri?, items }`. FileBrowser reads the trajectory document.
- `tests({ uri, offset, limit, signal })` returns `{ items, total }`, where `items` contains the test materials for that page. Supplying it enables the Test tab for an individual experience. The tab loads when opened.
- The page `offset` starts at 0 and `limit` is 20. Dates use UTC `YYYY-MM-DD` and are omitted for the all-time range.

### Experience dashboard sections

Pass `experienceDashboardSlots.sections` to customize the built-in dashboard while using its data and request state. See [ExperienceDashboard sections](../components/experience-dashboard#section-slots).

### Failure states

- Operation failures use floating feedback: Toast for local validation and clipboard failures, and a dismissible Notification for request failures. The title identifies the operation, the body preserves the server reason, and failed forms retain their inputs for retry.

- When a directory listing fails, the tree shows a failure row with Retry; the root is no exception and is never shown as "no files". Retry on the row reloads only that directory.
- When the preview fails, the detail pane shows a failure state: `labels.error` is the conclusion, the server's own message is the reason, and `labels.retry` is the button, which reloads the tree and the current preview together.
- The empty state (`labels.empty`) appears only when nothing is selected; a selected resource that cannot be read shows the failure state.
- A directory's L0 summary and L1 overview are requested separately: when one fails, only that level shows its reason, and when both fail the whole preview shows the failure state. Without a server message, `labels.summaryFailed` is shown.
- An empty response or a server-generated `Directory … is not ready` placeholder displays the empty state for that level.
- When a search fails, the dialog keeps the endpoint's reason, and you can submit the same query again to retry.

### Tree width

- When the container is narrower than 521px, the tree and preview stack and the horizontal resizer is hidden.

- A draggable divider sits between the tree and the preview: drag it, or focus it and press the left and right arrow keys (16px each). Its accessible name comes from `labels.resizeTree`.
- The tree is 352px wide by default and at least 200px. Its maximum is the smaller of 520px and the container width minus 321px (the preview keeps at least 320px, plus a 1px divider), so in a narrow column the tree shrinks instead of crowding out the preview.
- The width applies to the current instance only and is not written to `localStorage`; whether to remember it is up to your app.
- The current width is written as the CSS variable `--ov-file-browser-tree-width` in the root element's inline style. You can read it, but overriding it has no effect.
