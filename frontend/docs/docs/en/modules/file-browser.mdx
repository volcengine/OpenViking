# FileBrowser

Directory navigation, search and content preview as one module. The module loads its own data; the host supplies configuration, the controlled current resource, the toolbar entries and copy.

The component already wires the tree, the search and the preview together: directories expand on demand and page, clicking a file loads the preview, and a search result opens the preview too. `useFileBrowser` can be used on its own to assemble a different view.

## Basic usage

The example uses fixed data and makes no network request:

```tsx file="../../_demos/file-browser-basic.tsx" preview

```

## Scope

The module covers the file tree and the file preview only. The command panel belongs to `console`.

## What the module owns

- Directory, search, current URI and preview loading, coordinated inside the module: clicking a directory node or a search result moves the selection and loads the preview, and switching resources drops stale requests. Clicking a directory also expands it and makes it the current resource, with its L1 overview on the right (falling back to the L0 abstract when empty).
- Refreshing the affected directory, search results and preview after a save, rename or delete.
- The layout of the search, directory and preview area.
- The search box and refresh control in the toolbar, plus per-row state such as uploading progress, conflicts and retention settings.
- The preview tabs. Which tabs a resource has follows from the resource itself, so the host does not supply them.
- The search view. Search is a private view inside this module, not a published component or module: it opens from the toolbar or ⌘K, and picking a result moves the tree and loads the preview. Nothing about it is exported, because leaving the tree leaves it without a destination. `console` has its own `@` picker over the same kind of API; that is a separate view, not this one.

## What the host owns

- Request configuration through the Provider, overridable per module through `requestOptions`.
- Sign-in, account scope, routing and permissions.
- The entries in the top row: connect an agent, import resources. Compose them with `FileBrowserToolbarButton` inside `toolbarActions` so they match the console. Entries can nest inside a popover or dropdown when a click alone is not enough.
- Connection dialogs, import flows and onboarding. The module embeds none of them.

## Entries and toolbar

The top band holds the host's entries on a tinted background; under it sit the module's own search box and refresh button. The host adds entries through `toolbarActions`, using `FileBrowserToolbarButton` so the styling matches:

```tsx
import {
  FileBrowser,
  FileBrowserToolbarButton,
} from '@openviking/react/modules/file-browser';

<FileBrowser
  toolbarActions={
    <>
      <FileBrowserToolbarButton icon={<ConnectIcon />} onClick={connect}>
        Connect agent
      </FileBrowserToolbarButton>
      <span className="ov-file-browser__entry-divider" aria-hidden="true" />
      <FileBrowserToolbarButton icon={<UploadIcon />} onClick={openImport}>
        Import resources
      </FileBrowserToolbarButton>
    </>
  }
/>;
```

A divider between entries is the explicit `ov-file-browser__entry-divider` element rather than an inferred one, so the host decides which two entries it separates.

Because `toolbarActions` is a node, an entry that needs a menu wraps its button instead of asking for another prop:

```tsx
<Popover content={<ResourceMenu />} trigger="hover">
  <FileBrowserToolbarButton icon={<UploadIcon />}>
    Import resources
  </FileBrowserToolbarButton>
</Popover>
```

Dividers between entries come from a CSS adjacent-sibling rule, so how many entries the host passes and how they nest makes no difference.

## Props

The module exports `FileBrowserProps` from the subpath and the root entry. `FileBrowserToolbarButton`, `FileBrowserToolbarButtonProps` and `FileBrowserLabels` come from the subpath only.

| Property             | Type                            | Default     | Description                                                                                                                                                                                                                                  |
| -------------------- | ------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requestOptions`     | `OvRequestOptions`              | —           | Request configuration override, applied field by field over the nearest Provider.                                                                                                                                                            |
| `uri`                | `string`                        | —           | The controlled current resource URI. When given, the host owns the current resource and the module only reports switch intent.                                                                                                               |
| `defaultUri`         | `string`                        | —           | Initial resource URI when uncontrolled. Nothing is selected when omitted.                                                                                                                                                                    |
| `toolbarActions`     | `ReactNode`                     | —           | Host entries on the left of the toolbar, composed with `FileBrowserToolbarButton`. Search, refresh and the dividers between entries stay with the module.                                                                                    |
| `onUriChange`        | `(uri: string \| null) => void` | —           | Called after the current resource changes; `null` when the selection is cleared.                                                                                                                                                             |
| `rootUri`            | `string`                        | `viking://` | Root of the tree, narrowing the browsed scope to a subtree.                                                                                                                                                                                  |
| `defaultExpandedUri` | `string`                        | —           | Path to expand to after the first load, opening and loading each level. When omitted only the root is expanded.                                                                                                                              |
| `locale`             | `'en-US' \| 'zh-CN'`            | —           | Language of the preview base's built-in copy. The module's own copy stays with `labels`.                                                                                                                                                     |
| `labels`             | `FileBrowserLabels`             | —           | Replaceable copy: `searchPlaceholder`, `searchEmpty`, `loading`, `refresh`, `empty`, `error`, `retry`, `previewMode`, `sourceMode`, `history`, `copyPath`, `viewSwitch`, plus `tree` / `preview` passed through to the tree and the preview. |
| `className`          | `string`                        | —           | Additional container class.                                                                                                                                                                                                                  |
| `style`              | `CSSProperties`                 | —           | Container style overrides.                                                                                                                                                                                                                   |

Labels are plain text; the host maps its own translation system into these props. No prop carries data — the module loads it.

The module loads its own data through `useFileBrowser`, so the host supplies no directory or preview data; `labels.tree` and `labels.preview` are passed through to the file tree and the file preview.
