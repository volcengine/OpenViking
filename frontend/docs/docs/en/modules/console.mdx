# Console

A panel with two modes: conversation mode connects native VikingBot chat, and command mode sends `ov` commands to the OpenViking native API and shows the results.

## When to use

- You want one panel where users can chat with VikingBot or run `ov` commands to browse, search and write to the knowledge base.
- You want to run OpenViking native API commands in the browser and keep the command records and input drafts when users switch modes.
- You only need the conversation view or the command input: use [VikingBot](../components/viking-bot) or [CommandConsole](../components/command-console). Use CommandConsole as well when you want to provide your own command list, because Console's commands are built in.

## Import

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/console/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <Console />
</OpenVikingProvider>;
```

The stylesheet includes the CommandConsole and VikingBot styles. For the Provider and request configuration, see the [blocks overview](./).

Conversation mode uses [VikingBot](../components/viking-bot), which depends on the optional peer dependency `@ark-design/ui`. It is not installed with `@openviking/react`; see the Import section of that page for how to install it.

### Basic usage

The example uses a simulated service and fixed conversation data, so it sends no real request. Its `+` button only selects local files in the browser, and the composer cannot send because the example sets no `onSend`.

### Built-in chat

Omit `conversation.messages`, `conversation.onSend`, and `conversation.composer` to let Console own requests, messages, and its editor. Hosts can still provide labels, slots, and `conversation.sessions`: its items, loading state, and errors supply presentation metadata, while `currentId` follows host navigation. Each explicit history selection notifies `onSelect` once, including reselecting the current session; asynchronously created IDs also notify `onSelect`. Each explicit New action notifies `onNew`, even before a remote session exists. Reflecting a newly created ID back into `currentId` does not restart its active response. Navigating to another session clears the old draft and prevents cancelled requests from restoring it.

Console manages requests, sessions and streaming state internally. Adapt another backend with a stable `chatOptions.service` implementing both chat and session contracts. Changing panel mode preserves the conversation; selecting or starting a session cancels the old connection. Persistence errors appear separately and do not turn a successful answer into a failed send.

Select **Create Wiki** or **Schedule daily report** to fill an empty draft or switch presets. When you send the prompt, the configured conversation service handles the request. Console shows any compilation questions the service returns through the same confirmation flow described below. Set `conversation.quickInputs` to supply your own list, or pass `[]` to hide the shortcuts.

```tsx file="../../_demos/console-chat.tsx" preview

```

This example uses simulated services, including native capabilities and the current commercial contract. The native adapter implements `interrupt` and `steer` for stopping and in-flight follow-ups. The current commercial adapter omits both: sending is disabled during generation and stop is hidden. Both support another question after completion.

Click the toolbar `@` or type `@` in the draft to browse, search and reference files or directories. The built-in picker uses `/api/v1/fs/ls` and `/api/v1/search/glob` in the current request scope and loads only when opened. Pass `{ selected, onChange }` in `chatOptions.referenceSelection` to share the selection with a file tree while keeping the built-in picker. The host removes sent references, and Console clears the selection when the conversation resets. Set `conversation.references` to supply your own candidates and selection in place of the built-in picker. Custom chat services receive the chosen items in the `references` field.

### Bot activation

Use `chatOptions.activation` when the current library controls access to VikingBot and the host starts its runtime. The example simulates an eligible library, a library with Bot disabled, and a start error.

```tsx file="../../_demos/console-activation.tsx" preview

```

Implement `isEligible` to confirm whether the current scope allows Bot access. Console shows the conversation tab and calls `getStatus` after it returns `true`. When the runtime has yet to start, clicking **Enable VikingBot** triggers the host's `start` callback. Console confirms readiness again before loading chat and session history. Update `scopeKey` or pass the corresponding `activation` when the library or identity changes. The simulated Volcengine host adapter maps `GetOpenVikingCollection`'s `EnableVikingBot === true` to the boolean returned by `isEligible`.

Keep the adapter stable for the current library and identity. All three callbacks receive an `AbortSignal` and should throw on failure. Pass `media` to replace the illustration with your introduction media.

### Human input

Send a message to try the built-in Wiki questions, or send “daily report” to try scheduled updates. Enable host form customizations to try asynchronous name validation, a custom output directory picker, a replacement instruction card and a schedule limited to 09:00–18:00. Enable “Simulate answer send failure” to check retained input, error clearing and retry.

```tsx file="../../_demos/console-hitl.tsx" preview

```

Console shows questions after a successful `request_user_input` tool result and a normal end to the current turn. It asks for source directories and the configuration name before the output directory when those answers are needed. Interrupted or truncated streams, error results and unsupported schemas keep the ordinary tool presentation. Set `chatOptions.hitl={false}` to disable automatic interaction. An explicit `conversation.interaction` uses the host's question and callbacks.

With a configured filesystem, Console opens a picker for source directories and Skills and checks the output directory before advancing. Custom chat services without a filesystem connection can enter URIs directly. An output directory cannot overlap a source directory. Console skips the Output type question only when it has an explicit answer or recognizes the Skill. Automatic updates stay off unless the tool supplies an enabled schedule or the user enables them.

History does not establish whether a turn completed normally. Loading history restores messages and answer summaries without reopening question cards. A new live response can still activate HITL after normal completion.

Submitting the last card sends a `request_user_input_response` JSON message to continue the conversation. It includes `schema_version: '1.0'`, `tool_call_id` and ordered `answers: { card_type, title, value }[]`. User bubbles, copy actions and history show readable label/value rows. Transport and persistence retain the original protocol text; option labels come from the corresponding question.

Configure cards through `chatOptions.hitl.cards[card_type]`. Use `configureCard(card)` to distinguish repeated types by `card.id` or `card.payload`. See [VikingBotInteractionFields](../components/viking-bot#vikingbotinteractionfields) for field names and value types. Validation runs before advancing, and only the final card calls the chat service. Hosts can add validation and supply data and requests for custom pickers.

### Commit a session

Use **Commit session** below the latest completed reply to request memory extraction for the current conversation. Console shows the submission state and follows the background task when the server returns a task ID. When the task returns a memory change file and `conversation.onOpenUri` is available, the result can be opened from the completion notification.

Set `chatOptions.memoryCommit={false}` to hide the action. A custom chat service can implement `commitSession`. Otherwise, Console uses the native session endpoint when native chat or a configured provider supplies that endpoint.

### Mode selection

Use `modes={['command']}` for TUI only or `modes={['conversation']}` for VikingBot only. Omitting it enables both. The mode switch is hidden when only one mode is enabled. Disabled modes are not rendered and send no requests. If `mode` or `defaultMode` is unavailable, Console displays the first enabled mode without calling `onModeChange`. Switching modes preserves chat; removing conversation from `modes` aborts its connection, and re-enabling it reloads sessions.

| Property   | Description                                                   | Type                                                                               | Default  |
| ---------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------- |

| status     | Task status; required in query results                        | `'pending' \| 'running' \| 'cancelling' \| 'completed' \| 'failed' \| 'cancelled'` | -        |

| uri        | Associated resource URI                                       | `string`                                                                           | -        |
| stage      | Execution stage returned by the server                        | `string`                                                                           | -        |
| result     | Server task result                                            | `unknown`                                                                          | -        |

| queryError | Scheduler query error; the last known task state is preserved | `{ code: 'request' \| 'invalid-response'; message?: string }`                      | -        |

Active tasks are queried every 3 seconds, with one query per scope and task ID and up to 4 concurrent requests. Query failures use exponential backoff capped at 30 seconds. Terminal states stop polling. Resource import progress is shown in its result record. Other active tasks also show a loading notification. Terminal states show the result icon, and query failures display a warning while the task status stays the same.

The task snapshot uses the completed result's resource URI when available and retains the submission URI as a fallback. A custom task service can provide the final resource directly in `uri`. When a terminal task completes with a resource URI, **View result** opens it through `command.onOpenUri` or `Console.onOpenUri`. The notification remains until the user opens the result or dismisses it.

Changing modes or chat sessions, clearing terminal history and dismissing notifications do not cancel backend tasks. Dismissing a notification leaves its records updating. Identity changes and Console unmount abort queries and discard stale responses. Task state and notifications are not persisted across page reloads.

Adapt other backends through a stable `taskService`; `chatOptions.taskService` can override chat task queries. Different services, identities and `scopeKey` values are tracked separately. A host that fully controls `conversation` also supplies its task presentation state.

## Commands

Command mode runs only the built-in native API commands. Type `/` or run `ov help` to see the commands and their options, grouped as Core workflow, Filesystem, Search & context, File transfer, Sessions and Config & status.

### Syntax

- Write a command as `ov find`, `/find` or just `find`.
- Wrap arguments that contain spaces in single or double quotes; a backslash also escapes a character.
- Quote values that start with `--`, as in `ov write viking://resources/a.md --content "--heading"`. Use `--` to end option parsing before a positional value. Short options are case-sensitive. In `tree`, `-L` sets tree depth and `-l` sets the abstract length limit.
- Arguments are parsed as data and no shell runs. Unquoted `| ; & < > $` and backticks are rejected, so quote URLs that contain `&`.
- Unknown options, repeated single-value options, missing arguments, invalid resource URIs and unclosed quotes produce a failed record without sending a request.

### Supported commands

| Capability      | Commands                                                                                                                                                                                                                                      |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add and compile | `add-resource [path-or-url]`, `add-skill [skill-content-or-url]`, `add-memory <content> --session-id <id>`, `compile create --compile-name <name> --from <source-uri> --to <target-uri> --skill <skill-uri>`, `compile --compile-name <name>` |
| Local           | `help`, `clear`                                                                                                                                                                                                                               |
| Service         | `health`, `status`                                                                                                                                                                                                                            |
| Browse          | `ls [uri]`, `tree <uri>`, `stat <uri>`                                                                                                                                                                                                        |
| Content         | `read <uri>`, `abstract <uri>`, `overview <uri>`                                                                                                                                                                                              |
| Search          | `find [query]`, `search [query]`, `grep <pattern>`, `glob <pattern>`                                                                                                                                                                          |
| Write           | `mkdir <uri>`, `write <uri> --content <text>`, `cp <from-uri> <to-uri>`, `mv <from-uri> <to-uri>`, `rm <uri>`                                                                                                                                 |
| Tasks           | `task list [--task-type <type>] [--status <status>]`, `task status <task-id>`, `task cancel <task-id>`                                                                                                                                        |

- `ls` defaults to `viking://`. Both `ls` and `tree` use `-n` or `--node-limit` to cap results, with a default of 256, and `-a` or `--all` to include hidden files. Use `-r` or `--recursive` and `-s` or `--simple` with `ls`. Set depth with `ov tree viking://resources -L 2` or `ov tree viking://resources --level-limit 2`. Tree depth defaults to 3. The existing `--offset` option also works for paging.
- For ranked `find` and `search`, use `-u` or `--uri` to scope the results, `-n` or `--node-limit` to cap them, and `-t` or `--threshold` to set a minimum score. Both accept `--image <url>` to search by image and `--after` or `--before` to filter by time. Use `--mode context` with `search` to assemble context. `grep` accepts `-i` or `--ignore-case`, `-x` or `--exclude-uri`, and `-L` or `--level-limit`.
- `write` replaces existing content by default. Choose `--mode create` to create a file or `--append` to append text. Pass a quoted JSON object to `--acl` on `mkdir` or `write`, as in `ov mkdir viking://resources/demo --acl '{"acl_mode":"inherit","entries":[]}'`. Use `-r` or `--recursive` when copying or removing a directory tree.
- `add-resource` accepts a remote address with optional `--include` and `--exclude` filters. Both `add-resource` and `add-skill` accept `--temp-file-id <id>` for a file uploaded by the host application. `add-skill` also accepts inline Skill content and uses `-p` or `--target-uri` to set the destination.
- `add-memory` appends the content to the session given by `--session-id` as a user message, then commits that session.
- Save a named configuration with `compile create`, then run it with `compile --compile-name <name>`. Repeat `--from` or separate source directory URIs with commas. Use `--instruction` for extra instructions and `--args` for model and scheduling options as a JSON object. `task status <task-id>` checks the returned task ID.
- `task cancel` asks the server for cooperative cancellation, so a task may not stop immediately.
- Imports, compiles and memory commits returning task IDs are tracked automatically. Task state is separate from submission results, and the terminal unlocks when submission returns.
- `session` supports creation, listing, details, context, archives, message writes, commits, and configuration. Use `ov session add-messages <session-id> '<messages-json>'` for batches.
- `ov get <uri> <local-path>` and `ov export <uri> <output.ovpack>` use browser downloads. The last segment of the output path becomes the filename. `export` and `backup` accept `--include-vectors`.
- `ov import <file.ovpack> <target-uri>` opens a file picker and accepts `--on-conflict` and `--vector-mode`. Hosts can reuse their file browser's import dialog through `commandOptions.choosePackFile`. The dialog accepts valid `.ovpack` archives.
- Local `add-resource` sources and `write --from-file` use browser file selection. The host owns local configuration and sign-in. Authorized hosts can opt in to `backup` and `restore` with `commandOptions.allowAdminCommands`.

## Notes

Failed questions and client-only errors stay in the message list. If no session was created, the next send creates one and carries undelivered user inputs as context in a single chat request, while saving the original user messages separately. Errors are excluded from persistence and model input. The native gateway accepts one `message`; writing session records alone does not restore model context. Undelivered inputs stay queued until the first stream event acknowledges delivery. A failure before that event preserves them for the next send; once generation starts, subsequent sends do not replay those inputs.

- Console sends native VikingBot chat requests by default. Providing `conversation.messages` or `conversation.onSend` gives the host ownership of chat and attachment state.
- Set `conversation.isAvailable` and `conversation.unavailableMessage` from the Bot status your app queries; when the Bot is unavailable, the composer is disabled and shows the message.
- Commands send requests only when the user submits them, never on mount. An instance runs one command at a time and disables the input while it runs.
- A failed command shows its error in its own record; fix the command and submit it again. A failed write may already have been accepted by the server, so check the result before you resubmit.
- The New session button in command mode aborts the in-flight request, ignores a late response, and clears the command records, error and input; operations the server already accepted are not undone, and no server data is deleted. The `clear` command only clears the local records.
- The command history lists the records of this panel, newest first, with the local time of submission (`YYYY-MM-DD HH:mm`); clicking one fills the command back into the input without running it.
- Command records and drafts live in memory only. When `scopeKey`, `requestOptions` or the Provider configuration changes, Console clears the records and drafts and aborts in-flight requests; unmounting aborts them too.
- With `commandHistoryKey`, Console stores submitted command text and timestamps in browser local storage. The history menu and arrow keys recall the same entries after a reload. When browser storage reaches its quota, new entries replace the oldest entries in the current scope as needed. If the new entry still cannot fit, Console skips saving it and keeps the existing history. New session clears that scope’s history.
- When an identity field is a function, keep the function reference stable and update `scopeKey` when the identity changes, or key the component by identity.
- Console fills the width and height of its parent, so give the parent an explicit height or a flex layout that can stretch it.
- Changing `locale` updates the command help, argument errors and cancellation notices already in the records, and keeps the records and drafts; content returned by the server stays as is.
- Your app handles authentication, account switching and page layout. `onOpenUri` only reports the intent to open a resource link, and your app does the navigation.
- Types are exported from `@openviking/react/modules/console`; the package root exports only `Console` and `ConsoleProps`.

Native VikingBot validates attachments before sending a request. Toast explains an invalid image type or URL, and the composer retains its draft. A custom `chatOptions.service` owns its attachment contract.
