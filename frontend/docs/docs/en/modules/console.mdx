# Console

A panel with two modes: conversation mode connects native chat through the [VikingBot headless module](./viking-bot), and command mode sends `ov` commands to the OpenViking native API and shows the results.

## When to use

- You want one panel where users can chat with VikingBot or run `ov` commands to browse, search and write to the knowledge base.
- You want to run OpenViking native API commands in the browser and keep the command records and input drafts when users switch modes.
- You only need the conversation view or the command input: use [VikingBot](../components/viking-bot) or [CommandConsole](../components/command-console). Use CommandConsole as well when you want to provide your own command list, because Console's commands are built in.

## Import

```tsx
import { OpenVikingProvider } from '@openviking/react/client';
import { Console } from '@openviking/react/modules/console';
import '@openviking/react/modules/console/style.css';

<OpenVikingProvider baseURL={endpoint} apiKey={apiKey}>
  <Console />
</OpenVikingProvider>;
```

The stylesheet includes the CommandConsole and VikingBot styles. For the Provider and request configuration, see the [blocks overview](./).

Conversation mode uses [VikingBot](../components/viking-bot), which depends on the optional peer dependency `@ark-design/ui`. It is not installed with `@openviking/react`; see the Import section of that page for how to install it.

### Built-in chat

Omit `conversation.messages`, `conversation.onSend`, and `conversation.composer` to let Console own requests, messages, and its editor. Hosts can still provide labels, slots, and `conversation.sessions`: its items, loading state, and errors supply presentation metadata, while `currentId` follows host navigation. Each explicit history selection notifies `onSelect` once, including reselecting the current session; asynchronously created IDs also notify `onSelect`. Each explicit New action notifies `onNew`, even before a remote session exists. Reflecting a newly created ID back into `currentId` does not restart its active response. Navigating to another session clears the old draft and prevents cancelled requests from restoring it.

Console uses both hooks from `modules/viking-bot` by default. Adapt another backend with a stable `chatOptions.service` implementing both chat and session contracts. Changing panel mode preserves the conversation; selecting or starting a session cancels the old connection. Persistence errors appear separately and do not turn a successful answer into a failed send.


This example uses simulated services, including native capabilities and the current commercial contract. The native adapter implements `interrupt` and `steer` for stopping and in-flight follow-ups. The current commercial adapter omits both: sending is disabled during generation and stop is hidden. Both support another question after completion.

### ConsoleTaskSnapshot

| Property   | Description                                                   | Type                                                                               | Default  |
| ---------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------- |
| id         | Background task ID                                            | `string`                                                                           | Required |
| status     | Task status; required in query results                        | `'pending' \| 'running' \| 'cancelling' \| 'completed' \| 'failed' \| 'cancelled'` | -        |
| kind       | Task category used for notification titles                    | `'resource' \| 'skill' \| 'memory' \| 'compile'`                                   | -        |
| uri        | Associated resource URI                                       | `string`                                                                           | -        |
| stage      | Execution stage returned by the server                        | `string`                                                                           | -        |
| result     | Server task result                                            | `unknown`                                                                          | -        |
| error      | Server task error                                             | `string`                                                                           | -        |
| queryError | Scheduler query error; the last known task state is preserved | `{ code: 'request' \| 'invalid-response'; message?: string }`                      | -        |

Active tasks are queried every 3 seconds, with one query per scope and task ID and up to 4 concurrent requests. Query failures use exponential backoff capped at 30 seconds. Terminal states stop polling.

Changing modes or chat sessions, clearing terminal history and dismissing notifications do not cancel backend tasks. Dismissing a notification leaves its records updating. Identity changes and Console unmount abort queries and discard stale responses. Task state and notifications are not persisted across page reloads.

Adapt other backends through a stable `taskService`; `chatOptions.taskService` can override chat task queries. Different services, identities and `scopeKey` values are tracked separately. A host that fully controls `conversation` also supplies its task presentation state.

## Commands

Command mode runs only the built-in native API commands. Type `/` or run `ov help` to see the commands and their options, grouped as Core workflow, Filesystem, Search & context and Config & status.

### Syntax

- Write a command as `ov find`, `/find` or just `find`.
- Wrap arguments that contain spaces in single or double quotes; a backslash also escapes a character.
- Quote values that start with `--`, for example `ov write viking://resources/a.md "--heading"`, or end option parsing with `--`, for example `ov write viking://resources/a.md -- --heading`. Option values work the same way, for example `--description "--example"`.
- Arguments are parsed as data and no shell runs. Unquoted `| ; & < > $` and backticks are rejected, so quote URLs that contain `&`.
- Unknown or duplicate options, missing arguments, URIs that do not start with `viking://` and unclosed quotes produce a failed record without sending a request.

### Supported commands

| Capability      | Commands                                                                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Add and compile | `add-resource <path>`, `add-skill <path>`, `add-memory <content> --session-id <session-id>`, `compile --from <from> --to <to>`, `compile create --from <from> --to <to>` |
| Local           | `help`, `clear`                                                                                                                                                          |
| Service         | `health`, `status`                                                                                                                                                       |
| Browse          | `ls [uri]`, `tree [uri]`, `stat <uri>`                                                                                                                                   |
| Content         | `read <uri>`, `abstract <uri>`, `overview <uri>`                                                                                                                         |
| Search          | `find <query>`, `search <query>`, `grep <pattern>`, `glob <pattern>`                                                                                                     |
| Write           | `mkdir <uri>`, `write <uri> <content>`, `cp <from_uri> <to_uri>`, `mv <from_uri> <to_uri>`, `rm <uri>`                                                                   |
| Tasks           | `task list`, `task status <id>`, `task cancel <id>`                                                                                                                      |

- `ls` and `tree` start from `viking://` by default and return at most 100 entries; page with `--limit` and `--offset`, and `tree` also accepts `--level_limit`.
- `write` replaces existing content by default; `--mode create` creates a file and `--mode append` appends.
- `add-resource` and `add-skill` accept remote addresses, not local file paths.
- `add-memory` appends the content to the session given by `--session-id` as a user message, then commits that session.
- `compile` uses the built-in llm-wiki Skill by default, and `--skill` selects another one; `compile create` only saves the compile configuration without starting a compile.
- `task cancel` asks the server for cooperative cancellation, so a task may not stop immediately.
- Option spelling differs by command: `add-skill` uses `--target-uri` while `find` uses `--target_uri`. Check `ov help` for the exact names.
- Imports, compiles and memory commits returning task IDs are tracked automatically. Task state is separate from submission results, and the terminal unlocks when submission returns.
- The command set covers only native APIs that a browser can call; local configuration, login, local file upload or download and session management commands are not included.

## Notes

- Console uses the VikingBot headless module for native chat by default. Providing `conversation.messages` or `conversation.onSend` gives the host ownership of chat; attachment uploads remain with the host.
- Set `conversation.isAvailable` and `conversation.unavailableMessage` from the Bot status your app queries; when the Bot is unavailable, the composer is disabled and shows the message.
- Commands send requests only when the user submits them, never on mount. An instance runs one command at a time and disables the input while it runs.
- A failed command shows its error in its own record; fix the command and submit it again. A failed write may already have been accepted by the server, so check the result before you resubmit.
- The New session button in command mode aborts the in-flight request, ignores a late response, and clears the command records, error and input; operations the server already accepted are not undone, and no server data is deleted. The `clear` command only clears the local records.
- The command history lists the records of this panel, newest first, with the local time of submission (`YYYY-MM-DD HH:mm`); clicking one fills the command back into the input without running it.
- Command records and drafts live in memory only. When `scopeKey`, `requestOptions` or the Provider configuration changes, Console clears the records and drafts and aborts in-flight requests; unmounting aborts them too.
- When an identity field is a function, keep the function reference stable and update `scopeKey` when the identity changes, or key the component by identity.
- Console fills the width and height of its parent, so give the parent an explicit height or a flex layout that can stretch it.
- Changing `locale` updates the command help, argument errors and cancellation notices already in the records, and keeps the records and drafts; content returned by the server stays as is.
- Your app handles authentication, account switching and page layout. `onOpenUri` only reports the intent to open a resource link, and your app does the navigation.
- Types are exported from `@openviking/react/modules/console`; the package root exports only `Console` and `ConsoleProps`.
