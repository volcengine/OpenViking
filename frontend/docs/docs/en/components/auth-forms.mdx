# Authentication forms

Authentication views without requests, routing, storage or page layout. Built-in labels are available in English and Simplified Chinese.

## Components

| Export                     | Purpose                         | Specific props                                                                                       |
| -------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `LoginMethodSelector`      | Choose a login method           | `methods`, `onSelect`                                                                                |
| `EmailLoginForm`           | Email/password login            | `defaultEmail`, `readOnlyEmail`, `forgotPassword`, `alternateLogin`, `onSubmit({ email, password })` |
| `ApiKeyLoginForm`          | API Key login                   | `alternateLogin`, `onSubmit({ apiKey })`                                                             |
| `PasswordResetRequestForm` | Request or resend a reset email | `defaultEmail`, `sentMessage: { email, message }`, `retryAfter`, `onSubmit({ email })`               |
| `PasswordSetupForm`        | First-time or reset password    | `account`, `passwordHint`, `validatePassword`, `onSubmit({ password })`                              |
| `InvitationConfirmation`   | Confirm an invitation           | `details`, `onAccept`, `decline`, `defer`, `acceptLabel`, `locale`                                   |

## Imports

```tsx
import { EmailLoginForm } from '@openviking/react/components/email-login-form';
import type {
  EmailLoginFormProps,
  AuthAgreements,
  AuthLabels,
} from '@openviking/react/components/email-login-form';
import '@openviking/react/components/email-login-form/style.css';
```

Each component has its own kebab-case JS and `style.css` entry; `@openviking/react` also exports the six components and their main Props types. Shared configuration types are exported only from form subpaths. No UI framework or internal theme package is required. Styles use the existing `--ov-ui-color-*` theme variables; dark mode follows the host's `html.dark` class.

## Form options

| Prop                    | Default             | Behavior                                                                                                      |
| ----------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------- |
| `loading` / `disabled`  | `false`             | Disable fields and submission; `loading` also exposes busy state                                              |
| `error`                 | absent              | Host-provided visible error; no backend error-code interpretation                                             |
| `title` / `description` | absent              | Optional form heading and description                                                                         |
| `className`             | absent              | Additional root class                                                                                         |
| `back`                  | absent              | Optional `{ label, onClick }` action                                                                          |
| `agreements`            | absent              | No checkbox or agreement gate unless a nonempty items array is supplied                                       |
| `locale`                | Provider or `en-US` | Override the nearest language scope with `zh-CN` or `en-US`                                                   |
| `labels`                | Current locale      | Partial `AuthLabels`; `undefined` inherits, and an empty string hides the message without changing validation |

Optional actions are shown only when they have an `onClick` handler. `forgotPassword`, `alternateLogin`, `decline` and `defer` use the same `{ label, onClick }` shape. Their callbacks do not imply any navigation or request.

```tsx
<EmailLoginForm
  forgotPassword={{ label: 'Forgot password?', onClick: openReset }}
  agreements={{
    items: [{ label: 'Terms', href: 'https://example.com/terms' }],
    confirmation: {
      title: 'Read and agree',
      description: 'Please review the linked terms before continuing.',
      confirmText: 'Agree and continue',
      cancelText: 'Cancel',
    },
  }}
  loading={pending}
  error={errorMessage}
  onSubmit={handleLogin}
/>
```

## Interaction contract

Forms own input drafts, field errors, password visibility and agreement UI. Validation runs before agreement confirmation; cancel or Escape preserves values without submitting or checking the agreement. Agree checks the box and submits the current valid values. No agreement URLs, organization names or legal policies are hard-coded. Use a new React `key` when changing account or agreement policy, to discard previous drafts and acceptance.

Email and API Key login require nonempty credentials; email also checks basic format. Login does not apply new-password strength rules. Password setup requires both entries and equality. Strength is host-defined: `validatePassword(password)` returns an error string, or `undefined` for valid input. Without it only required/equality checks apply. Password and API Key values are never persisted or logged by the components, and passwords are not trimmed.

`defaultEmail` is initial-only. Remount with `key` to reset a form or clear secrets after an attempt. Submission callbacks express intent and return no service data. The host must set `loading` while an asynchronous operation is pending and pass failures through `error`; the components never retry mutations automatically. No success navigation is built in.

Reset-email `sentMessage` is tied to its email so editing the input does not show success for a different address. `retryAfter` is a nonnegative remaining number of seconds supplied and updated by the host; the component renders the remaining wait and disables resubmission, but owns no timer or email delivery.

Invitation details are display-only `{ label, value }` rows. The host maps its own preview response to those rows and decides whether to show login, setup, confirmation or enter a workspace directly. `onAccept`, decline and defer never accept an invitation themselves.

## Host responsibilities

GetSession, Cookie/CSRF, authentication clients, token parsing, invitation state machines, account storage, cross-tab checks, password policy, mail delivery and routing remain outside these views. The runnable demo uses only fixed public data and simulated state, and never sends a request.
