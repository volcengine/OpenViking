# Auth forms

Six components that cover choosing a login method, logging in with an email or an API Key, requesting a password reset email, setting a password and confirming an invitation.

## When to use

- `EmailLoginForm`: users log in with an email and password, with an optional forgot-password entry.
- `ApiKeyLoginForm`: users log in with an API Key. The input is masked by default and can be revealed.
- `PasswordResetRequestForm`: users who forgot their password request a reset email, with support for resending and for showing the wait before the next send.
- `PasswordSetupForm`: users set a password for the first time, or reset it from an email link.
- `LoginMethodSelector`: your app offers several login methods and users pick one first.
- `InvitationConfirmation`: show the details of an invitation and let users accept, decline or postpone it.
- You handle requests, sessions and navigation yourself: these components only collect input, validate it and render. They send no requests and do not need `OpenVikingProvider`.

## API

### Common props

`EmailLoginForm`, `ApiKeyLoginForm`, `PasswordResetRequestForm` and `PasswordSetupForm` all accept these props.

| Property    | Description                                                                                                                                    | Type                  | Default                        |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | ------------------------------ |
| loading     | Set while your app handles the submission: disables the inputs and submit button and shows a busy state                                        | `boolean`             | `false`                        |
| disabled    | Disables the inputs and submit button                                                                                                          | `boolean`             | `false`                        |
| error       | Error shown above the submit button; the component does not interpret backend error codes                                                      | `ReactNode`           | -                              |
| title       | Form title, rendered as an `h2`                                                                                                                | `ReactNode`           | -                              |
| description | Text below the title                                                                                                                           | `ReactNode`           | -                              |
| back        | Back entry at the top of the form; hidden without `onClick`                                                                                    | `AuthAction`          | -                              |
| agreements  | Agreement configuration; when `items` is not empty, shows an agreement checkbox and asks for confirmation before submitting if it is unchecked | `AuthAgreements`      | -                              |
| labels      | Overrides interface text, see `AuthLabels` for the fields                                                                                      | `Partial<AuthLabels>` | -                              |
| locale      | Interface language, see [Internationalization](../guide/i18n)                                                                                  | `'zh-CN' \| 'en-US'`  | Inherited, otherwise `'en-US'` |
| className   | Class name added to the root element                                                                                                           | `string`              | -                              |

### EmailLoginForm

Shared props are listed in Common props.

| Property       | Description                                                                                                       | Type                                                    | Default |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ------- |

## Notes

- Submitting validates the input first, then handles agreements: with the box checked, `onSubmit` fires directly; otherwise a confirmation dialog opens, and agreeing checks the box and fires `onSubmit`.
- The confirmation dialog is a native `<dialog>` opened with `showModal()`, so the browser must support it. Cancelling or pressing Esc closes it, keeps the input, leaves the box unchecked and does not submit.
- The components send no requests and ignore the return value of `onSubmit`. Set `loading` while your app handles the submission, pass failures through `error`, and navigate after success yourself.
- In the forms, `loading` and `disabled` disable the inputs, the submit button and `forgotPassword`, while `back` and `alternateLogin` stay clickable. In `InvitationConfirmation` they disable every button.
- Inputs, field errors, password visibility and the agreement checkbox live inside the form. To clear them when the account or agreements change, remount the form with a new `key`.
- The email must match a basic email format, and an empty email shows the invalid-email message too. Login passwords and API Keys are only checked for being non-empty, not against new-password rules.
- `PasswordSetupForm` checks that both entries match. Password strength comes only from `validatePassword`; there is no default strength rule.
- Setting `required`, `invalidEmail` or `mismatch` to an empty string hides that message only; the form still fails validation.
- Passwords and API Keys stay in the input state: the components do not store, log or trim them. The email is trimmed before `onSubmit`.
- Inputs set `autocomplete` so password managers can recognize them: `username` and `current-password` for email login, `new-password` for password setup, and `off` for the API Key.
- `LoginMethodSelector` has no built-in text, so it has no `locale` or `labels`. `InvitationConfirmation` has one built-in string, the accept button, which you change with `acceptLabel`; it has no `labels` either.
- `InvitationConfirmation` only renders `details`, and `onAccept`, `decline` and `defer` only notify your app. Your app loads the invitation, decides whether to show login, password setup or confirmation, and navigates.
- Each component is at most 440px wide and shrinks with its container; centering and page layout are up to your app.
- The six components share one stylesheet: every `style.css` entry has the same content, so import any one of them when a page uses several.
- Colors come from the `--ov-ui-color-*` theme variables, and dark mode follows the `.dark` class on `<html>`; see [Getting started](../guide/getting-started).
- Types are exported from each component's subpath: `AuthAction`, `AuthAgreements` and `AuthLabels` from the four form subpaths, and `AuthAction` also from `invitation-confirmation`. The package root exports only the six components and their Props types.
