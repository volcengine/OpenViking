# FilePreview

A tabbed file preview that renders each file by its format, with a path breadcrumb, preview/source switching, text editing and actions you define.

## When to use

- You want to preview Markdown, code, JSON, tables, PDF, Office documents, images, audio and video in your app, with a path, tabs and an action area.
- You want to switch between a file, a directory's summary levels (L0 abstract, L1 overview) and content of your own (a dashboard, a graph) in one area: they map to the `file`, `directory` and `content` tabs.
- You want to decide where the data comes from, how it is saved and how navigation works: the component sends no requests and does not need `OpenVikingProvider`. When you use [FileBrowser](../modules/file-browser), the preview is already built in.

## Import

FilePreview renders the body with FileViewer from the optional peer `@ark-design/ui`. Install a version that satisfies `>=0.0.0-beta.7`, using the `beta` tag or an exact version. It declares `@arco-design/web-react`, `three` and `@types/three` as required peers, so install them too:

```bash
npm install @ark-design/ui@beta @arco-design/web-react three@^0.180.0 @types/three@^0.180.0
```

```tsx
import { FilePreview } from '@openviking/react/components/file-preview';
import '@openviking/react/components/file-preview/style.css';
```

`style.css` already includes the FileViewer styles, so you need no separate import. The body's colors come from Arco theme variables, so load a color theme at your app entry; see "Theme variables" below.

## Examples

### Basic usage

The three tabs are an editable Markdown file, a native image preview and a content tab your app renders. Click a path level or a link in the body, or switch between preview and source; the result appears below the demo.

```tsx file="../../_demos/file-preview-basic.tsx" preview

```

The demo renders its own toolbar through `slots.actions` with controls from the docs site; use your app's own buttons.

### Content levels and images

`levels` give one file three levels (L0, L1, L2), and `resolveImage` resolves the relative and `viking://` images in the Markdown. Switch levels to check the images of each, and click the image under "Original image" to enlarge it.

```tsx file="../../_demos/file-preview-console.tsx" preview

```

The demo uses fixed mock data; "Empty file" and "Image error" show those states.

### Injected actions

Inject your own commands with `actions`: one command is an icon button, and several collapse into the "…" menu. Switch the action layout, tick "Simulate failure" to see the failure message, and use the other checkboxes to show or hide the built-in controls.

```tsx file="../../_demos/file-preview-actions.tsx" preview

```

Demo commands wait 2 seconds; switch tabs or tick "Custom toolbar" while one runs, and the commands of that resource stay locked.

### State fallbacks

Switch the file type and the read state to compare the built-in states with the custom ones in `slots`.

```tsx file="../../_demos/file-preview-fallbacks.tsx" preview

```

The demo deliberately feeds invalid image and video data to trigger the error state; choose "Unsupported format" to download the demo's original bytes.

## Notes

### Tabs and layout

- Size: the component is `100%` wide and tall, so give its parent a definite height; the body scrolls inside the component.
- Lazy loading: FileViewer loads when a file body first renders, and importing the component neither loads it nor touches `window` or `document`.
- Content tabs: they have no header row and no `slots`, and the component adds no wrapper or scrolling around `content`, so put any toolbar, title and scroll container inside it.
- Directory tabs: summaries are read-only and have no `editing`; with only one level, the level switch is hidden.
- Two kinds of `levels`: a file tab's `levels` appear as a button group below the path row, each level may supply its own `editing`, and the callback is `onLevelChange`; a directory tab's `levels` appear as underlined tabs below the header row, and the callback is `onActiveLevelChange`.
- Keyboard: the tab row and a directory tab's level switch respond to the arrow keys, Home and End; every tab is disabled while a save runs.
- Exports: the component and its types come from `@openviking/react/components/file-preview`, and the package root does not export `FilePreview`; `FileViewerResource`, `ViewerHandle`, `ConfirmSlotProps` and `DownloadSlotProps` come from `@ark-design/ui/file-viewer/core`.

### Content and formats

- Binary content: pass PDF, Office documents and images through `source.file` or `source.url`, and do not decode them into a string for `content`.
- Supported formats: Markdown, code, JSON and JSONL, plain text, HTML, diff and patch, CSV, TSV, XLSX, PDF, DOCX, PPTX, images, video, and MP3 and WAV audio; CAD and 3D models are not included. The exact extensions follow the FileViewer renderers in `@ark-design/ui`.
- Images and video: they render with native browser elements, recognized by extension (png, jpg, jpeg, gif, webp, avif, bmp, ico, svg; mp4, webm, mov), `fileType` or MIME type, so what displays depends on the browser.
- Limits of images and video: they have no source view and cannot be edited; audio (mp3, wav) is played by FileViewer.
- Image display: images are centered and scaled to fit, show their original pixel size at the bottom right and open enlarged in a dialog on click; video uses the native controls and does not autoplay.
- URL lifetime: the component revokes the Blob URLs it creates from the `content` or `file` of an image or video when the source changes or the component unmounts; URLs you pass in `url` or return from `resolveImage` stay yours to manage.
- Markdown front matter: leading YAML metadata appears as a code block in the preview, while the source view, editing, saving and copying keep the original text.
- Dotted backdrop: Markdown bodies and the area around PDF, Word and PowerPoint pages show a dotted backdrop that follows the host theme; its colors are in Theme variables below.
- Markdown images: `resources` are matched first, then `resolveImage` is called, and a rejected `resolveImage` falls back to the image's original target; the component never turns `viking://` into an HTTP address.
- Markdown links: only Markdown bodies trigger `operations.openUri`, and the component passes the target as written, without resolving relative paths.
- JSON logs: `.json` and `.jsonl` render as a JSON tree; render structured files that need their own view, such as session logs, in a content tab.
- Large files: the component does not check file size; FileViewer shows a confirmation state when it needs one, and `slots.confirmFallback` replaces it. Limit the length of editable text in `editing`.
- Extras: previous/next image, neighbor preloading and video transcripts are not part of the component; compose them outside the preview, or inject them through `slots.actions` and `slots.footer`.
- FileViewer's own controls: the component hides its download, fullscreen, paging, search and zoom controls; use `getViewerHandle()` for paging, search and zoom, and an injected action for download.

### Path and breadcrumb

- Levels: `source.path` is split on `/`, a scheme such as `viking://` appears on the first level, and the last level is the current file name.
- No path: without `source.path` the breadcrumb shows only the file name and there is no copy-path button.
- Navigation: every ancestor is a button that passes its full URI (for example `viking://a/b`) to `operations.openParent`, not only the direct parent; the buttons are disabled without `operations.openParent`.
- Absolute paths: the ancestors of `/a/b/c.md` keep the leading `/`, and relative paths stay as written.
- Overflow: when the path does not fit, the levels after the first move into a "…" menu, and only if that is still too wide does the first level collapse too; the menu entries also call `operations.openParent`.
- Copy path: it uses `navigator.clipboard`, which needs a secure context (HTTPS or localhost); a failure shows `labels.copyFailed` and does not call `onCopyPath`.

### Actions and editing

- Presentation: no commands show no entry, one command is an icon button, and two or more collapse into a "…" menu.
- Groups: consecutive single commands form one group, each nonempty array is its own group, and empty arrays are ignored without splitting their neighbors; dividers separate groups.
- Function form: `actions` and `slots.actions` may be functions called during rendering, so return content from the context only, and do not send requests or update state inside them.
- Failure: the failure message appears beside the toolbar of that resource, and clicking again retries.
- Locking: a resource's injected commands stay locked while one runs, across tab or level switches and `slots.actions` replacement; other resources and other component instances are unaffected. A resource is identified by `source.path`, or by the tab's `key` and `fileName` when there is no path.
- While editing: injected commands and `slots.extraActions` are hidden, the toolbar shows Save and Cancel, and the view switch is disabled.
- Replacing the toolbar: `slots.actions` replaces the default toolbar together with Save and Cancel, so render them yourself with `startEditing`, `saveEditing` and `cancelEditing` from the context.
- Editing flow: Edit opens the source view with a text box, and saving or cancelling returns to the preview. While saving, switching tabs or levels and duplicate saves are blocked, and a failed save keeps the draft and shows `labels.saveFailed`.

### Text and states

- Scope of `labels`: it overrides only text the component renders itself; text rendered by FileViewer (large-file confirmation, unsupported-format messages, messages inside each renderer) follows `locale` and cannot be overridden one by one.
- Replacing it wholesale: to customize FileViewer's states, replace them with `confirmFallback`, `unsupportedFallback` and `downloadFallback` in `slots`.
- Images and video: they also use `loadingFallback` and `errorFallback`, and use `unsupportedFallback` when there is no source.
- Unsupported formats: passing `unsupportedFallback` takes over the whole unsupported state, so the download entry FileViewer would offer no longer appears.
- Download entry: `downloadFallback` receives `onDownload` and `onRetry`, and wins over `unsupportedFallback` when both are given.

## Theme variables

The shell takes its colors from `--ov-ui-color-*`: set them on your app root or any ancestor to re-skin, and the defaults below apply when they are unset; see [Getting started](../guide/getting-started). Dark mode reads the `.dark` class on `<html>` and ignores `prefers-color-scheme`.

| -------------------------------- | ----------------- | ------------------------ | ---------------------------------------- |
| `--ov-ui-color-primary`          | `#5252ff`         | `#5f5fff`                | Primary, focus ring                      |
| `--ov-ui-color-primary-hover`    | `#7075ff`         | `#7075ff`                | Primary on hover                         |
| `--ov-ui-color-text-1`           | `#0b0b0f`         | `#c7ccd6`                | Body text                                |
| `--ov-ui-color-text-3`           | `#6e718c`         | `#737a87`                | Secondary text                           |
