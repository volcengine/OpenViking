# FilePreview

Required `locale: 'zh-CN' | 'en-US'` selects built-in Chinese or English copy. Existing `labels` override individual fields; omitted fields follow locale. Hosts provide business content.

A tabbed file preview. The host supplies the content and file name; the component handles format detection, the tab row, the content header and the body.

Bodies use lazily loaded FileViewerCore adapters for Markdown, images, code, tables, PDF, Office and media, inside the console-style tab, breadcrumb and footer shell.

## Basic usage

Pass at least one tab. A file tab carries `source`; a content tab carries a node the host renders itself.


## Content levels and images

```tsx file="../../_demos/file-preview-console.tsx" preview

```

A file tab may supply `levels`, each with `key`, `label`, `source` and optional `resources`, `disabled`, `editing`. The selector appears below the path and defaults to the first enabled level. Control it with `activeLevelKey` and `onLevelChange`. Disabled levels cannot be selected. Switching discards drafts and restores preview mode; loading or saving blocks switching. Levels are read-only unless that level explicitly supplies `editing`.

The host loads each level: directories can expose L0 abstract and L1 overview, and files can add L2 content. The component does not request summaries. The required tab `source` remains the fallback when no level is available.

Supply original images through `source.url` or `source.file`, rather than binary data decoded into `source.content`. Images fit proportionally in a plain panel, show their original pixel dimensions at the bottom right and open a larger preview on click.

For Markdown images, `resources` matches the original image target. For dynamic authenticated images, supply `resolveImage(src, source): Promise<string>`. The host resolves relative paths or Viking URIs using the active level's `source.path`, returning an accessible URL. The host owns requests, cancellation and blob URL cleanup. Each level can override `resources`; omission inherits the file tab's resources. The component does not translate Viking URIs into HTTP endpoints.

Use `slots.footer` for modification time and parsing attribution in a two-sided footer, `slots.titleExtra` for permission badges and `slots.actions` for the host's menu.

## Two tab kinds

| Kind              | Rendered by     | Typical use                    |
| ----------------- | --------------- | ------------------------------ |
| `kind: 'file'`    | The component   | A file, its source, a document |
| `kind: 'content'` | The host, as-is | Dashboards, graphs, summaries  |

Both share the shell — tab row, path breadcrumb, copy path and the header action area. They differ in how the body arrives, and in that the preview/source switch is a file-tab capability: a content tab renders whatever views it needs inside `content`.

**The component ships no action buttons of its own.** Copy body, copy path, download, the preview/source switch and editing all carry host product semantics and copy; built in they could be neither trimmed nor restyled. Copy path is the exception — any file with a `source.path` needs it under every host, so it stays in the shell at the end of the breadcrumb. Everything else is rendered by the host in `slots.actions`, which receives a `FilePreviewActions` context: the current view mode, editing state, which capabilities are available, and the methods that change them. The state stays with the component.

Control the active tab with `activeKey` / `onActiveKeyChange`, set its initial value with `defaultActiveKey`, or use the ref handle:

```tsx
const previewRef = useRef<FilePreviewHandle>(null);
previewRef.current?.setActiveTab('dashboard');
```

## Where content comes from

`source` accepts three mutually exclusive inputs, checked in order:

- `content` — inline text, wrapped into a `File` named after `fileName`.
- `file` — a `File` or `Blob`, passed through.
- `url` — an accessible link; the component performs no authentication.

`fileName` is required and drives both format detection and the default tab title.

## States

Loading, failure and unsupported formats are not props: this component decides loading and failure, while whether a format can be previewed is the base component's call. All three can be replaced through `slots`:

- `slots.loadingFallback`
- `slots.errorFallback`
- `slots.unsupportedFallback` — handed to the base, which then owns the whole unsupported state, so the download entry it would otherwise offer no longer appears

The host supplies asynchronous `editing.save` and optional `editing.loadContent` capabilities. `loadContent` returns the full text; `undefined` abandons the edit, and rejection shows a read error. A failed save retains the draft and shows an error. `editing.onSave` only reports a successful save; `editing.onCancel` reports a discarded draft. Saving prevents duplicate submissions and tab changes until completion.

Execution capabilities and notifications are separate. Operation resolution triggers the corresponding `on…` callback; rejection does not. Missing methods hide or disable their controls, and notifications do not perform the operations. URI handling will be wired into the future FileViewer body.

## Props

| Property    | Type                                             | Default  | Description                                                    |
| ----------- | ------------------------------------------------ | -------- | -------------------------------------------------------------- |
| `tabs`      | `readonly [FilePreviewTab, ...FilePreviewTab[]]` | Required | At least one tab; the first is shown initially.                |

### Per-tab fields

Shared by both kinds:

| Property       | Type                         | Default   | Description                                                                  |
| -------------- | ---------------------------- | --------- | ---------------------------------------------------------------------------- |
| `key`          | `string`                     | Required  | Unique tab key.                                                              |
| `title`        | `ReactNode`                  | File name | What the tab row shows. Required for content tabs.                           |
| `icon`         | `ReactNode`                  | —         | Tab icon, supplied by the host; omit to hide.                                |
| `labels`       | `Partial<FilePreviewLabels>` | —         | Overrides the outer copy for this tab.                                       |
| `disabled`     | `boolean`                    | `false`   | Disables the tab.                                                            |
| `onOpenParent` | `(path: string) => void`     | —         | Called after the parent directory opens successfully; not called on failure. |
| `onCopyPath`   | `(path: string) => void`     | —         | Called after path copying succeeds.                                          |

`slots.titleExtra` renders after the path and copy button, before the action group. Use it for a marker beside the title — a permission tag, a status badge, a version label. The component does not interpret or style it: whatever you pass is what renders, and omitting it takes no space.

```tsx
{
  kind: 'file',
  key: 'file',
  source: { content, fileName: 'JC-17-A.md', path },
  slots: { titleExtra: <Tag>Can manage</Tag> },
}
```

File tabs add:

| Property         | Type                               | Default             | Description                                                                                                        |
| ---------------- | ---------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `source`         | `FilePreviewSource`                | Required            | The content and file name.                                                                                         |
| `operations`     | `FilePreviewOperations`            | —                   | Async `openParent(path)` and `download()` capabilities, each returning `Promise<void>`.                            |
| `resources`      | `readonly FileViewerResource[]`    | —                   | Companion resources, e.g. textures.                                                                                |
| `levels`         | `readonly FilePreviewLevel[]`      | —                   | Content levels with individual sources and optional resources/editing.                                             |
| `activeLevelKey` | `string`                           | First enabled level | Controlled content level.                                                                                          |
| `onLevelChange`  | `(key: string) => void`            | —                   | Selection intent; the host updates activeLevelKey when controlled.                                                 |
| `resolveImage`   | `(src, source) => Promise<string>` | —                   | Host resolution of Markdown images to accessible URLs.                                                             |
| `editing`        | `FilePreviewEditing`               | —                   | Editing capability; omit for read-only.                                                                            |
| `slots`          | `FilePreviewFileTabSlots`          | —                   | `actions` (node or renderer), `titleExtra`, `footer`, plus fallbacks for loading, failure and unsupported formats. |
| `onCopyContent`  | `(text: string) => void`           | —                   | Called after content copying succeeds.                                                                             |
| `onDownload`     | `() => void`                       | —                   | Called after the download operation succeeds; not called on failure.                                               |
| `onOpenUri`      | `(uri: string) => void`            | —                   | Called after a content resource opens successfully; not called on failure.                                         |

Content tabs add:

| Property  | Type        | Default  | Description                                                                           |
| --------- | ----------- | -------- | ------------------------------------------------------------------------------------- |
| `content` | `ReactNode` | Required | The tab body, filling everything below the tab row; the host lays it out and scrolls. |

A content tab has no content header row and does not use `slots` — that whole area belongs to the host, so there is no component-provided header or state to fill. The component places no wrapper around `content` either: a wrapper would only constrain the host's layout. Put any toolbar, title or status line inside `content` itself.

```tsx
import { FilePreview } from '@openviking/react/components/file-preview';
import '@openviking/react/components/file-preview/style.css';
```

Copying is handled by the component: the host renders the button and calls `actions.copyContent()` or `actions.copyPath()`, both resolving to whether it succeeded. `onCopyContent` / `onCopyPath` fire after a successful copy with the value already copied, and never on failure.

## Accessibility

The tab row uses `role="tablist"` with `role="tab"` buttons and reports `aria-selected`. Every icon-only control carries an accessible name through `aria-label` and a `title` tooltip. The path breadcrumb is enabled only when `operations.openParent` is supplied.

## Implementation scope

The component renders the shell and reports successful operations. Reading, saving, downloading and navigation are supplied as execution capabilities by the host; success notifications do not execute them.

`labels.showHiddenPath` overrides the collapsed-path menu button’s accessible name: “Show hidden path levels” in English and “显示隐藏的路径层级” in Chinese.
