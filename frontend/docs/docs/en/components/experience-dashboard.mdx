# ExperienceDashboard

Shows how Agent experiences are used: the directory view lists experience files, and the file view shows one experience's impact, source trajectories and test materials.

## When to use

- You need to review how experiences are used while browsing files, and jump to a specific experience or trajectory.
- You want to decide the data source, pagination and page layout yourself. The component only renders: it sends no requests and does not need `OpenVikingProvider`.
- When you use [FileBrowser](../modules/file-browser), the dashboard is built in and needs no separate setup.

## Import

```tsx
import { ExperienceDashboard } from '@openviking/react/components/experience-dashboard';
import '@openviking/react/components/experience-dashboard/style.css';
```

## Examples

### Basic usage

Switch between "Experience directory", "Experience file", "Host data" and "Error state"; the tabs support arrow keys and Home/End. "Host data" adds the impact metrics and test materials: the metrics show "—" without `effect`, and the Test tab appears only when `testMaterials` is provided.

```tsx file="../../_demos/experience-dashboard-basic.tsx" preview

```

The example uses fixed data: click an experience name to open its file view; clicking a trajectory name only shows the URI it receives.

### Rendering failure

When host content fails to render, the component shows the default fallback: an illustration, a message and a Retry display button. Pass `slots.errorFallback` to replace it.

### ExperienceDashboardState

| Property | Description                                                                                                | Type            | Default |
| -------- | ---------------------------------------------------------------------------------------------------------- | --------------- | ------- |
| loading  | Shows a skeleton in the section while it loads, with the loading state also stated as visually hidden text | `boolean`       | `false` |
| error    | Shows the error state and `error.message` when the section has no data, except appended trajectory pages   | `Error \| null` | -       |

## Notes

- `states` is set per section and usually shows only while that section has no data: `list` covers the experience list of the directory view, `effect` the three Impact metrics, `outcomes` the outcome distribution, `trajectories` the injection trajectories, `sources` the source trace and `tests` the test materials. Two exceptions apply. When appending a trajectory page fails, the loaded rows stay and the error with its retry appears below the list. When `effect` carries `loading` or `error`, that block becomes a skeleton or an error even if `data.effect` still has values, because the metrics fetch on their own and stale numbers must not sit beside a failed refresh. The errors and retries of different sections are independent.
- The pager appears when there is more than one page: `data.total` and `pageSize` decide the count, otherwise `hasMore` bounds it. The paging buttons are disabled while the matching section's `loading` is `true`.
- The Impact tab lists injection trajectories and offers "Scroll down to load more" when `hasMore` is `true`: scrolling within 240px of the bottom appends the next page, and the button does the same. It calls `onLoadMore`, or `onPageChange(page + 1)` when only the latter is given. Resting in place does not request repeatedly; after scrolling back up or leaving the trigger zone, returning to the end asks once more. That is what retries the same page after a failure, where the content does not grow. A loading label shows while `loadingMore` is `true`.
- Updating the test materials keeps the selected tab and time range. When `testMaterials` becomes `undefined`, a selected Test tab falls back to Impact.
- Copying uses `navigator.clipboard.writeText`, which is available only over HTTPS or on localhost; when it is unavailable or the browser rejects it, the button shows "Copy failed".
- The component is `100%` high and scrolls its content internally, so give its parent a height.
- Types are exported from `@openviking/react/components/experience-dashboard`, including `ExperienceDashboardTab` and `ExperienceOutcome`; the package root exports only the component and `ExperienceDashboardProps`.
