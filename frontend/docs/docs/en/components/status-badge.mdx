# StatusBadge

A compact label for a resource or operation state. This example exercises the public package export, scoped styles, interactive demos, and the documentation build.

## Props

| Property    | Type                                 | Default      | Description                                                                |
| ----------- | ------------------------------------ | ------------ | -------------------------------------------------------------------------- |
| `status`    | `'ready' \| 'processing' \| 'error'` | Required     | Selects the indicator color and default text.                              |
| `children`  | `ReactNode`                          | Status label | Replaces the default English label.                                        |
| `className` | `string`                             | —            | Adds a class to the outer span.                                            |
| Other props | `HTMLAttributes<HTMLSpanElement>`    | —            | Standard span attributes, including `aria-*`, `title`, and event handlers. |

```tsx
import { StatusBadge, type StatusBadgeStatus } from '@openviking/react';
import '@openviking/react/style.css';
```

## Accessibility

Status is communicated through visible text, so color is not the only cue. The badge itself is non-interactive. When updates need to be announced, place it inside an application-owned live region, as in the interactive example.

## Theme tokens

| CSS variable                | Default   | Purpose                                       |
| --------------------------- | --------- | --------------------------------------------- |
| `--ov-ui-status-ready`      | `#187347` | Ready state text, border, and indicator.      |
| `--ov-ui-status-processing` | `#2563c5` | Processing state text, border, and indicator. |
| `--ov-ui-status-error`      | `#c43838` | Error state text, border, and indicator.      |
| `--ov-ui-radius`            | `6px`     | Badge corner radius.                          |

## Implementation scope

`StatusBadge` displays the state supplied by its caller. Applications own requests, retries, permissions, and transitions between states.
