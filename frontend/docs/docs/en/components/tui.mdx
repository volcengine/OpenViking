# Tui

Optional `locale: 'zh-CN' | 'en-US'` overrides the nearest module or Provider; without either, copy defaults to `en-US`. Existing `labels` override individual fields. Hosts provide business content.

A command console body: current records, results and input, including suggestions and help. The host supplies the command catalogue and owns requests, permissions, execution and sessions. The component reports submission intent through `onSubmit` and successful copying through `onCopy`.

The view renders seven result variants, the empty state, and a controlled input with completion and parameter hints. It contains no built-in business command catalogue.

## Basic usage

```tsx file="../../_demos/tui-basic.tsx" preview

```

The demo keeps the records and input in its own state: sending appends a pending record, then resolves it using the command’s result shape. All demo commands use fixed, simulated data; no command reaches a service. Try `ov compile --compile-name demo-wiki`, `ov task list`, `ov session get session_demo` or `ov help` to compare write, table, status and help results.

The composer is a full-width, borderless editing area with a top separator, at least 80px for editing, and a 40px shortcut legend below. Focusing the editor leaves the separator unchanged. Text grows up to three lines, then scrolls. The legend shows `/` for all commands, `↑` to recall commands from the current records, and `↵` to send; Shift+Enter inserts a newline. There is no separate Send button.

Typing `o` previews `v` in gray; Tab accepts the prefix, and Space completes it to `ov `. Press Tab after `ov ` to open all commands, then type to filter and preview the remaining text; Tab accepts the inline hint or selected command. Ordinary typing shows inline hints; `/` or an explicit Tab opens the list. Completion is derived from the host’s `inputText`. Plain Tab always keeps focus in the composer; without a completion, while entering arguments, or while editing in the middle, it leaves the value and page position unchanged. Shift+Tab moves focus out. Ghost text is never submitted.

Typing `/`, or pressing Tab after `ov `, opens the list with no selected command. Filtering or reopening clears selection. Slash discovery also supports multiword names and aliases, such as `/session g`; it stays available until arguments begin. Down selects the first item; Up selects the last. Hovering or navigating to a command reveals its examples and parameter table. With no keyword and no selected candidate, Tab leaves the input unchanged. The panels stack when horizontal space is limited. Escape and outside clicks dismiss them; browsers without native Popover use an inline panel.

After accepting a command, its host-provided `inputText` prefix is rendered with a muted CLI prefix and an emphasized command name in the text color, with light inline hints for positional parameters (or required flags when there are no positional parameters). The hints disappear when arguments are typed and never enter `value` or submitted text. The full detail panel is only shown while the command list is open.

HTTP, HTTPS and Viking URI text in the editor, command records and results becomes native links using the host theme primary color. Activating a link does not submit a command.

The editor and command records share a muted CLI prefix, an emphasized command name in the text color, and resource URIs in the link color. Links are underlined on hover. Records use the same `inputText` prefix and preserve their arguments. Timestamps appear on a separate line, aligned right. Copying and history recall use the same prefix; unknown commands retain their original text.

The shared demo follows the documentation language via `useLang()`, supplying localized command descriptors, groups and records. `locale="zh-CN"` selects Chinese interface copy; `locale` is optional. `labels` overrides individual interface strings. Hosts localize their own command and result content.

## Empty state and quick commands

```tsx file="../../_demos/tui-empty.tsx" preview

```

This example starts with no records and configures `{ name, value }` shortcuts through `quickCommands`. Each `name` resolves the summary or description from `commands` in order; unknown names are skipped and repeats keep their first entry. Selection fills `value` verbatim and focuses without adding an `ov` prefix or submitting. Preset values follow the Volcengine host: import the official README, add the llm-wiki Skill, save a sample memory and search. URLs and sample text follow the site language. The compile shortcut fills only `ov compile `, matching that host; enter `--compile-name <name>` before submitting. Users press Enter to execute. The first submission replaces the welcome view with a simulated result.

The demo catalogue follows saved compilation configurations: `ov compile create --compile-name <name> --from <source-uri> --to <target-uri> --skill <skill-uri>` saves without starting a compilation; then `ov compile --compile-name <name>` runs it. Sources and Skills use directory URIs; demo paths are simulated data. The demo host owns this workflow, and Tui itself never executes commands.

Hovering a quick command nudges its arrow backward, forward and back into place once. The arrow stays still when the system requests reduced motion.

Passing neither `emptyState` nor `quickCommands` shows no empty-state content at all. Pass `emptyState` to replace the whole built-in empty state.

## Component boundary

Tui contains the current command records and results, the empty state, and command input with its suggestions and help. Session creation, history panels, view and user switching, surrounding toolbars are composed separately by the host through independent components.

The host handles session and history actions, then updates `records` and `value`. Historical results use the same records view; Tui has no history list, history-preview state, or surrounding toolbar/action slots.

The host supplies `commands` and optional `commandGroups`; Tui handles filtering, highlighting, keyboard selection, filling and parameter help. Accepting a completion updates `value` through `onValueChange`. Explicit submission calls `onSubmit`; the host executes the operation and supplies status and results through `records`.

Names, aliases, groups, descriptions, parameters, options and examples are descriptor data. New commands using the existing descriptor and result variants require only host data changes. Hosts may load or update that data from their own services; Tui does not fetch it. The demo catalogue lives in `docs/docs/_demos/tui-commands/`.

## Props

The public props are published as types from the same subpath. Read them from the source of truth:

```tsx
import type {
  TuiCommandDefinition,
  TuiCommandGroup,
  TuiLabels,
  TuiProps,
  TuiRecord,
  TuiRecordContent,
  TuiSearchResultItem,
} from '@openviking/react/components/tui';
```

The table describes the implemented behaviour.

| Property      | Type                            | Default           | Description                                                                                                                                                                                                          |
| ------------- | ------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| records       | readonly TuiRecord[]            | Required          | Currently displayed execution records in submission order; the host updates them on session or history changes.                                                                                                      |
| value         | string                          | Required          | Controlled input value.                                                                                                                                                                                              |
| disabled      | boolean                         | false             | Disables command input and submission; the message comes from `labels.unavailableMessage`.                                                                                                                           |
| emptyState    | ReactNode                       | —                 | Empty-state node shown without records, replacing the built-in empty state; `null` shows nothing.                                                                                                                    |
| quickCommands | readonly TuiQuickCommand[]      | `[]`              | Shortcuts `{ name, value }`; names resolve copy from commands, unknown names are skipped and repeated names keep their first entry. Selection fills value verbatim and focuses without adding a prefix or executing. |
| `locale`      | `'zh-CN' \| 'en-US'`            | Inherited / en-US | Built-in Chinese and English copy.                                                                                                                                                                                   |
| commands      | readonly TuiCommandDefinition[] | `[]`              | Host command catalogue for completion, help and pending skeletons.                                                                                                                                                   |
| commandGroups | readonly TuiCommandGroup[]      | `[]`              | Host group labels and ordering; undeclared groups are appended.                                                                                                                                                      |
| labels        | TuiLabels                       | —                 | Interface copy and guidance.                                                                                                                                                                                         |
| onValueChange | (value: string) => void         | —                 | Reports input changes, including accepted commands and examples; inline hints never change the value or submit. Omission makes the input read-only and disables submission and help insertion.                       |
| onSubmit      | (command: string) => void       | —                 | Reports explicit submission intent. The host executes it; omission disables submission.                                                                                                                              |
| onOpenUri     | (uri: string) => void           | —                 | Receives the URI on link activation; the host opens the resource.                                                                                                                                                    |
| onCopy        | (text: string) => void          | —                 | Called after copying succeeds, with the copied text; not called on failure. Omission does not affect copying.                                                                                                        |

Record updates follow the output only while the reader is near the bottom. Scrolling up preserves the reading position; an explicit submission resumes following. Resource tables retain each entry’s title, native URI target and metadata, including entries without detail rows.

Structured resource links accept `viking://`, `https://` and `http://`; unsupported targets render as plain text. Sentence punctuation is excluded from prose URI links, including search summaries/excerpts, descriptions, metadata and write-result messages. Resource identities and raw structured values use literal matching. Command, editor and code URI tokens preserve filename punctuation such as commas, semicolons and parentheses; whitespace and quoting delimiters bound literal tokens.

`onSubmit` reports the submitted text and does not await a result. The host owns sending, permissions and execution, and updates pending, successful or failed records. A pending record does not block later submissions.

`emptyState` is the entry for a fully custom empty view: a node replaces the built-in empty state, and `null` shows no empty state. When omitted, the built-in empty state renders the heading, description and quick command list from `quickCommands`; without any resolved command nothing is shown.

### Command descriptors

`TuiCommandDefinition` includes `name`, `description`, `usage`, and optional `inputText`, `summary`, `aliases`, `group`, `params`, `options`, `examples` and `skeleton`. Parameter entries use `label`; options use `token`; both support `description`, `required` and `defaultValue`. `inputText` is the prefix filled when a command is accepted, defaulting to `name`; the demo supplies `ov read` and other CLI prefixes. `required` defaults to `false`, and an omitted `defaultValue` displays an em dash. Group entries contain `key` and `label`. Examples accept a string or `{ value, label? }`; selecting one fills `value` without submitting. This also lets the host display a CLI-prefixed example while filling a slash command.

Omitting `commands` leaves text input and submission available, without command suggestions or parameter help. The component does not translate host descriptors or validate command permissions.

### Result content

Every result has a command heading and an accessible success, error or loading icon. The heading uses the matched host descriptor’s `inputText` without arguments; duplicate command titles in the body are hidden. Write results use a separate shaded row for each line; status results use shaded key/value rows; resource previews have their own content surface. JSON and Markdown code fences share copyable code blocks. Markdown ordered lists retain visible native numbering, including a non-default start value. Execution success is independent of a returned task’s `pending` status.

Code blocks use an icon-only copy button. Hover or keyboard focus shows “Copy”; after success the icon briefly changes to a check and the tooltip shows “Copied”. Customize these strings through `labels.copy` and `labels.copied`. A failed copy neither shows success feedback nor calls `onCopy`.

Empty result messages use `labels.noResult`; command-help headings and hints use `labels.availableCommands` and `labels.helpHint`.

`TuiRecordContent` contains one general text result and six structured results:

| variant          | Data            | Description                               |
| ---------------- | --------------- | ----------------------------------------- |
| text             | text, format?   | General output; format defaults to plain. |
| search-list      | items, summary? | Search results and summary.               |
| resource-preview | title, content  | A resource body preview.                  |
| resource-tree    | items, title?   | Resource entries and their details.       |
| status           | rows, title?    | Key/value status rows.                    |
| write-result     | lines, title?   | Write operation results.                  |
| command-help     | sections        | Available commands grouped by section.    |

For `text`, `format` accepts `plain` or `markdown` and defaults to `plain`. Format JSON as a string and display it through `text`. Failures use `TuiRecord.status: 'error'`, with the error body in a text result; there is no separate error content variant.

Each variant has a dedicated view: plain or Markdown text (JSON is indented without changing numeric tokens or other values), search rows with optional score details, resource preview, an aligned resource table with paging, status rows, write lines and grouped command help. Resource URI links in the input, command bubbles, Markdown and structured result strings share `onOpenUri`. Custom React nodes own their internal links. Clicking an input URI does not change or submit the command; Shift+Tab can focus links for Enter activation. Converting CLI output into these variants stays with the host.

### Copy and guidance

General interface copy follows `locale`, with individual overrides through `labels`. Command names, descriptions, group labels and parameter help come from host descriptors.

| Property                  | Type   | Description                                                                                 |
| ------------------------- | ------ | ------------------------------------------------------------------------------------------- |
| labels.unavailableMessage | string | Message shown when `disabled` is `true`; changing this copy does not disable the component. |
| labels.pending            | string | Text for the pending state.                                                                 |
| labels.emptyTitle         | string | Heading of the built-in empty state.                                                        |
| labels.emptyDescription   | string | Description of the built-in empty state.                                                    |
| labels.quickStart         | string | Label above the quick command list.                                                         |
| labels.allCommands        | string | Label for the `/` shortcut.                                                                 |
| labels.historyCommands    | string | Label for the `↑` shortcut, which recalls commands from the current records.                |
| labels.send               | string | Label for the `↵` shortcut.                                                                 |

`disabled` defaults to `false`. To disable command input and submission, set it to `true`. `labels.unavailableMessage` customizes the resulting message.

Parameter headings, column labels, required values and pagination copy can also be overridden through `labels.parameters`, `examples`, `noParameters`, `parameter`, `required`, `description`, `defaultValue`, `yes`, `no`, `loadMore` and `resource` (the resource-table identity column).

### Search result details

`TuiSearchResultItem` supports these optional display fields:

| Property     | Type      | Description                                                                          |
| ------------ | --------- | ------------------------------------------------------------------------------------ |
| levelLabel   | string    | Content level label next to the title.                                               |
| typeLabel    | string    | Result type label next to the score.                                                 |
| scoreLabel   | string    | Host-formatted score.                                                                |
| scoreDetails | ReactNode | Host-rendered details shown on score hover or keyboard focus; requires `scoreLabel`. |

### Record times

The host supplies `createdAtMs`, a Unix timestamp in milliseconds. The component displays “Just now” for less than one minute, whole minutes below one hour, and whole hours below 24 hours. At 24 hours or more it displays `YYYY-MM-DD HH:mm` in the browser’s local time zone. Future timestamps display “Just now”.

| Field       | Type   | Default | Behavior                                                                                                       |
| ----------- | ------ | ------- | -------------------------------------------------------------------------------------------------------------- |
| createdAtMs | number | —       | Preferred timestamp for component-side formatting. Non-finite or out-of-range values fall back to `createdAt`. |
| createdAt   | string | —       | Optional display text used without a valid timestamp; strings such as `10:24` are never parsed as dates.       |

The initial server render and hydration use `createdAt`, or omit the time if it is absent. After hydration, the component formats the timestamp using the client clock. It recalculates on rendering without a periodic timer. `labels.justNow`, `labels.formatMinutesAgo(minutes)` and `labels.formatHoursAgo(hours)` override the time copy; defaults follow `locale`. Both demos supply timestamps, and completed results preserve the original submission time.

### Loading records

For a pending `TuiRecord`, the component matches `command` against the supplied catalogue, including aliases, and uses the descriptor’s optional `skeleton`. Missing or unrecognized descriptors use the generic skeleton. `content` can be omitted while pending.

Import the component and its scoped stylesheet:

```tsx
import { Tui } from '@openviking/react/components/tui';
import '@openviking/react/components/tui/style.css';
```

## Implementation scope

The component renders supplied data and handles local input interaction. Requests, response adaptation, execution, persistence, permissions and network connections belong to the host.
