# VikingBot

Optional `locale: 'zh-CN' | 'en-US'` overrides the nearest module or Provider; without either, copy defaults to `en-US`. Existing `labels` override individual fields. Hosts provide business content.

The conversation view: message list, composer and the pending-interaction area. The open-source and managed-agent hosts speak different protocols, so the component takes an already normalized message model and lets each host replace the regions it renders differently.

The welcome state and composer follow the Volcengine layout; the message list and composer reuse Ark Design. Props supply data and callbacks report user actions; the host owns sessions, streaming requests and uploads. Customize the welcome copy through `labels.welcomeTitle` and `labels.welcomeDescription`, or replace the entire welcome area with `emptyState`.

Message rendering follows Volcengine `release/openviking/2026-11-12`: ordinary answers use `MDRenderer` directly with 13px / 22px text, 8px paragraph spacing and no long-answer collapse. The final answer in each turn shows its timestamp on hover; resource URIs in Markdown, inline code and text code blocks invoke `onOpenUri`. `ActivityTimeline` owns status, elapsed time and completion collapse, with separate input/output details. `locale` controls built-in copy and timestamp formatting.

The `tool` and `tool_result` parts accept `results: readonly VikingBotToolResultLink[]`. Each item has a `uri`, optional `label` and `score`, rendered as a file/resource/similarity card. The host adapts its search response; the view does not inspect tool names or API protocols. Cards invoke `onOpenUri` and are disabled without that callback. Omit `results` or pass an empty array to show the raw output.

## How the two hosts connect

| Difference          | Handling                                                                |
| ------------------- | ----------------------------------------------------------------------- |
| Message shape       | Normalized to `parts[]`, with roles user, assistant, system and tool    |
| Activity collapsing | Parts carry `groupId`; `startedAt` and `durationMs` feed the display    |
| Text format         | `text.format` separates `plain` from `markdown`                         |
| Tool calls          | `server`, `endpoint` and `durationMs` cover MCP semantics               |
| Message actions     | `message.action` declares one; `onMessageAction` reports it             |
| Streaming           | `{ parts, insertIndex, iteration }`; append-at-end passes the count     |
| Human confirmation  | The `components/viking-bot/interaction` subpath, four forms plus custom |
| Render base         | `messageList`, `composer`, `interaction` and `children` replace regions |

Protocol adaptation stays in each host repository; the component imports no backend event type.

## Session and input extensions

`sessions` supplies items, the current ID, loading/error state and callbacks for creation, selection and pagination. Dates use host-provided ISO timestamps. `headerActions` accepts optional controls such as a More menu. The component neither loads nor persists sessions. Use `VikingBotSessionActions` independently in a shared host header. The header shows a copyable current session ID. Supply both `sessions.currentUri` and `onOpenUri` to enable locating it. The disabled reason appears by the composer, or in the conversation when there is no built-in composer.

The host supplies `quickInputs` as `{ id, label, prompt, icon? }`; no business commands are built in. They appear at the bottom of the welcome state or above Sender when messages exist. Selecting one fills and focuses the draft without sending. Another shortcut replaces the previously inserted prompt, preserving custom text before and after it, including identical text typed separately. Editing inside the inserted prompt makes it custom text; the next shortcut appends to it. An external draft replacement that cannot be mapped unambiguously also releases ownership. Override this behavior with `onQuickInputSelect`.

`references` supplies visible FileTree `rows`, controlled `selected`, `onChange`, and optional `onQueryChange`, `onExpand`, `isLoading` and `error`. The toolbar and typed `@` use the same picker. Selections are deduplicated by URI and reported separately in `VikingBotDraft.references`, rather than flattened into text. Omitting the configuration hides the entry point. The host handles queries, expansion and permissions, and resets references and attachments when identity or session changes. `onFilesAdded` enables `+`; it reports files for the host to upload.

Input extensions also work with standalone `VikingBotComposer`. Customize welcome, session, reference, loading and removal text through `labels`.

### File and directory references

Selected references are separate from uploaded attachments. Each tag shows a file-type or directory icon and the full URI, with ellipsis and a full-path title when space is limited. The first five tags remain visible; `+N` reveals the rest on hover, focus, or click. Each tag can be removed independently, and `onOpenUri` enables opening the selected file or directory. Standalone `VikingBotComposer` also accepts `onOpenUri`. Sending keeps references in `VikingBotDraft.references` without rewriting the draft text.

This example uses fixed public data and never accesses real resources; open and send actions only display their callback values.

## Pending interaction


An interaction is host state, not a backend pause: the host derives the question from its own stream and clears it once the answer is sent. `choice`, `text`, `schedule` and `repair` render built in; use `custom` when a question needs a tree picker or an uploader.

### VikingBotInteractionProps

| Prop         | Type                                | Default           | Description                                      |
| ------------ | ----------------------------------- | ----------------- | ------------------------------------------------ |
| `locale`     | `'zh-CN' \| 'en-US'`                | Inherited / en-US | Built-in Chinese and English copy.               |
| `request`    | `VikingBotInteractionRequest`       | required          | The current question.                            |
| `className`  | `string`                            | —                 | Class name applied to the root element.          |
| `index`      | `number`                            | `0`               | Current step index, starting at 0.               |
| `total`      | `number`                            | `1`               | Total steps; progress shows when greater than 1. |
| `disabled`   | `boolean`                           | —                 | Whether the form is disabled.                    |
| `submitting` | `boolean`                           | —                 | Whether a submission is in flight.               |
| `error`      | `ReactNode`                         | —                 | Why the last submission failed.                  |
| `onSubmit`   | `(answer) => void \| Promise<void>` | —                 | Reports an answer.                               |
| `onCancel`   | `() => void`                        | —                 | Abandons the interaction; omission hides cancel. |
| `labels`     | `VikingBotInteractionLabels`        | locale            | Replaceable copy.                                |

## Development entry

The standalone style entry is `@openviking/react/components/viking-bot/style.css`, which already includes the theme baseline and can be consumed on its own.

Interaction `labels.answer` sets the text answer’s accessible name; `labels.other` sets the default custom-input prompt. A request’s `allowCustomInput.placeholder` takes precedence. Embedded interactions inherit VikingBot’s `locale` unless `interaction.locale` overrides it.
