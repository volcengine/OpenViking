# VikingBot

Shows the conversation messages your app provides, with a composer and a pending-interaction area: sending, stopping and opening resources are reported through callbacks, and the component sends no requests.

## When to use

- You need to show an AI conversation in your own page, including replies, reasoning and tool-call activity, a composer and a session history entry.
- You want to decide how the conversation service, streaming requests and file uploads are connected. The component only renders and does not need `OpenVikingProvider`.
- When you use [Console](../modules/console), the conversation view is built in and needs no separate setup.

## Import

```tsx
import { VikingBot } from '@openviking/react/components/viking-bot';
import '@openviking/react/components/viking-bot/style.css';
```

The style entry already contains the theme baseline and the `@ark-design/ui` styles the view uses, so it can be imported on its own.

The message list, composer and pending-interaction area are rendered by `@ark-design/ui`. It is an optional peer dependency that is not installed with `@openviking/react`, so install version `0.0.0-beta.7` or later in your app:

```bash
npm install @ark-design/ui@0.0.0-beta.7
```

If you only need the pending-interaction area, import `VikingBotInteraction` from the `interaction` subpath; the style entry is the same:

```tsx
import { VikingBotInteraction } from '@openviking/react/components/viking-bot/interaction';
import '@openviking/react/components/viking-bot/style.css';
```

## Examples

### Basic usage

The example has a reasoning and tool-call timeline, search result cards, Markdown replies, a message action button and a system notice; expand a tool call to see the search results, and click a `viking://` address in a reply or a result card to show the opened URI below the example.

```tsx file="../../_demos/viking-bot-basic.tsx" preview

```

The example uses fixed data: sending only clears the draft, and selected files are not uploaded.

### User messages

User messages sit on the right with attachments outside the bubble, and a message with only attachments gets no empty bubble; click an attachment or the copy button, and the value the callback receives appears below the example.

```tsx file="../../_demos/viking-bot-user-messages.tsx" preview

```

### File and directory references

Reference tags in the composer show the full URI, so files with the same name stay distinguishable; the first 5 are shown and the rest collapse into `+N`, and clicking a tag or sending shows the callback value below the example.

```tsx file="../../_demos/viking-bot-references.tsx" preview

```

### Pending interaction

The example shows the four built-in forms in turn, `choice`, `text`, `schedule` and `repair`, with the submitted answer at the bottom; the first form also demonstrates step progress, the "Other" input and the cancel button.

```tsx file="../../_demos/viking-bot-interaction.tsx" preview

```

### Rendering failure

When host content fails to render, the component shows the default fallback: an illustration, a message and a Retry display button. Pass `slots.errorFallback` to replace it.


## Notes

- The component sends no requests: loading and saving sessions, streaming connections, deciding when a reply ends and uploading files are up to your app. Your app converts its own messages and stream events into `VikingBotMessage` and `VikingBotStreamingState`.
- The root element is 100% as tall as its parent and the message area scrolls inside it, so give the parent a height.
- Assistant replies are rendered as Markdown, and text with `format: 'plain'` is shown literally. `viking://` addresses in the text, in inline code and in `bash`, `shell`, `sh`, `text` and `txt` code blocks become links that call `onOpenUri`.
- Markdown links in assistant replies keep only the `http`, `https`, `mailto` and `tel` schemes, and links with any other scheme render as plain text; `http` and `https` links open in a new tab.
- User messages are also rendered as Markdown, but `viking://` addresses in them are not turned into links.
- Adjacent reasoning and tool-call parts with the same `groupId` form one activity block: its title bar shows the status and elapsed time, it is expanded by default and can be collapsed, and each tool call expands to show its input and output. Parts without a `groupId` each form their own block.
- A quick input fills an empty draft directly and is appended on a new line otherwise; selecting another one replaces the previously inserted text and keeps what the user typed around it.
- If the user edits the inserted text, or your app replaces the whole draft in a way that cannot be mapped back, that text counts as the user's own and the next quick input is appended.
- Typing `@` in the input and clicking the `@` button open the same picker; a chosen reference is added to `references.selected` and the typed `@` query is removed. References are deduplicated by URI.
- Reference tags show an icon and the full URI, truncated with the full path in the title when space is short; the first 5 are shown and the rest collapse into `+N`, which expands on hover, focus or click.
- References stay out of the draft text and are reported only in `VikingBotDraft.references`. When the account or session changes, reset both `references.selected` and `attachments`.
- A pending interaction is state of your app, not a backend pause: derive the question from your own stream and clear `interaction` once the answer is sent. The component only renders the form and reports the answer through `onSubmit`.
- `@ark-design/ui` is loaded when the message list, composer or interaction area first renders, and an empty container shows while it loads. Importing VikingBot does not load it, so the module can be imported in environments without `window`.
- `VikingBotComposer`, `VikingBotMessageList` and `VikingBotSessionActions` can be used on their own, for example `VikingBotSessionActions` in your own header.
- `groupMessages`, `groupByActivity` and `messageText` follow the same rules as the built-in list, so you can use them when you replace `messageList`.
- `DEFAULT_LABELS` and `DEFAULT_INTERACTION_LABELS` are the built-in English text and list every key of the matching `labels`.
- Types are exported from `@openviking/react/components/viking-bot`; the package root exports only `VikingBot` and `VikingBotProps`. `VikingBotInputFeatures` holds the `quickInputs`, `onQuickInputSelect` and `references` that `VikingBot` and `VikingBotComposer` share.
