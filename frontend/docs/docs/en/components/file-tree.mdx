# FileTree

Optional `locale: 'zh-CN' | 'en-US'` overrides the nearest module or Provider; without either, copy defaults to `en-US`. Existing `labels` override individual fields. Hosts provide business content.

A flattened file tree. The host owns the tree state and passes the visible rows in order; the component renders them and reports successful operations.

The component renders the host-flattened row list and handles selection, expansion, paging and keyboard interaction. Search and refresh controls are visible by default and can be hidden independently; the host supplies search UI, data requests and import flows.

## Basic usage

Rows come from `rows`; expansion is controlled by the consumer. The example keeps its own expanded set, flattens the tree into `FileTreeRow[]` and renders it, showing async loading, paging, empty rows and the built-in directory copy in action.


Search only displays the `onSearch` event and opens no dialog. Choose a refresh result and click refresh to run the success or failure case. Pending refresh shows loading; failure restores the button without firing `onRefresh`, and choosing success allows a retry. Toggle "Host-controlled loading" to try the controlled pending state. All data is simulated offline.

The example also demonstrates these host responsibilities:

- **Async loading**: expanding a directory shows a `Loading…` row for 400 ms before the children appear — `FileTreeLoadingRow`.
- **Paging**: each page loads three children; while more remain, `Load more` appears and appends one page per click — `FileTreeLoadMoreRow`. `archive` holds nine files and loads in three pages.
- **Row-end icons**: the mutually exclusive marks rendered by `renderDashboard`. `memories/experiences` shows the Agent experience board icon. `project-wiki` is a Wiki root: its leading folder is replaced by a book icon and the row ends with a green board icon. `archive` is a Wiki root too but has pending conflicts, so its icon turns orange and gains an exclamation mark.

Names like `memories`, `peers` and `privacy` are followed by their built-in description.

The example mounts `<FileTree />` directly, keeping only the tree data and the expansion and paging state the host owns.

## Search and refresh

`search` and `refresh` both default to `true`; pass `false` to hide either. A missing `operations` method disables its control. `slots.toolbar` remains above the built-in controls.

The default search text matches the console: `Search files ⌘+K...`. Override it with `labels.search`. The component invokes host operations; the host supplies search UI, keyboard shortcuts and result handling.

Refresh shows a hint on hover or keyboard focus. Top-level `loading`, `refresh.loading`, and the pending refresh Promise are combined: any active state spins and disables the button and prevents repeated execution. `labels.refresh` overrides both the hint and accessible name.

```tsx
<FileTree
  rows={rows}
  loading={isRefreshing}
  operations={{ search: openSearch, refresh: reloadTree }}
  labels={{
    search: 'Search documents...',
    refresh: 'Refresh context directory',
  }}
  onSearch={() => notifySearch()}
  onRefresh={() => notifyRefresh()}
/>
```

## How rows work

The tree never inspects parent/child relationships. The host flattens its own state into an ordered list:

- `entry` — a directory or file.
- `loading` — a children area that is still loading.
- `load-more` — a children page the host can fetch next.
- `error` — a children area that failed.
- `empty` — an expanded directory with no children.

Emit only the ones your data source needs. A host that returns all children at once never emits `load-more`.

Rows size to their content rather than being squeezed into the container width: names render in full and the container scrolls sideways. Deep indentation gets its space the same way, so deep nodes never squeeze each other. The description is capped at 200px and truncates as needed — it is supplementary, and one long description would drag a row hundreds of pixels wide, making horizontal scrolling harder rather than easier.

The name is the only way to tell nodes apart, so it never truncates; a host that wants a tighter column narrows the container rather than asking the component to clip names.

## Slots and host content

- `slots.toolbar` — custom content above built-in controls, such as connecting agents or importing resources.
- `slots.spinner` — replaces the spinner shown while a directory loads its children, rendered at 12 × 12. Omitted uses the built-in `FileTreeSpinner` (a CSS ring with no icon asset behind it).
- `renderDashboard` — the row-end indicator, for example a dashboard entry.
- `renderRowTooltip` — hover content; the component handles the delay and positioning. When omitted the component renders a built-in tooltip from the row `uri` (description, trigger copy, path).

## Directory copy

The component derives a directory's meaning from the structure of its `uri` and ships built-in description and trigger copy. A host gets descriptions without passing anything; override copy key by key through `labels.info`.

Matching looks only at the path shape, never the node type. Both `viking://user/{id}/memories` and `viking://user/{id}/memories/` match `memories`; `viking://resources` matches `sharedResources`, while `viking://resources/docs` does not — built-in copy covers fixed levels only, and deeper nodes are the host's call.

| Group            | Keys                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| User scope       | `userRoot`, `memories`, `peers`, `privacy`, `userResources`, `sessions`, `skills`                          |
| Long-term memory | `profile`, `preferences`, `entities`, `events`, `identity`, `soul`, `cases`, `trajectories`, `experiences` |
| Shared and roots | `sharedResources`, `agentRoot`, `memoryRoot`, `resourceRoot`, `sessionRoot`, `systemRoot`                  |

The nine long-term-memory keys describe themselves in the tooltip only: the directory names already say what they are, and an inline line would crowd out siblings.

**Copy precedence**: when a row carries `description`, the host's value wins and the built-in one is not used; the built-in copy applies only when it is absent, so a host can always take full control.

```tsx
<FileTree
  locale="en-US"
  rows={rows}
  labels={{
    info: {
      description: { userRoot: 'Current user' },
      triggerBehavior: {
        memories: 'Distilled whenever a session is committed',
      },
      field: {
        description: 'Description',
        triggerBehavior: 'Trigger',
        path: 'Path',
      },
    },
  }}
/>
```

Both `labels.info.description` and `triggerBehavior` are `Partial<Record<FileTreeInfoKey, string>>`, so only the keys you change need writing. An empty string hides that key.

The matching rules and copy are also exported as plain functions from the component subpath, so a host can assemble its own view on the same rules:

```ts
import {
  resolveFileTreeInfoKey,
  showsInlineDescription,
  resolveInfoCopy,
} from '@openviking/react/components/file-tree';

resolveFileTreeInfoKey('viking://user/alice/memories/profile.md'); // 'profile'
showsInlineDescription('profile'); // false — tooltip only
resolveInfoCopy('memories', { description: { memories: 'Custom' } });
```

## One-off effects

Highlighting is a page-level effect, not a tree prop. Three options are available and can be combined:

1. `data-file-tree-row-id` on every row element, exported as `FILE_TREE_ROW_ATTRIBUTE`.
2. `getRowAttributes(row)` for per-row classes and attributes.
3. The `ref` handle: `getRowElement(id)` and `scrollToRow(id, options)`.

```tsx
const treeRef = useRef<FileTreeHandle>(null);
treeRef.current?.scrollToRow('resources', { block: 'center' });
```

`operations` provides `select(row)`, `toggleExpand(row)`, `loadMore(row)`, `retry(row)` and `openRetentionSettings(uri)`. Each returns `Promise<void>`: resolution means success, rejection means failure. The existing `on…` callbacks are optional success notifications and no longer perform these operations. Repeated requests for the same pending operation are ignored.

## Accessibility

The tree uses `role="tree"` with `role="treeitem"` rows and reports `aria-level`, `aria-selected` and `aria-expanded`. Arrow keys move between rows, Right/Left expand and collapse, Enter and Space select. Status is carried by visible text, not colour alone.

## Implementation scope

The host supplies asynchronous execution capabilities through `operations`; the component calls the matching success notification only after the operation resolves. Rejection does not trigger a success notification. Omitting a method disables that operation; omitting a notification does not prevent execution. Directory loading, pagination, search, permissions and navigation remain host-owned.

## Row permission status

The view renders host-provided state and makes no authorization requests. `FileBrowser` maps native listing results to these row properties:

| `FileTreeEntryRow` property | Default | Behavior                                                                                    |
| --------------------------- | ------- | ------------------------------------------------------------------------------------------- |
| `disabled`                  | `false` | Prevent selection and expansion                                                             |
| `selectable`                | `true`  | `false` prevents pointer and keyboard selection while allowing directory expansion          |
| `access`                    | —       | Display a `read-only`, `denied` or `container` badge; the properties above control behavior |

Override badge strings with `labels.readOnly`, `labels.noAccess` and `labels.traverseOnly`; defaults follow the locale.
