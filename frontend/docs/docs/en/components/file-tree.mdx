# FileTree

FileTree renders the rows your app provides as an expandable, keyboard-operable file tree.

## When to use

- Your app already loads and manages the tree data, for example with paging, lazy loading or permission trimming: flatten the tree state into ordered rows, run expand, select and load-more yourself, and the component reports each operation that succeeds.
- You want to decide the search UI, import entry points and row-end actions yourself: the component only renders and calls back. It sends no requests and does not need `OpenVikingProvider`.
- When you use [FileBrowser](../modules/file-browser), the file tree is built in and needs no separate setup.

## Import

```tsx
import { FileTree } from '@openviking/react/components/file-tree';
import '@openviking/react/components/file-tree/style.css';
```

Your app keeps the expanded set and the paging state and passes the flattened tree as `FileTreeRow[]`. ### FileTreeRow

Every item in `rows` is one of the five types below, told apart by `kind`.

| Value         | Description                                                                                                                        | Type                  |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| `'entry'`     | A directory or a file, one row per node                                                                                            | `FileTreeEntryRow`    |
| `'loading'`   | The children of a directory are loading; sits under the parent, and you can skip it and use `busy` on the entry row instead        | `FileTreeLoadingRow`  |

## Notes

### Exports

- Types and helper functions are exported from `@openviking/react/components/file-tree`; the package root exports only `FileTree` and `FileTreeProps`.
- `FileTree` is typed as `FileTreeComponent`. Get `FileTreeHandle` through `ref`; React 18 and 19 are both supported.

### Rows

- Your app owns the tree state: expansion, selection and children loading all live there, and the component only renders `rows`. After an expand or a select, update `expanded` and `selectedId` and pass the rows in again.
- `rows` is a flat list rendered in the order you pass it and indented by `depth`; the component does not check how rows relate to each other. Place child rows and their state rows right after the parent, with a `depth` one higher.
- Rows are plain objects, so you can sort, filter or trim them by permission before passing them in.
- `rootOrder="context"` orders root directories by the first URI segment as `user → session → agent → resources`, accepting singular and plural forms (such as `users` and `agents`); other directories follow in their original order. Only root-level directory rows are sorted, and each moves together with its subtree. Root-level file rows and state rows, such as a paging row, stay in place.

### Operations and notifications

- Methods in `operations` return `Promise<void>`: resolving means success and rejecting means failure. The matching `on…` callback fires only after a success, never after a failure.
- Omitting a method makes its operation unavailable: the expand arrow, "Load more", "Retry", search and refresh buttons are disabled, and clicking a row does not select it. Omitting an `on…` callback does not affect execution.
- While an operation is still pending (a select, expand, load more or retry on the same row, or search or refresh), repeated triggers are ignored.

### Selection, keyboard and permissions

- Clicking a directory and clicking a file both call `operations.select`, so branch on `row.type`. Clicking the expand arrow only calls `operations.toggleExpand` and does not select.
- Content returned by `renderRowTrailing` sits inside the row, so a click on it bubbles up and selects the row. Call `event.stopPropagation()` when it needs its own click behavior, as the board icons in the example do.
- Keyboard: Up and Down move focus, Right expands a directory, Left collapses it, and Enter and Space select.
- The tree uses `role="tree"` and rows use `role="treeitem"` with `aria-level` (`depth` plus 1), `aria-selected`, `aria-expanded` and `aria-disabled`. Name the tree with `aria-label`.
- Permission state comes from your app and the component sends no authorization requests: a `disabled` row can be neither selected nor expanded, a row with `selectable: false` cannot be selected but can be expanded, and `access` only shows a text badge at the row end without changing behavior.

### Search and refresh

- The search trigger and refresh button are shown by default. Pass `false` to `search` or `refresh` to hide one; when both are hidden the row is not rendered, and `slots.toolbar` is unaffected.
- While a refresh is pending (any of `loading`, `refresh.loading` or the Promise returned by `operations.refresh`), the button shows a loading state and is disabled, so repeated clicks do not run it twice. After `operations.refresh` rejects, the button recovers and `onRefresh` does not fire.
- The refresh button shows a hint on hover or focus and closes it on Escape. `labels.refresh` is both the hint and the button's accessible name.
- The default search text includes a `⌘+K` hint, but the component registers no shortcut and filters no rows. Provide the search UI, the shortcut and the result handling yourself through `operations.search`.

### Directory descriptions

- The component derives a directory's meaning from the structure of a row's `uri` and ships built-in description and trigger copy, so you pass nothing. Matching looks only at the path, ignoring the `viking://` prefix, letter case, query string and trailing slashes, and never at `type`.
- Built-in copy covers fixed levels only: `viking://resources` matches `sharedResources`, `viking://resources/docs` does not, and deeper nodes are up to you.
- The description appears after the name. Hovering a row opens a tooltip on its right with the title, description, trigger copy and path. The nine long-term memory keys (`profile` to `experiences`) show their description in the tooltip only.
- A row's own `description` wins over the built-in one, and an empty string hides it. `labels.info` overrides copy per key, an empty string hides that key too, and keys you leave out use the built-in copy for the current language.
- A `uri` that matches no key gets no built-in tooltip. When you provide `renderRowTooltip`, the tooltip content is entirely yours.

```tsx
<FileTree
  rows={rows}
  labels={{
    info: {
      description: { userRoot: 'Current user' },
      triggerBehavior: {
        memories: 'Distilled whenever a session is committed',
      },
      field: {
        description: 'Description',
        triggerBehavior: 'Trigger',
        path: 'Path',
      },
    },
  }}
/>
```

### Finding rows

- Every row element carries `data-file-tree-row-id` with the row's `id`; the attribute name is exported as `FILE_TREE_ROW_ATTRIBUTE`. Use it for one-off highlights or overlays at the page level.
- `getRowAttributes(row)` adds classes and attributes per row: `className` and `style` are merged with the component's own, and for entry rows `onClick` and `onKeyDown` stay under the component's control.
- `ref` gives you `getRowElement(id)` and `scrollToRow(id, options)`, for example to return the target row from `locateTarget` of [DirectoryTour](./directory-tour).

```tsx
const treeRef = useRef<FileTreeHandle>(null);

<FileTree ref={treeRef} rows={rows} />;

treeRef.current?.scrollToRow('resources', { block: 'center' });
```

### Layout

- The root element is `100%` tall and scrolls its content internally, so give its container a height.
- Rows size to their content: names render in full, the container scrolls sideways, and deep indentation gets its space the same way.
- Descriptions are at most 200px wide and truncate beyond that, so a long description does not stretch the row.
- Chromium browsers use the same scrollbar styling on every platform. Overflow reserves 12px of space for an 8px rounded thumb, with native macOS light and dark colors. Hovering the scrollbar reveals its track and border; hovering the thumb darkens it in light mode and lightens it in dark mode.
- Content returned by `renderRowTrailing` sits at the right edge of the row; when the row also shows trailing markers such as the level or access, it follows them directly.
