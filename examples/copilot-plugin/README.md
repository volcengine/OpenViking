# OpenViking Memory Plugin for GitHub Copilot

Long-term semantic memory for [GitHub Copilot](https://docs.github.com/en/copilot) (VSCode Copilot Chat / agent mode, `gh copilot` CLI, and the GitHub.com Copilot cloud agent), powered by [OpenViking](https://github.com/volcengine/OpenViking).

This is the Copilot counterpart to [`claude-code-memory-plugin`](../claude-code-memory-plugin), [`codex-memory-plugin`](../codex-memory-plugin), and [`zcode-memory-plugin`](../zcode-memory-plugin) — with one important honest difference documented in [DESIGN.md](./DESIGN.md):

> **GitHub Copilot does not expose Claude-Code-style lifecycle hooks** (no `SessionStart` / `UserPromptSubmit` / `Stop`). Verified against official GitHub docs on 2026-07-28. Memory therefore cannot be auto-injected before each turn or auto-captured after each turn the way it is for Claude Code / Codex / Cursor / TRAE / ZCode. Instead, this plugin wires OpenViking's MCP server into all three Copilot surfaces and supplies an [Agent Skill](./skills/openviking-memory/SKILL.md) that tells the model when to call `recall` / `remember`. The capabilities are all there; the *policy* that hooks would have supplied lives in the skill.

## Status

Functional and honestly scoped. The MCP wiring is verified against the official GitHub Copilot MCP docs (GA for VSCode + `gh copilot` CLI; public preview for the GitHub.com repo-level cloud agent / code review). The hook-based auto-recall / auto-capture parity story is intentionally **not** implemented because Copilot has no hook surface for it. See [DESIGN.md](./DESIGN.md) for the full rationale, [RESEARCH.md](./RESEARCH.md) for the source links.

## Quick start

```bash
# Default: wire ~/.copilot/mcp-config.json for `gh copilot` CLI
bash examples/copilot-plugin/setup-helper/install.sh --cli --with-skill

# Or: write .vscode/mcp.json in the current workspace for VSCode Copilot Chat
bash examples/copilot-plugin/setup-helper/install.sh --vscode

# Or: print a JSON snippet to paste into a GitHub repo's MCP settings UI
bash examples/copilot-plugin/setup-helper/install.sh --repo
```

Non-interactive:

```bash
OPENVIKING_URL=https://your-openviking.example.com \
OPENVIKING_API_KEY=sk-... \
bash examples/copilot-plugin/setup-helper/install.sh --cli --with-skill --yes
```

See [INSTALL.md](./INSTALL.md) (or [INSTALL-ZH.md](./INSTALL-ZH.md) for Chinese) for full instructions including how to verify the connection and the differences between the three Copilot surfaces.

## What it provides

- **Ready-to-use MCP config snippets** for the three Copilot surfaces, generated by tested pure functions in [`scripts/build-configs.mjs`](./scripts/build-configs.mjs):
  - `.vscode/mcp.json` for VSCode Copilot Chat / agent mode (top-level `servers`, HTTP type).
  - `~/.copilot/mcp-config.json` for `gh copilot` CLI (top-level `mcpServers`, with `type`/`tools`/`headers`).
  - A repo-level JSON snippet for GitHub.com (Settings → Copilot → MCP servers), with the API key referenced as `${COPILOT_MCP_OPENVIKING_API_KEY}` so it is never hard-coded.
- **An [Agent Skill](./skills/openviking-memory/SKILL.md)** (`openviking-memory`) that supplies the recall/remember policy the missing hooks would have supplied. Copilot auto-discovers skills under `~/.copilot/skills/`, `.github/skills/`, and `~/.agents/skills/`.
- **An optional stdio MCP proxy** at [`servers/mcp-proxy.mjs`](./servers/mcp-proxy.mjs) (mirrors [`zcode-memory-plugin`](../zcode-memory-plugin/servers/mcp-proxy.mjs)) for users who want OpenViking credentials auto-resolved from `~/.openviking/ovcli.conf` instead of pasted into each MCP config. Most users should use direct HTTP instead; the proxy is for the local-unauthenticated-server or credential-rotation case.

## How it works

```
   ┌────────────────────────────────────────────────────┐
   │                GitHub Copilot                       │
   │  (VSCode Chat / agent mode · `gh copilot` · cloud)  │
   └──────────────────────┬─────────────────────────────┘
                          │ MCP (HTTP, Bearer api-key)
                          ▼
              OpenViking /mcp endpoint
              (~/.openviking/ovcli.conf)
                          │
                          ▼
                  recall · search · find
                  remember · read · list
                  grep · glob · code_search
                          ▲
                          │ nudges when to call
              ┌───────────┴────────────┐
              │  Agent Skill           │
              │  openviking-memory     │
              └────────────────────────┘
```

The model calls the OpenViking MCP tools itself, guided by the Agent Skill. There is no `SessionStart` injecting a profile, no `UserPromptSubmit` injecting recall, no `Stop` capturing turns — Copilot does not fire those events.

## Configuration

Connection and identity are resolved by the shared runtime in this order (same as the other plugins):

1. `OPENVIKING_CREDENTIAL_SOURCE=env` forces `OPENVIKING_URL` / `OPENVIKING_API_KEY` / `OPENVIKING_ACCOUNT` / `OPENVIKING_USER` / `OPENVIKING_PEER_ID`.
2. Active `~/.openviking/ovcli.conf` when present (`url`, `api_key`, `account`, `user`, `actor_peer_id`).
3. `~/.openviking/ov.conf` legacy fallback, then `http://127.0.0.1:1933` unauthenticated.

Auth is sent as `Authorization: Bearer <api_key>` to the `/mcp` endpoint. The HTTP configs install a workspace-derived peer by default; set `OPENVIKING_WORKSPACE_PEER=0` to disable, or `OPENVIKING_PEER_ID` to override (see the [shared library README](../memory-plugin-shared/README.md)).

## Available MCP tools

The proxy forwards OpenViking's real `tools/list` response. Current OpenViking servers expose: `recall`, `search`, `find`, `remember`, `read`, `list`, `grep`, `glob`, `add_resource`, `forget`, `list_watches`, `cancel_watch`, `code_search`, `code_outline`, `code_expand`, `health`.

**Important caveat for the repo-level (GitHub.com) surface**: Copilot cloud agent and Copilot code review support MCP **tools only** — MCP resources and prompts are ignored. The skill's recall-via-tool pattern works on all surfaces; resource-based context injection does not work on the cloud agent.
