# 一个全局 MCP，两个项目

这个示例让两个虚构工作区共用一个 OpenViking MCP 注册。每次检索显式传入
项目资源目录，切换项目无需改连接，也没有进程级“当前项目”。

英文操作稿见 [README.md](README.md)，基线是 2026-11-06 核对的上游
`5caada112a60783d4ec21234be90e95f0261fbd5`。建议贡献位置为
`examples/multi-project-mcp/`，后续可在中英文 MCP 指南各加一个入口链接。

## 最小用法

1. 准备隔离测试服务、同版本 `ov` CLI 和普通用户身份。模型须可用；准备资料会写入
   两份合成 Markdown，并可能产生模型费用。不要连接真实项目数据。
2. 将 [config/mcp.json](config/mcp.json) 的唯一 MCP 条目合入客户端的用户级/全局
   配置。替换测试地址及密钥占位符；填好的配置保留在私有位置。客户端字段可能不同。
3. 按英文稿执行 `ov write --from-file ... --wait`，检查原文与索引状态。
4. 打开 `project-a/` 并加载其 `AGENTS.md`：带 A 的 `target_uri` 检索，再读 A 的
   `brief.md`，预期答案是 **3 次**；换到 B，显式改用 B 的 URI，预期是 **7 次**。
5. [requests.json](requests.json) 提供 A → B → A 和并发请求示例。完成 MCP 初始化后
   逐条发送；它不是可直接 POST 的批处理体。并发响应按请求 ID 对应，各自携带范围。

## 现有机制与新增内容

| 内容 | 归属 |
| --- | --- |
| 全局 MCP 注册、`find.target_uri`、`read.uri` | 上游现有能力 |
| `.openviking/config.json` 的 `peer.id`、recall、capture 设置 | 上游现有 workspace schema |
| 账号、用户、actor-peer、ACL | 上游现有权限与作用域机制 |
| 合成资料、工作区操作说明、请求样本 | 本次新增的文档示例 |

不需要新增项目注册表、自动发现服务、路由代理或公共接口。

## 必须保留的边界

- **连接不等于权限。** 全局注册只决定连接与认证；项目目录和 `target_uri` 决定
  本次查哪里。`read` 仍需单独给出正确 URI，不继承上一次检索范围。
- **peer 不等于租户。** workspace peer 主要组织记忆；actor-peer 限制当前用户的
  peer 集合，不隔离普通共享资源。持有完整用户密钥的客户端可以更改或省略它。
- **工作区配置不会自动路由原生 MCP。** 这些文件由兼容的记忆插件读取；直接 HTTP
  MCP 和 `ov` CLI 不读取它们。模板没有固定 actor-peer，也不承诺自动切换 peer。
- **检索流程只读不等于身份只读。** 本例的准备身份可写。要强制限制读写，沿用账号、
  用户与 ACL；`acl.enabled` 默认关闭，开启后还需配置有效授权。`readOnlyHint`
  或隐藏写工具都不能代替服务端检查。同一示例身份可以主动访问 A 和 B。
- **不默认采集聊天。** 主流程不安装 hooks；工作区文件关闭自动 recall/capture。
  若原来已经装了采集插件，还需检查更高优先级配置，不能仅凭此文件断言采集已停。
- **并发不切全局变量。** 请求各自带 URI；需要记忆 peer 时，由可信客户端逐请求
  带 actor-peer，或由独立客户端实例固定上下文。

## 验证范围

本地检查覆盖配置解析、workspace/peer 解析、请求参数与源码契约、合成内容及链接。
尚未实测隔离服务入库、真实模型检索、MCP 协议、客户端切换、并发请求或权限拒绝。
**3 次/7 次是验收预期，不是实测结果。** 详细记录和后续 PR 草稿保留在本地交付目录。
